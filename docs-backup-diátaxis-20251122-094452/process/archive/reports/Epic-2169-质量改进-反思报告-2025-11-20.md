## 📚 学习要点（Epic级别）

### 1. XAML绑定模式深度理解 ⭐⭐⭐⭐⭐

**关键洞察**:

**发现1: 控件默认绑定模式陷阱**
```xml
<!-- 高风险控件（默认TwoWay） -->
<TextBox Text="{Binding ReadOnlyProperty}" />       ❌ 运行时错误！
<RadioButton IsChecked="{Binding ReadOnlyFlag}" />  ❌ 运行时错误！
<CheckBox IsChecked="{Binding ReadOnlyState}" />    ❌ 运行时错误！

<!-- 正确方式 -->
<TextBox Text="{Binding ReadOnlyProperty, Mode=OneWay}" />       ✅
<RadioButton IsChecked="{Binding ReadOnlyFlag, Mode=OneWay}" />  ✅
<CheckBox IsChecked="{Binding ReadOnlyState, Mode=OneWay}" />    ✅
```

**发现2: 明确性原则（即使默认是OneWay也要声明）**
```xml
<!-- TextBlock默认OneWay，但仍应明确指定 -->
<TextBlock Text="{Binding CreatedAt}" />                        ⚠️ 可工作但不推荐
<TextBlock Text="{Binding CreatedAt, Mode=OneWay}" />           ✅ 推荐（明确性）
```

**只读属性识别方法**:
1. **Server生成属性**: CreatedAt, UpdatedAt, ConsultationDate
2. **计算属性**: `public int HerbCount => HerbItems.Count(...)`
3. **表达式属性**: `public bool IsReadOnly => !IsEditMode`
4. **private set属性**: `public string Name { get; private set; }`

**可复用性**:
- 已创建`docs/checklists/xaml-binding-checklist.md`作为检查标准
- 已创建`docs/templates/DetailView-XAML-Template.md`作为开发模板
- 下次开发DetailView可直接复用

### 3. 5 Why根因分析方法 ⭐⭐⭐⭐⭐

**方法**: 连续5次询问"为什么"，直到找到可控的根本原因

**实践案例: git index.lock问题**
```
Why 1: 为什么出现index.lock问题？
→ .git/index.lock文件被遗留（0字节孤儿锁）

Why 2: 为什么锁文件未清理？
→ 持有锁的进程被强制终止，未执行正常清理流程

Why 3: 为什么进程被强制终止？
→ 测试运行超时（超过300秒限制），VSTest强制中止

Why 4: 为什么测试超时？
→ 并发运行多个test项目，资源竞争导致执行缓慢

Why 5（根本原因）: 为什么并发运行？
→ 在bash中启动了5个后台test进程，未进行串行化管理
```

**价值**:
- 避免治标不治本（仅删除锁文件）
- 找到可落地的解决方案（串行化测试）
- 可复用的问题分析方法

**应用场景**:
- 复杂问题根因定位
- 技术债务分析
- 流程改进

### 4. Windows环境特殊性 ⭐⭐⭐⭐

**关键差异**:

**1. 文件锁机制更严格**
```
Unix/Linux: 进程终止 → 自动释放文件锁
Windows:    进程终止 → 可能不释放锁（需手动清理）
```

**2. 路径格式**
```bash
# ❌ Windows反斜杠（可能导致转义问题）
D:\source\repos\LYBTZYZS

# ✅ 推荐使用正斜杠（跨平台兼容）
D:/source/repos/LYBTZYZS
```

**3. 并发操作敏感性**
```bash
# Unix: 通常可以并发操作
dotnet test Project1 &
dotnet test Project2 &

# Windows: 容易触发文件锁冲突
# 建议：串行执行
dotnet test Project1
dotnet test Project2
```

**最佳实践**:
- Windows环境避免并发文件操作
- 使用正斜杠路径
- 操作前检查文件锁状态
- 已记录到`docs/guides/ai-tools-best-practices.md`
