# 安全验证清单 (Security Checklist)

**用途**: 验证功能实现的安全性，确保符合医疗数据保护标准
**适用阶段**: Design阶段和Implementation阶段
**强制级别**: 必选 (MUST) - 所有涉及数据处理、用户交互、网络通信的功能

---

## 1. 身份认证与授权 (Authentication & Authorization)

### 1.1 身份认证 (Authentication)
- [ ] **双轨认证系统合规** - 普通用户(Users表) 与 超级管理员(AdminSecrets表) 物理隔离
- [ ] **JWT Token验证** - 所有API端点都验证JWT Token有效性
- [ ] **Token刷新机制** - Refresh Token机制正确实现，防止会话劫持
- [ ] **密码强度要求** - 强制密码策略（长度≥8，包含大小写字母+数字+特殊字符）
- [ ] **密码哈希安全** - 使用BCrypt/PBKDF2，禁止明文存储或MD5/SHA1弱哈希
- [ ] **登录失败保护** - 实施登录失败锁定机制（3次失败锁定15分钟）

### 1.2 授权控制 (Authorization)
- [ ] **基于角色的访问控制** - 正确实现RBAC，角色权限清晰
- [ ] **最小权限原则** - 用户只能访问其职责所需的最小资源
- [ ] **超级管理员特权隔离** - 超级管理员操作独立验证，不依赖普通权限体系
- [ ] **资源所有权验证** - 用户只能操作自己的数据（医生只能看自己的患者）
- [ ] **API端点权限控制** - 每个API端点都有明确的权限要求（`[Authorize]`标注）

---

## 2. 数据保护 (Data Protection)

### 2.1 敏感数据加密 (Sensitive Data Encryption)
- [ ] **患者隐私数据加密** - 姓名/身份证号/联系方式等使用AES256加密存储
- [ ] **超级管理员密钥加密** - AdminSecrets表的SecretHash使用AES256加密
- [ ] **传输加密** - 生产环境强制HTTPS，禁止HTTP明文传输
- [ ] **数据库连接加密** - 连接字符串使用加密存储，不在代码中硬编码
- [ ] **配置文件保护** - appsettings.json中的敏感配置（JWT Secret/数据库密码）加密

### 2.2 数据脱敏 (Data Masking)
- [ ] **日志脱敏** - 日志中不记录密码/Token/身份证号等敏感信息
- [ ] **API响应脱敏** - 返回用户信息时隐藏密码哈希/Salt等
- [ ] **错误消息脱敏** - 错误提示不泄露系统内部信息（数据库结构/文件路径等）
- [ ] **调试信息控制** - 生产环境禁用详细错误堆栈，仅记录到安全日志

### 2.3 数据完整性 (Data Integrity)
- [ ] **并发控制** - 使用乐观锁/悲观锁防止并发数据冲突
- [ ] **事务一致性** - 关键业务操作使用数据库事务保证ACID
- [ ] **数据备份** - 关键数据变更前进行备份（软删除而非物理删除）
- [ ] **审计日志不可篡改** - 审计日志只能追加，不可修改或删除

---

## 3. 输入验证与防护 (Input Validation & Protection)

### 3.1 输入验证 (Input Validation)
- [ ] **所有用户输入都验证** - 客户端和服务端双重验证
- [ ] **数据类型验证** - 严格验证数据类型（int/string/DateTime等）
- [ ] **长度限制验证** - 字符串长度、数组大小等都有上限
- [ ] **格式验证** - 邮箱/电话/身份证号等使用正则表达式验证
- [ ] **白名单验证** - 枚举类型使用白名单验证，拒绝非法值

### 3.2 注入攻击防护 (Injection Protection)
- [ ] **SQL注入防护** - 100%使用参数化查询，禁止字符串拼接SQL
- [ ] **XSS防护** - 所有用户输入HTML转义，禁止直接渲染
- [ ] **命令注入防护** - 禁止用户输入直接传递给Shell命令
- [ ] **LDAP注入防护** - 如使用LDAP，正确转义用户输入
- [ ] **路径遍历防护** - 文件路径操作验证，禁止`../`等路径遍历

### 3.3 业务逻辑验证 (Business Logic Validation)
- [ ] **业务规则验证** - 验证业务约束（一案一诊一方/当日可编辑等）
- [ ] **金额计算验证** - 处方价格计算使用Decimal，防止浮点误差
- [ ] **状态机验证** - 状态转换符合业务流程（草稿→已完成→已锁定）
- [ ] **时间逻辑验证** - 就诊日期≤当前日期，开始时间<结束时间等

---

## 4. 会话管理 (Session Management)

### 4.1 Token管理 (Token Management)
- [ ] **Token过期控制** - Access Token有效期≤1小时，Refresh Token≤7天
- [ ] **Token吊销机制** - 支持强制注销（Token黑名单）
- [ ] **Token签名验证** - 验证JWT签名，防止Token伪造
- [ ] **Token Claims最小化** - Token中只包含必需的Claims（UserId/Role），不包含敏感信息
- [ ] **多设备登录控制** - 如需单设备登录，实现Token唯一性验证

### 4.2 会话安全 (Session Security)
- [ ] **CSRF防护** - 状态变更操作使用Anti-CSRF Token
- [ ] **Clickjacking防护** - HTTP响应头设置`X-Frame-Options: DENY`
- [ ] **会话固定攻击防护** - 登录成功后重新生成Token
- [ ] **会话超时控制** - 长时间无操作自动注销（建议15分钟）

---

## 5. 日志与审计 (Logging & Auditing)

### 5.1 审计日志 (Audit Logging)
- [ ] **关键操作审计** - 登录/注销/权限变更/敏感数据访问都记录审计日志
- [ ] **审计日志完整性** - 记录谁(Who)/何时(When)/做了什么(What)/结果(Result)
- [ ] **医疗数据访问审计** - 患者数据访问、医案查看、处方开具都记录
- [ ] **超级管理员操作审计** - 超级管理员所有操作都记录到独立审计日志
- [ ] **审计日志持久化** - 审计日志写入数据库，定期归档，保留≥1年

### 5.2 安全日志 (Security Logging)
- [ ] **异常事件记录** - 登录失败/权限拒绝/异常访问都记录
- [ ] **安全事件告警** - 高频登录失败/权限提升尝试触发告警
- [ ] **日志级别合理** - Error/Warning/Info级别使用正确
- [ ] **日志存储安全** - 日志文件访问受限，定期轮转
- [ ] **日志脱敏** - 见"2.2 数据脱敏"

---

## 6. 第三方依赖安全 (Third-party Dependency Security)

### 6.1 依赖审查 (Dependency Review)
- [ ] **NuGet包来源可信** - 仅使用官方NuGet源或经审查的私有源
- [ ] **依赖漏洞扫描** - 使用`dotnet list package --vulnerable`检查已知漏洞
- [ ] **依赖版本锁定** - 生产环境锁定依赖版本，避免自动升级引入漏洞
- [ ] **最小依赖原则** - 仅引入必需的依赖，定期清理未使用的包
- [ ] **依赖许可证审查** - 确保依赖许可证与项目兼容

### 6.2 API安全 (API Security)
- [ ] **外部API HTTPS** - 调用外部API强制HTTPS
- [ ] **API密钥安全** - API Key存储在安全配置中，不硬编码
- [ ] **API速率限制** - 实施API调用频率限制，防止滥用
- [ ] **API错误处理** - 外部API错误不直接返回给客户端

---

## 7. 部署与运行时安全 (Deployment & Runtime Security)

### 7.1 部署安全 (Deployment Security)
- [ ] **环境隔离** - 开发/测试/生产环境严格隔离
- [ ] **生产配置独立** - 生产环境配置独立管理，不提交到代码库
- [ ] **默认密码更改** - 超级管理员默认密码首次登录强制修改
- [ ] **端口访问控制** - 生产环境仅开放必需端口（443/5001等）
- [ ] **数据库访问控制** - 数据库仅允许应用服务器IP访问

### 7.2 运行时安全 (Runtime Security)
- [ ] **异常处理完整** - 所有异常都捕获，防止应用崩溃
- [ ] **资源限制** - 设置合理的内存/CPU/连接数上限
- [ ] **DDoS防护** - 实施请求频率限制（Rate Limiting）
- [ ] **文件上传限制** - 限制文件类型/大小/数量
- [ ] **定期安全更新** - .NET Runtime/依赖包定期更新补丁

---

## 8. 医疗数据特定要求 (Medical Data Specific Requirements)

### 8.1 患者隐私保护 (Patient Privacy Protection)
- [ ] **HIPAA合规性** - 符合医疗数据保护规范（如适用）
- [ ] **患者数据访问控制** - 仅授权医生可查看患者数据
- [ ] **患者数据最小化** - 只收集/存储必需的患者信息
- [ ] **患者数据导出控制** - 导出功能受限，记录审计日志
- [ ] **患者数据删除** - 支持患者数据删除请求（软删除+脱敏）

### 8.2 医案数据完整性 (Medical Case Integrity)
- [ ] **医案不可篡改** - 已锁定医案禁止修改
- [ ] **医案变更审计** - 医案修改记录版本历史
- [ ] **处方防伪造** - 处方编号唯一，防止伪造
- [ ] **医案签名** - 关键医案支持数字签名（如需要）

## 9. 合规性检查 (Compliance Check)

### 9.1 Constitution合规 (Constitution Compliance)
- [ ] **符合双轨认证系统** - Users表与AdminSecrets表物理隔离
- [ ] **符合密码加密要求** - BCrypt/PBKDF2哈希
- [ ] **符合审计日志要求** - 关键操作都记录
- [ ] **符合HTTPS要求** - 生产环境强制HTTPS

### 9.2 行业标准合规 (Industry Standards Compliance)
- [ ] **OWASP Top 10合规** - 不存在OWASP十大安全风险
- [ ] **GDPR合规** - 符合数据保护法规（如适用）
- [ ] **PCI-DSS合规** - 如涉及支付，符合支付卡行业标准

---

## 10. 安全测试 (Security Testing)

### 10.1 渗透测试 (Penetration Testing)
- [ ] **SQL注入测试** - 使用SQLMap等工具测试
- [ ] **XSS测试** - 测试反射型/存储型/DOM型XSS
- [ ] **CSRF测试** - 测试状态变更操作的CSRF防护
- [ ] **权限绕过测试** - 尝试越权访问其他用户数据
- [ ] **暴力破解测试** - 测试登录失败锁定机制

### 10.2 代码安全扫描 (Code Security Scanning)
- [ ] **静态代码分析** - 使用Roslyn Analyzer/SonarQube扫描
- [ ] **依赖漏洞扫描** - 使用`dotnet list package --vulnerable`
- [ ] **敏感信息扫描** - 检查代码中是否硬编码密码/密钥
- [ ] **安全配置检查** - 检查Web.config/appsettings.json安全配置
