#### 问题详情

**标准格式** (认证、用户、患者、药材模块使用):

```json
  "message": "操作成功",
  "data": [...],
  "timestamp": "2025-08-01T08:35:18.9213096Z"

```

**问题格式** (其他6个模块使用):
```json
[...] // 直接返回数据数组
```

| 模块 | 成功响应格式 | 错误响应格式 | 问题严重程度 |
|------|-------------|-------------|-------------|
| 医生管理 | ✅ 使用ApiResponse | ❌ 部分接口不统一 | 中等 |
| 挂号管理 | ❌ 直接返回数组 | ❌ 简单字符串 | 严重 |

#### 影响分析
1. **前端开发复杂度增加**: 需要处理多种不同的响应格式
2. **错误处理不统一**: 不同模块的错误信息格式不一致

4. **用户体验差**: 错误信息不友好，缺少时间戳等元信息
5. **调试困难**: 缺少统一的状态码和错误码

### 2. 处方管理模块特殊问题 🔴 **高优先级**

#### 问题列表

1. **ID参数类型不一致**
   ```csharp
   // 问题：使用string而不是Guid
   [HttpGet("{id}")]
   public async Task<ActionResult<PrescriptionDetailDto>> GetById(string id)
   
   // 应该使用：
   public async Task<ActionResult<ApiResponse<PrescriptionDetailDto>>> GetById(Guid id)
   ```

2. **操作用户信息硬编码**
   ```csharp
   // 问题：硬编码了操作用户信息
   var result = await _service.CreateAsync(dto, Guid.Empty, "system");
   
   // 应该获取当前用户：
   var (operatorId, operatorName, _) = GetOperator();
   var result = await _service.CreateAsync(dto, operatorId, operatorName);
   ```

3. **缺少GetOperator方法**
   - 其他控制器都有GetOperator方法获取当前用户信息
   - 处方管理控制器缺少此方法

4. **响应格式问题**
   - 成功操作返回简单的Ok()
   - 失败操作返回简单的BadRequest()
   - 没有使用ApiResponse统一格式

### 4. 中文字符编码问题 🔸 **中优先级**

#### 问题表现
```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "$.name": ["The JSON value could not be converted to System.String. Path: $.name"]
  }
}
```

#### 受影响模块
- 所有支持创建/更新操作的模块
- 特别是需要输入中文药材名、患者姓名等的场景

#### 解决方向
1. **后端**: 确保JSON序列化配置支持UTF-8
2. **前端**: 确保请求头包含正确的Content-Type和字符编码
3. **测试**: 使用正确的编码格式进行API测试
