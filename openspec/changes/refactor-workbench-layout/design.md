# Design: 工作台布局重构技术设计

## Context

### 重要说明：工作区范围
本次重构关注的**工作区空间**不仅仅是首页工作台，而是**整个应用的所有二级工作界面**：
- 首页工作台（AdminHomeView、ClinicalHomeView）
- 看诊界面（MedicalCaseWorkspaceView）- **核心工作界面**
- 管理界面（PatientManagementView、HerbManagementView等）
- 详情界面（MedicalCaseDetailView、PatientDetailView等）

**核心目标**: 最大化所有工作界面的可用空间，避免上下滚动。

### 当前Shell布局空间分析（1920×1080分辨率）

**MainWindow.xaml 固定占用**:
| 区域 | 高度 | 说明 |
|-----|------|------|
| 顶部工具栏 | 60px | Header区域 |
| 内容区外边距 | 40px | Border Margin="20" 上下各20px |
| 内容区内边距 | 40px | Grid Margin="20" 上下各20px |
| **Shell总占用** | **140px** | |

**二级工作界面内部占用（以MedicalCaseWorkspaceView为例）**:
| 区域 | 高度 | 说明 |
|-----|------|------|
| 患者信息条 | 50px | Row 0 |
| 底部操作栏 | 64px | Row 2 |
| 内容区边距 | 32px | Margin="12,8,12,8" 上下各16px |
| **界面内部总占用** | **146px** | |

**当前实际可用工作区**: 1080 - 140 - 146 = **794px** (仅73.5%)

### 两个工作台视图
- `AdminHomeView.xaml` - 管理员工作台（6个功能卡片，3x2网格）
- `ClinicalHomeView.xaml` - 医生工作台（主卡片+统计+4个辅助卡片）

两个工作台都在内容区域包含用户信息和"修改个人信息"/"修改密码"按钮，这些操作与工作台主功能无关，应移至Header统一管理。

### 现有布局问题
1. **Shell层**: 顶部工具栏60px + 内容区边距80px，固定占用140px
2. **内容层**: 各二级界面自身的标题栏、操作栏等额外占用
3. 标题区域（系统名称+工作台名称+用户信息）占用约120-150px垂直空间
4. 功能卡片使用emoji图标，与系统整体MaterialDesign风格不一致
5. Admin和Clinical工作台设计语言不统一

## Goals / Non-Goals

### Goals
- **Shell层优化**: 压缩顶部工具栏高度（60px→48px），减少内容区边距
- **最大化工作区**: 将Shell层固定占用从140px减少到80px以内（节省60px+）
- 将用户账户操作（个人信息/密码修改）集中到Header用户菜单
- 减少标题区域高度，增加功能区可用空间
- 统一两个工作台的设计语言
- 采用MaterialDesign图标替换emoji
- 提升整体视觉效果的现代感和专业感

### Non-Goals
- 不改变功能卡片的实际功能
- 不重构ViewModel业务逻辑
- 不引入新的第三方UI框架
- 不改变导航结构
- 不修改二级工作界面的内部布局（如MedicalCaseWorkspaceView的患者信息条、操作栏）

## Decisions

### D1: Header用户菜单设计
**决策**: 使用Popup实现下拉菜单，包含用户头像、用户名、角色，以及三个操作项。

**布局**:
```
[时间] [API状态] [用户头像+名称 v] [退出]
                    |
                    +-- 修改个人信息
                    +-- 修改密码
                    +-- 分隔线
                    +-- 退出登录
```

**替代方案**:
- ComboBox下拉：样式定制困难，交互体验一般
- 独立按钮：占用过多Header空间
- 右键菜单：发现性差

### D2: 标题区域布局
**决策**: 采用单行标题设计，高度80px。

**布局**:
```
+------------------------------------------+
|  [Logo] 凌隐宝堂中医诊所 - 系统管理工作台  |  80px
+------------------------------------------+
|                                          |
|          [功能卡片网格区域]               |  剩余空间
|                                          |
+------------------------------------------+
```

**替代方案**:
- 保持双行标题（系统名称+工作台名称）：占用空间仍较大
- 无标题直接显示卡片：缺乏上下文信息

### D3: 功能卡片图标方案
**决策**: 使用MaterialDesignThemes包中的图标替换emoji。

图标映射：
| 功能 | 当前(emoji) | 新图标(MaterialDesign) |
|------|-------------|----------------------|
| 用户管理 | U+1F9E3 | Account |
| 病患管理 | U+1F93A | AccountGroup |
| 中药管理 | U+1F331 | Leaf |
| 方剂管理 | U+1F3BA | Flask |
| 看诊管理 | U+1F9E7 | Stethoscope |
| 处方管理 | U+1F48A | PillMultiple |
| 开始接诊 | - | PlayCircle |
| 患者列表 | - | FormatListBulleted |
| 今日接诊 | - | CalendarToday |
| 查看报表 | - | ChartLine |

**替代方案**:
- FontAwesome图标：需要额外引入字体资源
- 自定义SVG图标：维护成本高
- 保持emoji：风格不统一

### D4: 卡片布局参数
**决策**: 统一卡片样式参数

| 参数 | 当前值 | 新值 |
|------|--------|------|
| 卡片间距 | 16px | 20px |
| 卡片圆角 | 8px | 12px |
| 卡片阴影 | 轻微 | 中等(elevation 2) |
| 图标大小 | 48px | 56px |
| 卡片最小宽度 | - | 160px |

## Risks / Trade-offs

### R1: MaterialDesign图标一致性
- **风险**: 部分功能可能找不到完全匹配的图标
- **缓解**: 提前确认所有图标可用性，必要时使用相近图标

### R2: Header高度增加
- **风险**: 添加用户菜单可能需要稍微增加Header高度
- **缓解**: 保持60px高度，使用紧凑布局

### R3: 样式迁移复杂度
- **风险**: 两个工作台样式不同，统一需要较多修改
- **缓解**: 创建共享样式资源字典，逐步迁移

## Migration Plan

1. **Phase 1**: 创建UserMenuControl和共享样式资源
2. **Phase 2**: 修改MainWindow.xaml集成用户菜单
3. **Phase 3**: 重构AdminHomeView.xaml
4. **Phase 4**: 重构ClinicalHomeView.xaml
5. **Phase 5**: 测试验证和微调

**回滚策略**: 每个Phase独立提交，可按需回退到任意Phase。

## 布局方案深度对比分析

### 核心需求
- **最大化工作区空间**
- **避免上下滚动**
- **保持功能可访问性**

### 空间占用量化分析（1920×1080分辨率）

| 方案 | 固定占用 | 工作区面积 | 空间效率 |
|------|---------|-----------|----------|
| 顶部Header 60px | 115,200px² | 1,958,400px² | **94.4%** |
| 左侧Sidebar 200px | 216,000px² | 1,857,600px² | 89.6% |
| 左侧可折叠Sidebar 60px | 64,800px² | 2,008,800px² | **96.9%** |

### 方案A: 紧凑顶部Header（推荐）

```
+------------------------------------------+
|  [Logo] 系统  [时间][状态][用户v][退出]   |  48px
+------------------------------------------+
|         凌隐宝堂 - 系统管理工作台          |  60px
+------------------------------------------+
|                                          |
|           功能卡片网格区域                 |  972px
|           (6-8卡片，无滚动)               |
|                                          |
+------------------------------------------+
```

**有效工作区高度**: 1080 - 48 - 60 = **972px**

**优点：**
- 工作区效率最高（94.4%+），接近全屏
- Header从60px压缩到48px，标题区从120px压缩到60px
- 改动成本最低，风险可控
- 适合工作台入口页特性

**缺点：**
- 水平Header空间有限
- 后续功能扩展受限

### 方案B: 左侧Sidebar布局

```
+--------+-------------------------------+
| Logo   |  [时间][状态][用户v][退出]     |  48px
+--------+-------------------------------+
|        |                               |
| 导航   |     工作台标题 + 卡片          |  1032px
| 菜单   |     (全部垂直空间)             |
|        |                               |
+--------+-------------------------------+
  200px            1720px
```

**有效工作区**: 1720×1032 = **1,775,040px²** (85.6%)

**优点：**
- 眼动追踪研究显示用户80%时间关注屏幕左侧
- 支持更多导航项（5-10+）
- 符合大多数EHR/EMR系统惯例
- 可扩展性强

**缺点：**
- 水平空间减少200px
- 需要大规模重构
- 对工作台入口页而言过度设计

### 方案C: 可折叠左侧Sidebar

```
常态（折叠态）:
+----+-------------------------------------+
|图标|  [时间][状态][用户v][退出]           |  48px
+----+-------------------------------------+
| 图 |                                     |
| 标 |     工作台标题 + 卡片                |  1032px
| 栏 |     (最大化空间)                     |
+----+-------------------------------------+
 60px              1860px

展开态（Hover或点击）:
+--------+-------------------------------+
| 导航   |     (覆盖内容)                 |
| 菜单   |                               |
+--------+-------------------------------+
  200px
```

**有效工作区**: 1860×1032 = **1,919,520px²** (**96.9%**)

**优点：**
- 空间效率最高
- 兼顾导航扩展性
- 符合现代SaaS设计趋势

**缺点：**
- 交互复杂度增加
- 改动成本最大
- 图标导航可发现性降低

### 行业案例分析

从搜索的医疗系统案例来看：

| 系统类型 | 主流布局 | 原因 |
|---------|---------|------|
| EHR/EMR系统 | 左侧Sidebar | 功能模块多，需频繁切换 |
| 诊所管理系统 | 顶部Header + 卡片 | 入口页简洁，进入模块后再导航 |
| 中医诊所系统 | 顶部Header | 功能相对集中，工作流线性 |

### 方案D: 隐藏式左侧Sidebar（备选方案）

```
隐藏态（默认）:
+------------------------------------------+
|  [汉堡]  系统  [时间][状态][用户v][退出]   |  48px
+------------------------------------------+
|                                          |
|     工作台标题 + 功能卡片                  |  100%宽度
|     (完全最大化空间)                      |  1032px高度
|                                          |
+------------------------------------------+

显示态（点击汉堡按钮）:
+--------+-------------------------------+
| 导航   |                               |
| 菜单   |     (内容区被遮罩暗化)         |
| 200px  |     点击遮罩关闭               |
+--------+-------------------------------+
    Drawer覆盖式
```

**空间效率**: 1920×1032 = **1,981,440px²** (**100%内容区**)

**优点：**
- 工作区**完全最大化**，无任何固定导航占用
- 现代SaaS设计趋势（Notion、Linear、Figma都采用）
- WPF有成熟的NavigationDrawer控件支持
- 支持动画过渡，用户体验现代感强
- **最佳扩展性**：未来功能增多时无需改变布局

**缺点：**
- 导航不可见，新用户需要学习
- 每次访问导航需要额外点击
- 实现复杂度较高
- 医疗系统用户可能更习惯固定可见导航

**WPF实现方式：**
- MaterialDesignInXAML NavigationDrawer
- Syncfusion WPF Navigation Drawer
- 自定义Grid + Visibility + Storyboard动画

### 四方案综合对比

| 维度 | 方案A顶部Header | 方案B侧边Sidebar | 方案C折叠Sidebar | 方案D隐藏Sidebar |
|------|----------------|-----------------|-----------------|-----------------|
| 空间效率 | 90% | 86% | 97% | **100%** |
| 导航可见性 | 无需 | 始终可见 | 图标可见 | 点击显示 |
| 实现复杂度 | **低** | 中 | 中高 | 中 |
| 改动范围 | **小** | 大 | 大 | 大 |
| 扩展性 | 一般 | 优秀 | 优秀 | **最优** |
| 现代感 | 一般 | 一般 | 好 | **最好** |
| 医疗用户接受度 | 高 | 高 | 中 | 中 |

### 决策点：用户明确需求

**用户核心需求**：最大化工作区上下左右空间，避免滚动。用户明确表示：
- 当前上下分布比例不协调
- 增加Header高度会牺牲工作区高度
- 重点是**工作区最大化**，而非Header功能扩展

### 最终推荐：方案E - Shell层紧凑优化

基于用户反馈，推荐**方案E**：在现有顶部Header架构下进行紧凑化优化，而非添加新功能。

**优化策略**:
1. **Header压缩**: 60px → 48px（节省12px）
2. **内容区外边距**: 20px → 12px（节省16px上下）
3. **内容区内边距**: 20px → 12px（节省16px上下）
4. **用户菜单**: 利用现有Header空间，不增加高度

**优化后Shell层固定占用**:
| 区域 | 当前 | 优化后 | 节省 |
|-----|------|--------|------|
| 顶部工具栏 | 60px | 48px | 12px |
| 内容区外边距 | 40px | 24px | 16px |
| 内容区内边距 | 40px | 24px | 16px |
| **总计** | **140px** | **96px** | **44px** |

**优化后实际可用工作区**: 1080 - 96 - 146 = **838px** (77.6%, 提升4.1%)

**方案E优点**:
- 工作区空间最大化（不添加任何新的固定占用）
- 改动范围小，风险可控
- 保持现有架构，仅调整参数
- 用户菜单复用现有Header空间，不增加高度

**备选：方案D（隐藏式Sidebar）**
如果未来需要添加更多导航项，可考虑方案D，将顶部Header完全移除，使用隐藏式左侧Sidebar。
- 空间效率可达100%（仅在需要时显示导航）
- 但改动范围大，需重构Shell布局
