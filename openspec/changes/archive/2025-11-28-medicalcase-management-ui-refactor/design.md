## 3. 审计判断逻辑

### 3.1 审计需求判断规则

```csharp
public interface IAuditRequirementChecker
{
    bool IsAuditRequired(MedicalCaseDto medicalCase, Guid currentUserId);
}

// 实现逻辑
public bool IsAuditRequired(MedicalCaseDto medicalCase, Guid currentUserId)
{
    // 规则1：已完成的医案必须审计
    if (medicalCase.CaseStatus == MedicalCaseStatus.Completed)
        return true;

    // 规则2：非本人修改必须审计
    if (medicalCase.DoctorId != currentUserId)
        return true;

    // 规则3：隔天修改必须审计
    var caseDate = medicalCase.CreatedAt.Date;
    var today = DateTime.Today;
    if (caseDate < today)
        return true;

    // 其他情况：当天本人修改进行中的医案，无需审计
    return false;
}
```

### 3.2 审计场景示例

| 场景 | 需要审计 | 原因 |
|------|----------|------|
| 医生当天修改自己Draft医案 | 否 | 正常看诊流程 |
| 医生当天修改自己Active医案 | 否 | 正常看诊流程 |
| 医生当天修改自己Completed医案 | **是** | 已结案需追溯 |
| 医生隔天修改自己Draft医案 | **是** | 时间间隔需记录 |
| 医生隔天修改自己Completed医案 | **是** | 已结案+时间间隔 |
| 管理员修改任何人的医案 | **是** | 非本人操作 |

## 4. 审计理由对话框设计

### 4.1 对话框布局

```
┌─────────────────────────────────────────┐
│           修改原因（必填）               │
├─────────────────────────────────────────┤
│                                         │
│  请输入修改原因：                        │
│  ┌─────────────────────────────────┐   │
│  │                                 │   │
│  │  (多行文本框, 200字以内)         │   │
│  │                                 │   │
│  └─────────────────────────────────┘   │
│                                         │
│  常用原因（可选）：                      │
│  ○ 补充遗漏信息                         │
│  ○ 更正录入错误                         │
│  ○ 患者要求修改                         │
│  ○ 医嘱调整                             │
│                                         │
│           [取消]    [确认保存]           │
└─────────────────────────────────────────┘
```

### 4.2 对话框行为
- 选择常用原因时自动填充到文本框
- 文本框为空时"确认保存"按钮禁用
- 点击取消返回编辑界面
- 点击确认保存后执行保存+记录审计日志
