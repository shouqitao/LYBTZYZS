## 1. Executive Summary

### 1.1 优化目标

统一医案导航和挂起处理逻辑，提升用户体验，简化代码实现。

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **单一挂起** | 同一患者只允许有一个挂起医案 |
| **角色区分** | 前台只挂号，医生直接看诊 |
| **模式区分** | 查看模式无提示，编辑模式有提示 |
| **弹窗复用** | 四选项弹窗和三选项弹窗统一复用 |

## 2. 业务流程设计

### 2.1 患者选择界面

```
选择患者 → 查询是否有挂起医案
              │
              ├── 无挂起
              │      │
              │      ├── 前台角色 → 挂号 → 患者进入待诊列表
              │      │
              │      └── 医生角色 → 新建医案 → 跳转看诊界面
              │
              └── 有挂起
                     │
                     ├── 前台角色 → 禁止挂号 + 提示"请先到XX医生处理"
                     │
                     └── 医生角色 → 【四选项弹窗】
```

### 2.2 看诊界面 - 待诊列表

#### 状态定义

| 状态 | 英文 | 含义 | 可操作性 |
|------|------|------|----------|
| 待诊 | Waiting | 无医案，等待看诊 | 可双击 |
| 挂起 | Suspended | 有Draft医案 | 可双击 |
| 正在看诊 | InProgress | 当前患者（编辑/查看） | **不可操作** |

#### 交互逻辑

```
待诊列表双击
    │
    ├── 待诊(Waiting) → 直接新建医案
    │
    ├── 挂起(Suspended) → 【四选项弹窗】
    │
    └── 正在看诊(InProgress) → 双击无效 / 按钮无效
```

### 2.3 看诊界面 - 切换/离开

#### 查看模式（只读）

```
医案完成或暂存后 → 自动切换为查看模式
    │
    ├── 切换其他患者 → 直接切换，无提示
    │
    └── 离开看诊界面 → 直接离开，无提示
```

#### 编辑模式

```
当前医案处于编辑状态
    │
    ├── 切换其他患者 → 【三选项弹窗】
    │
    └── 离开看诊界面 → 【三选项弹窗】
```

## 3. 弹窗设计

### 3.1 四选项弹窗（处理挂起医案）

**触发场景**:
- 患者选择界面：医生选择有挂起的患者
- 看诊界面：双击挂起状态的患者

| # | 选项 | 操作 | 结果 |
|---|------|------|------|
| 1 | 继续挂起医案 | 导航到挂起医案 | 继续编辑原医案 |
| 2 | 关闭挂起+新建 | 取消原医案 → 创建新医案 | 开始新的看诊 |
| 3 | 仅关闭挂起 | 取消原医案 | 留在当前界面 |
| 4 | 取消 | 不做任何操作 | 留在当前界面 |

**UI设计**:
```
┌─────────────────────────────────────────┐
│  该患者有未完成的挂起医案                 │
│                                         │
│  患者：张三                              │
│  挂起时间：2025-12-29 10:30             │
│  医生：李医生                            │
│                                         │
│  ┌─────────────┐  ┌─────────────────┐   │
│  │ 继续挂起医案 │  │ 关闭挂起+新建医案│   │
│  └─────────────┘  └─────────────────┘   │
│  ┌─────────────┐  ┌─────────────────┐   │
│  │ 仅关闭挂起   │  │     取消        │   │
│  └─────────────┘  └─────────────────┘   │
└─────────────────────────────────────────┘
```

### 3.2 三选项弹窗（编辑模式离开）

**触发场景**:
- 看诊界面：编辑模式下切换患者
- 看诊界面：编辑模式下点击返回

| # | 选项 | 操作 | 结果 |
|---|------|------|------|
| 1 | 暂存当前医案 | 保存为Draft → 执行目标操作 | 医案变为挂起状态 |
| 2 | 取消当前医案 | 取消医案 → 执行目标操作 | 医案被关闭 |
| 3 | 取消 | 不做任何操作 | 留在当前界面 |

**UI设计**:
```
┌─────────────────────────────────────────┐
│  当前医案尚未保存                         │
│                                         │
│  患者：张三                              │
│  是否保存当前医案？                       │
│                                         │
│  ┌─────────────┐  ┌─────────────────┐   │
│  │ 暂存当前医案 │  │  取消当前医案    │   │
│  └─────────────┘  └─────────────────┘   │
│           ┌─────────────┐               │
│           │    取消     │               │
│           └─────────────┘               │
└─────────────────────────────────────────┘
```

## 4. 状态与模式设计

### 4.1 医案状态（后端）

| MedicalCaseStatus | 含义 | 可编辑 |
|-------------------|------|--------|
| Active | 正在看诊 | 是 |
| Draft | 已暂存（挂起） | 是 |
| Completed | 已完成 | 否（需审核） |
| Cancelled | 已取消 | 否 |

### 4.2 编辑状态（前端）

| EditState | 含义 | 切换/离开行为 |
|-----------|------|---------------|
| ReadOnly | 查看模式 | 直接操作，无提示 |
| Editing | 编辑模式 | 【三选项弹窗】 |
| Saving | 保存中 | 禁止操作 |

### 4.3 待诊队列状态

| PendingCaseType | 后端状态 | 显示 | 颜色 |
|-----------------|----------|------|------|
| Waiting | 无医案 | 待诊 | 灰色 #E0E0E0 |
| Suspended | Draft | 挂起 | 橙色 #FF9800 |
| InProgress | Active（当前） | 看诊中 | 绿色 #4CAF50 |
