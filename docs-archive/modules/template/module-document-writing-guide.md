## 📋 指南概述

本文档为开发人员提供模块文档编写的详细指导，包含实用的写作技巧、模板使用方法和最佳实践。帮助开发团队创建高质量、一致的模块文档。

## 🎯 编写原则

### 1. 读者导向
- **明确读者**: 确定文档的主要读者（开发人员、架构师、运维人员等）
- **匹配背景**: 适当调整技术深度和详细程度
- **用户视角**: 从用户使用场景出发组织内容

### 2. 实用性优先
- **可操作性**: 确保读者能够根据文档完成实际工作
- **示例驱动**: 使用具体示例说明抽象概念
- **问题解决**: 重点解决常见问题和痛点

### 3. 一致性标准
- **模板遵循**: 严格按照模块文档模板结构编写
- **术语统一**: 使用项目统一的术语和命名规范
- **格式规范**: 遵循 Markdown 格式和项目文档标准

## 📝 文档编写流程

### 阶段 1: 准备工作

#### 1.1 理解模块功能
```bash
# 分析清单

□ 模块的主要使用场景有哪些？
□ 模块的技术架构和依赖关系？
```

#### 1.2 确定读者群体
- **内部开发者**: 需要了解实现细节和 API
- **外部使用者**: 需要了解集成方法和使用示例

### 阶段 3: 内容编写

#### 3.1 模块简介 (核心部分)
**写作要点**:
- 用通俗语言解释模块的用途
- 列出 3-5 个核心功能点
- 说明模块的业务价值

**示例**:
```markdown
## 🎯 模块简介

### 模块用途
患者管理模块是 LYBT 系统的核心模块之一，负责管理患者的基本信息、就诊记录和医疗档案。支持患者信息的全生命周期管理，从建档到随访的完整流程。

### 核心功能
- **患者建档**: 创建和维护患者基本信息
- **就诊记录**: 记录患者的就诊历史和诊断信息
- **档案管理**: 管理患者的医疗文档和检查报告
- **信息查询**: 提供多维度患者信息检索功能

### 业务价值
- 提高患者信息管理效率 30%
- 减少信息查找时间 50%
- 确保患者数据的安全性和完整性
```

#### 3.2 技术实现 (关键章节)
**Server 端实现**:
- 实体模型设计
- 服务接口定义
- 业务逻辑实现

**Client 端实现**:
- ViewModel 设计
- Repository 实现
- View 交互逻辑

**写作技巧**:
- 使用代码片段说明关键实现
- 添加注释解释设计意图
- 说明技术选型的原因

## ✍️ 写作技巧

### 1. 标题和段落
- **标题简洁**: 使用动词开头的简洁标题
- **段落适中**: 每段 3-5 句话，避免过长段落
- **逻辑清晰**: 使用标题层级组织内容结构

### 2. 代码示例
- **完整可运行**: 确保代码示例可以直接执行
- **上下文充分**: 提供必要的上下文信息
- **注释详细**: 添加行内注释解释关键代码

### 3. 链接和引用
- **内部链接**: 链接到相关的模块文档
- **外部资源**: 引用官方文档和最佳实践
- **更新维护**: 定期检查链接有效性

### 4. 术语和定义
- **术语一致**: 使用项目统一的术语表
- **首字母缩写**: 在首次使用时定义缩写
- **避免歧义**: 使用精确的技术术语

## 🚫 常见错误

### 1. 内容问题
- ❌ 信息过时：文档与实际代码不符
- ❌ 语义模糊：使用不确定的表述
- ❌ 信息冗余：重复相同的信息

### 2. 结构问题
- ❌ 层级混乱：标题层级不合理
- ❌ 逻辑断裂：章节之间缺乏联系
- ❌ 重点不明：重要信息不突出

### 3. 技术问题
- ❌ 代码错误：示例代码无法运行
- ❌ 版本不符：文档与代码版本不一致
- ❌ 格式错误：Markdown 格式不正确

## 📏 质量标准

### 内容质量指标
- **准确性**: 技术信息 100% 准确
- **完整性**: 覆盖所有重要功能点
- **实用性**: 90% 的读者能够成功完成任务

### 格式规范
- **结构一致性**: 严格遵循模板结构
- **格式规范性**: Markdown 格式 100% 正确
- **链接有效性**: 所有链接都能正常访问

### 可读性标准
- **语言清晰**: 使用简洁明了的表达
- **逻辑清晰**: 内容组织有逻辑性
- **示例充分**: 提供足够的代码示例
