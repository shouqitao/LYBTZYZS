# 已废弃：统一工作流程

> **状态**: 已废弃
> **废弃日期**: 2025-11-13
> **替代方案**: [需求驱动工作流程](../../guides/requirement-driven-workflow.md)

---

## 废弃原因

此文档描述的四阶段工作流程（RETRIEVE → EXECUTE → STORE → CLEANUP）已被更完整的**需求驱动工作流程**所替代。

## 问题分析

1. **缺少需求起点**: 原流程从知识检索开始，没有需求确认和方案设计阶段
2. **不完整**: 缺少GitHub Issue跟踪、PR流程、用户确认等关键环节
3. **不实用**: 没有考虑大需求(Epic)和小需求(Issue)的区别
4. **缺少技能调用**: 没有集成LYBTZYZS专门的自动化Skills

## 新流程优势

### 需求驱动
- 从需求分析开始，符合实际开发流程
- 大需求和小需求分别处理
- 明确的决策点和检查清单

### 技能集成
- 自动生成需求确认文档
- 自动生成方案设计文档
- 自动执行GitHub Issues
- 自动生成PR描述

### 完整闭环
- 需求 → 设计 → 开发 → 验证 → 交付
- Graphiti记忆存储决策和经验
- 环境清理确保代码整洁

## 迁移指南
