# DT-006 异常处理统一化 - Service层统一异常处理

## 描述

统一Service层的异常处理模式，消除部分Service有异常处理而部分缺乏的不一致问题，提升系统调试效率和用户体验。

## 验收标准

- [ ] 创建统一的异常处理装饰器机制
- [ ] 为所有Service层方法添加统一异常处理
- [ ] 建立异常分类和标准化错误消息体系
- [ ] 确保异常信息对用户友好且便于调试
- [ ] 现有功能正常工作，无业务逻辑回归

## 技术要求

### 实现范围

**核心Service层**：
- AuthService/AuthModule - 认证相关异常处理
- UserService/UserModule - 用户管理异常处理
- PatientService/PatientModule - 患者信息异常处理
- ConsultationService/ConsultationModule - 诊疗异常处理
- PrescriptionService/PrescriptionModule - 处方异常处理
- HerbService/HerbModule - 药材管理异常处理
- FormulaService/FormulaModule - 验方管理异常处理
- MedicalCaseService/MedicalCaseModule - 医疗案例异常处理

**异常处理标准化**：
- 建立异常分类体系（业务异常、系统异常、验证异常）
- 统一异常日志格式
- 标准化用户友好错误消息

### 技术设计

```csharp
// 统一异常处理装饰器
public class ServiceExceptionHandler<T> : IServiceExceptionHandler<T>
{
    private readonly ILogger<ServiceExceptionHandler<T>> _logger;
    
    public async Task<ServiceResult<T>> ExecuteAsync<TResult>(
        Func<Task<ServiceResult<TResult>>> operation,
        string operationName,
        object context = null)
    {
        try
        {
            return await operation();
        }
        catch (ValidationException ex)
        {
            _logger.LogWarning(ex, "验证失败 - {OperationName}: {Message}", 
                operationName, ex.Message);
            return ServiceResult<TResult>.Failure($"输入验证失败: {ex.Message}");
        }
        catch (BusinessException ex)
        {
            _logger.LogWarning(ex, "业务逻辑异常 - {OperationName}: {Message}", 
                operationName, ex.Message);
            return ServiceResult<TResult>.Failure(ex.Message);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "系统异常 - {OperationName} 执行失败. Context: {@Context}", 
                operationName, context);
            return ServiceResult<TResult>.Failure($"系统繁忙，请稍后重试");
        }
    }
}

// 异常处理特性注解
[AttributeUsage(AttributeTargets.Method)]
public class HandleExceptionsAttribute : Attribute
{
    public string OperationName { get; set; }
    public bool LogContext { get; set; } = false;
}

// 业务异常基类
public class BusinessException : Exception
{
    public string ErrorCode { get; }
    
    public BusinessException(string message, string errorCode = null) 
        : base(message)
    {
        ErrorCode = errorCode;
    }
}
```

## 风险评估

### 中等风险
- 涉及所有Service层的修改，影响面较广
- 异常处理逻辑变更可能影响现有错误处理流程
- 需要确保不改变现有业务逻辑行为

### 风险缓解措施
- 采用装饰器模式，最小化对现有代码的侵入
- 分阶段实施，逐步验证每个Service的处理效果
- 保留原有异常处理逻辑作为回滚方案
- 充分的测试覆盖，包括异常场景测试
