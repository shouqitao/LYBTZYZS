# DT-004 基础查询优化 - AsNoTracking实现

## 描述

优化所有只读查询操作，添加 `.AsNoTracking()` 以提升查询性能和减少内存占用。EF Core 的变更跟踪对只读操作是不必要的开销。

## 验收标准

- [ ] 识别所有只读查询场景（Search、Get、List等方法）
- [ ] 为适用的查询添加 `.AsNoTracking()` 调用
- [ ] 验证查询性能提升（通过日志或性能监控）
- [ ] 确保现有测试仍然通过
- [ ] 更新相关文档说明何时使用 AsNoTracking

## 技术要求

### 实现范围

**Repository层优化**：
- UserRepository：SearchUsersAsync, GetUsersByRoleAsync等查询
- PatientRepository：SearchPatientsAsync, GetPatientStatisticsAsync等
- HerbRepository：SearchHerbsAsync, GetHerbStatisticsAsync等
- 其他Repository的类似只读查询方法

**QueryService层优化**：
- 所有Service层的复杂查询方法
- 统计和报表相关查询
- 搜索和筛选功能

### 技术标准

```csharp
// 优化前
public async Task<List<UserDto>> GetUsersByRoleAsync(UserRole role)
{
    return await _context.Users
        .Where(u => u.Role == role)
        .Select(u => new UserDto { ... })
        .ToListAsync();
}

// 优化后  
public async Task<List<UserDto>> GetUsersByRoleAsync(UserRole role)
{
    return await _context.Users
        .AsNoTracking()
        .Where(u => u.Role == role)
        .Select(u => new UserDto { ... })
        .ToListAsync();
}
```

## 风险评估

### 低风险
- AsNoTracking是EF Core标准优化技术
- 仅影响查询性能，不改变业务逻辑
- 对只读查询无副作用

### 注意事项
- 确认查询确实是只读的（无后续Update操作）
- 避免在需要延迟加载的场景中使用
- 注意Select投影可能已隐含AsNoTracking效果
