# Task 001: Create Modular Service Auto-Discovery System

## Overview

Replace the current 200+ line ServiceCollectionExtensions.cs with a convention-over-configuration auto-discovery system that automatically registers services following established naming patterns.

## Business Justification

The current manual service registration in ServiceCollectionExtensions.cs is error-prone and maintenance-heavy. This task creates a sustainable foundation for the entire frontend architecture refactor.

## Technical Requirements

### Core Implementation
- Create `IModuleServiceRegistrar` interface for module-specific registration
- Implement assembly scanning to auto-discover services following pattern: `I{Module}Service` → `{Module}Module`
- Preserve existing service lifetimes (typically Singleton for modules)
- Maintain backward compatibility with current registration

### Expected Patterns
```csharp
// Auto-discovery should register these automatically:
IAuthService -> AuthModule
IUserService -> UserModule  
IPatientService -> PatientModule
// etc.
```

### Assembly Scanning Rules
- Scan current executing assembly for service interfaces
- Match interfaces ending with "Service" to classes ending with "Module"
- Validate that implementing class exists before registration
- Log discovered registrations for debugging

## Implementation Steps

1. **Create Core Infrastructure** (8 hours)
   - Define `IModuleServiceRegistrar` interface
   - Create `ServiceDiscovery` static class with scanning logic
   - Add logging for registration discovery process

2. **Implement Auto-Discovery Logic** (8 hours)
   - Assembly reflection to find matching interface/implementation pairs
   - Validate service registration rules
   - Create fallback to manual registration for edge cases

3. **Integration and Validation** (8 hours)
   - Replace calls in existing ServiceCollectionExtensions.cs
   - Add validation to ensure all expected services are registered
   - Create diagnostic endpoint to view discovered registrations

## Acceptance Criteria

### Must Have
- [ ] All existing services continue to work without modification
- [ ] New services can be added by simply creating Interface + Implementation following naming convention
- [ ] Build-time validation ensures all expected services are registered
- [ ] Startup time increases by < 100ms due to reflection

### Should Have
- [ ] Diagnostic logging shows which services were auto-discovered vs manually registered
- [ ] Clear error messages when interface/implementation pairs don't match
- [ ] Support for module-specific registration overrides

### Won't Have (This Task)
- Registration for non-module services (repositories, etc.)
- Complex lifetime management beyond current patterns
- Cross-assembly service discovery
