# Task 002: Implement Build-Time Dependency Validation

## Overview

Create Roslyn analyzer and MSBuild targets to validate service dependencies at compile time, preventing runtime dependency injection errors that currently plague the application.

## Business Justification

Runtime DI errors are one of the most common causes of application crashes. Moving this validation to build time will eliminate 95% of these errors and improve developer confidence.

## Technical Requirements

### Core Implementation
- Create Roslyn analyzer to validate dependency injection patterns
- Add MSBuild target for dependency validation during compilation
- Generate clear, actionable error messages for DI issues
- Integrate validation with existing build pipeline

### Validation Rules
```csharp
// These should be validated at build time:
// ✓ Valid: Constructor parameter matches registered service
public class SomeViewModel(IAuthService authService) 

// ✗ Invalid: Unregistered service dependency  
public class BadViewModel(INonExistentService service)

// ✗ Invalid: Circular dependency detection
public class ServiceA(ServiceB b) where ServiceB(ServiceA a)
```

### MSBuild Integration
- Custom MSBuild task that runs during build
- Fails build if critical DI issues are found
- Provides warnings for potential issues
- Integrates with Visual Studio error list

## Implementation Steps

1. **Create Roslyn Analyzer** (8 hours)
   - Implement analyzer to scan constructor dependencies
   - Validate against discovered service registrations from Task 001
   - Create diagnostic rules for common DI anti-patterns

2. **MSBuild Target Creation** (4 hours)
   - Create custom MSBuild target that invokes validation
   - Configure to run during BeforeBuild target
   - Add conditional execution to avoid performance impact in Debug builds

3. **Integration and Error Reporting** (4 hours)
   - Integrate analyzer with Visual Studio error experience
   - Create clear error messages with suggested fixes
   - Add configuration options for validation strictness

## Acceptance Criteria

### Must Have
- [ ] Build fails when unregistered services are injected into constructors
- [ ] Clear error messages indicate which service is missing and where
- [ ] Validation runs automatically during build in Release configuration
- [ ] Performance impact < 15% increase in build time

### Should Have
- [ ] Circular dependency detection with clear cycle identification
- [ ] Warning for services with complex dependency chains (> 3 levels deep)
- [ ] Configuration option to disable validation for specific files/projects
- [ ] Integration with IntelliSense for immediate feedback during typing

### Won't Have (This Task)
- Runtime performance monitoring of DI container
- Automatic service registration suggestion
- Cross-project dependency validation

## Notes and Considerations

### Implementation Notes
- Use `Microsoft.CodeAnalysis.Analyzers` package for Roslyn analyzer
- Consider caching validation results between builds
- Validate against both auto-discovered and manually registered services

### Edge Cases
- Generic service dependencies may need special handling
- Optional dependencies (nullable parameters) should be validated differently
- Services registered conditionally may need runtime validation

### Performance Considerations
- Cache dependency graph between builds
- Only validate changed files in incremental builds
- Consider parallel analysis for large projects

### Future Enhancements
- Integration with dependency graph visualization tools
- Automatic service registration suggestions for missing dependencies
