# Task 009: Enhanced Cross-Component Communication

## Overview

Create standardized patterns for cross-component communication using Prism EventAggregator, building on reactive session management (Task 004) and standardized async patterns (Task 008) to provide consistent, type-safe communication between ViewModels and components.

## Business Justification

Current ad-hoc communication patterns lead to:
- Tight coupling between components
- Difficult-to-debug communication flows
- Inconsistent message handling
- Memory leaks from unsubscribed event handlers

## Technical Requirements

### Core Implementation
- Standardize EventAggregator usage patterns across the application
- Create typed event definitions for common communication scenarios
- Implement automatic subscription management to prevent memory leaks
- Provide debugging and monitoring tools for event communication

### Standardized Event Communication Pattern
```csharp
// Standard typed events
public class PatientSelectedEvent : PubSubEvent<PatientInfo>
{
    // Type-safe patient selection communication
}

public class OperationCompletedEvent : PubSubEvent<OperationResult>
{
    // Standard operation completion notification
}

public class NavigationRequestEvent : PubSubEvent<NavigationContext>
{
    // Consistent navigation request handling
}

// Enhanced ViewModel base with communication support
public abstract class CommunicatingViewModelBase : ModernViewModelBase, IDisposable
{
    protected readonly IEventAggregator EventAggregator;
    private readonly List<SubscriptionToken> _subscriptions = new();
    
    protected void Subscribe<T>(Action<T> handler) where T : PubSubEvent<T>, new()
    {
        var token = EventAggregator.GetEvent<T>().Subscribe(handler, ThreadOption.UIThread);
        _subscriptions.Add(token);
    }
    
    protected void Publish<T>(T eventData) where T : class
    {
        EventAggregator.GetEvent<PubSubEvent<T>>().Publish(eventData);
    }
    
    // Automatic cleanup prevents memory leaks
    public virtual void Dispose()
    {
        foreach (var token in _subscriptions)
        {
            token.Dispose();
        }
        _subscriptions.Clear();
    }
}
```

### Communication Patterns
```csharp
// Standard patterns for common scenarios:

// 1. Data Selection Communication
public class PatientListViewModel : CommunicatingViewModelBase
{
    private void OnPatientSelected(Patient patient)
    {
        Publish(new PatientSelectedEvent { Patient = patient });
    }
}

public class PatientDetailsViewModel : CommunicatingViewModelBase
{
    public PatientDetailsViewModel(IEventAggregator eventAggregator)
    {
        Subscribe<PatientSelectedEvent>(OnPatientSelected);
    }
    
    private void OnPatientSelected(PatientSelectedEvent args)
    {
        LoadPatientDetails(args.Patient.Id);
    }
}

// 2. Operation Status Communication
public class DataService : ICommunicatingService
{
    public async Task<Result> SavePatientAsync(Patient patient)
    {
        var result = await _repository.SaveAsync(patient);
        Publish(new OperationCompletedEvent 
        { 
            Operation = "SavePatient", 
            Success = result.IsSuccess,
            Message = result.Message 
        });
        return result;
    }
}
```

## Notes and Considerations

### Implementation Notes
- Use weak event patterns where appropriate to prevent memory leaks
- Implement proper disposal patterns in base classes
- Consider using `ThreadOption.UIThread` for UI-bound event handlers

### Event Categories and Naming
1. **Selection Events**: `{Entity}SelectedEvent` (PatientSelectedEvent, UserSelectedEvent)
2. **Operation Events**: `{Operation}CompletedEvent` (SaveCompletedEvent, DeleteCompletedEvent)
3. **Navigation Events**: `NavigationRequestEvent`, `PageChangedEvent`
4. **State Events**: `{State}ChangedEvent` (SessionStateChangedEvent, ThemeChangedEvent)
5. **Data Events**: `{Entity}UpdatedEvent` (PatientUpdatedEvent, ConfigurationChangedEvent)

### Communication Patterns
1. **Selection Communication**: List views publish selection events, detail views subscribe
2. **Operation Notification**: Services publish completion events, UI components subscribe
3. **Navigation Coordination**: Navigation requests published by any component, handled by navigation service
4. **State Synchronization**: State changes published automatically, dependent components subscribe

### Memory Management
- Automatic subscription cleanup in Dispose method
- Use of SubscriptionToken for proper cleanup
- Weak event patterns for long-lived subscribers
- Monitoring tools to detect subscription leaks

### Threading Considerations
- All UI-bound events use ThreadOption.UIThread
- Service events may use ThreadOption.BackgroundThread
- Proper synchronization for cross-thread communication
- Deadlock prevention in event handler chains

### Debugging and Monitoring
- Event publication logging in debug mode
- Subscription counting and leak detection
- Event flow visualization tools
- Performance monitoring for event-heavy scenarios

### Future Enhancements
