# Task 006: Systematic Resource Dictionary Restructuring

## Overview

Reorganize the existing UnifiedDesignSystem.xaml and related resource dictionaries into logical, modular components with systematic resource definitions to prevent runtime resource errors like the recent ToolBarContainer issue.

## Business Justification

The current monolithic resource dictionary approach leads to:
- Runtime resource errors (ToolBarContainer, missing styles)
- Difficulty finding and maintaining resources
- Circular reference issues between resource dictionaries
- Inconsistent resource naming and organization

## Technical Requirements

### Core Implementation
- Break down UnifiedDesignSystem.xaml into logical modules
- Create systematic resource naming conventions
- Implement build-time resource validation
- Organize resources by functional area and component type

### Resource Organization Structure
```
Resources/
├── Core/
│   ├── Colors.xaml           # Color palette and theme colors
│   ├── Typography.xaml       # Font families, sizes, weights
│   └── Spacing.xaml          # Margins, padding standards
├── Controls/
│   ├── Buttons.xaml          # Button styles and templates
│   ├── TextBoxes.xaml        # Input control styles  
│   ├── DataGrids.xaml        # Data display controls
│   └── ToolBars.xaml         # Toolbar and menu styles
├── Themes/
│   ├── LightTheme.xaml       # Light theme definitions
│   └── DarkTheme.xaml        # Dark theme definitions (future)
└── Application/
    ├── MainWindow.xaml       # Main window specific resources
    └── Dialogs.xaml          # Dialog and popup resources
```

### Resource Naming Convention
```xaml
<!-- Systematic naming pattern: {Category}.{Control}.{Variant}.{Property} -->
<Style x:Key="Button.Primary.Default" TargetType="Button" />
<Style x:Key="TextBox.Search.Default" TargetType="TextBox" />
<Style x:Key="DataGrid.Patients.Default" TargetType="DataGrid" />

<!-- Color naming: {Semantic}.{Shade} -->
<Color x:Key="Primary.500">#2563EB</Color>
<Color x:Key="Success.600">#059669</Color>
<Color x:Key="Background.Default">#FFFFFF</Color>
```

## Notes and Considerations

### Migration Strategy
- Use alias approach during transition: keep old resource keys working while adding new ones
- Migrate view by view to avoid massive breaking changes
- Provide clear mapping from old resource names to new ones

### Resource Organization Principles
1. **Semantic over Visual**: Name resources by their purpose, not appearance
2. **Consistent Hierarchy**: Follow established naming patterns
3. **Modular Loading**: Each dictionary should be loadable independently
4. **Clear Dependencies**: Avoid circular references between dictionaries

### Performance Considerations
- Lazy loading of resource dictionaries where possible
- Minimize resource dictionary merging depth
- Consider resource compilation optimization
