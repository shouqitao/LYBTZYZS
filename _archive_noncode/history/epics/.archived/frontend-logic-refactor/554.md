# Task 008: Standardized Async Operation Patterns

## Overview

Create standardized patterns for async operations in ViewModels, extending the existing ModernViewModelBase and AsyncRelayCommand patterns to provide consistent progress indication, error handling, and cancellation support across the application.

## Business Justification

Inconsistent async operation handling leads to:
- Poor user experience with no progress feedback
- Inconsistent error handling and user messaging
- UI freezing during long operations
- Difficulty debugging async operation failures

## Technical Requirements

### Core Implementation
- Extend existing ModernViewModelBase with standardized async patterns
- Enhance AsyncRelayCommand usage with consistent progress and error handling
- Create standardized progress indication and cancellation patterns
- Integrate with reactive session management from Task 004

### Standardized Async Operation Pattern
```csharp
public abstract class ModernViewModelBase : BindableBase
{
    // Existing functionality preserved
    
    // New standardized async operation support
    protected async Task ExecuteWithProgressAsync<T>(
        Func<IProgress<OperationProgress>, CancellationToken, Task<T>> operation,
        string operationName,
        Action<T> onSuccess = null,
        bool showProgress = true)
    {
        // Standard implementation for progress, errors, cancellation
    }
    
    // Standard progress properties
    public bool IsOperationInProgress { get; protected set; }
    public string CurrentOperationName { get; protected set; }
    public double OperationProgress { get; protected set; }
    public bool CanCancelOperation { get; protected set; }
    
    // Standard error handling
    public string LastErrorMessage { get; protected set; }
    public bool HasError { get; protected set; }
}

public class OperationProgress
{
    public double Percentage { get; set; }
    public string Message { get; set; }
    public bool CanCancel { get; set; }
}
```

### Enhanced AsyncRelayCommand Integration
```csharp
// Standard pattern for async commands in ViewModels:
public AsyncRelayCommand LoadDataCommand => _loadDataCommand ??= new AsyncRelayCommand(
    async (ct) => await ExecuteWithProgressAsync(
        async (progress, token) => await _service.LoadDataAsync(progress, token),
        "加载数据",
        data => UpdateUI(data),
        showProgress: true
    ),
    () => !IsOperationInProgress
);
```

## Notes and Considerations

### Implementation Notes
- Use `ConfigureAwait(false)` for all async operations to avoid deadlocks
- Implement proper IDisposable pattern for progress handlers
- Consider using `SemaphoreSlim` for operation concurrency control

### Progress Reporting Patterns
1. **Simple Progress**: Just percentage and basic message
2. **Detailed Progress**: Step-by-step operation breakdown
3. **Indeterminate Progress**: For operations without predictable duration
4. **Background Progress**: For operations that don't require user attention

### Error Handling Strategies
1. **User-Facing Errors**: Clear, actionable messages in Chinese
2. **Developer Errors**: Detailed technical information in logs
3. **Recoverable Errors**: Automatic retry with user notification
4. **Fatal Errors**: Graceful degradation with error reporting

### Cancellation Support Levels
1. **Immediate**: Operations that can stop immediately
2. **Clean**: Operations that need to finish current step before stopping
3. **Background**: Operations that continue but don't block UI
4. **Non-Cancellable**: Critical operations that must complete

### UI Integration Points
- Progress bars for operations with known duration
- Spinning indicators for indeterminate operations
- Cancel buttons for cancellable operations
- Error panels with retry/dismiss options
- Toast notifications for background operation completion
