# Task: Interface & Architecture Cleanup

## Description
Eliminate critical interface duplication and architectural inconsistencies by consolidating IModule/IService patterns, optimizing dependency injection containers, and ensuring full UltraThink dual-layer architecture compliance. This task addresses the core structural issues identified in "接口重复定义横跨4层" problem and establishes clean separation between frontend and backend architectural patterns.

## Acceptance Criteria
- [ ] All IModule interfaces eliminated from frontend (8 modules: Auth, Users, Patients, MedicalCase, Consultation, Prescriptions, Herbs, Formula)
- [ ] Frontend dependency injection consolidated to IService interfaces only
- [ ] UltraThink dual-layer architecture compliance verified: QueryService + BusinessService + Module纯委托
- [ ] Dependency injection container optimized with consistent registration patterns
- [ ] Interface segregation principle applied to eliminate fat interfaces
- [ ] Circular dependency issues resolved across all modules
- [ ] Frontend-backend architectural boundary clearly defined and enforced
- [ ] ViewModel dependency injection standardized to IService interfaces
- [ ] Service registration patterns unified across all 8 business modules
- [ ] Interface naming conventions standardized (I{ModuleName}Service pattern)

## Technical Details
- Remove duplicate IModule interfaces: IAuthModule, IUserModule, IPatientModule, etc.
- Consolidate to single IService interface pattern: IAuthService, IUserService, IPatientService, etc.
- Update all ViewModel constructors to inject IService interfaces instead of concrete Module types
- Optimize Prism.DryIoc container registrations for consistent service lifecycle management
- Implement UltraThink pure delegation pattern in main Module classes
- Separate QueryService and BusinessService registration patterns
- Apply dependency inversion principle consistently across frontend architecture
- Remove CS0246 errors caused by missing interface definitions
- Establish clear frontend (UltraThink dual-layer) vs backend (traditional 3-layer) architectural boundaries
- Implement interface versioning strategy for future evolution
