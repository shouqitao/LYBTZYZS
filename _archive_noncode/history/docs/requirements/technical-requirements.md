## 🏗️ 技术架构需求

### 总体架构原则
- **简洁性原则**: 避免过度设计，专注业务实现
- **实用性原则**: 技术选择以稳定可靠为优先
- **可维护性**: 适合小团队维护的技术复杂度
- **成本效益**: 最小化技术学习和维护成本

### 架构模式需求
```
TR-ARCH-001: 后端架构模式
- 架构类型: UltraThink双层架构 (实际三层实现)
- 服务层次: 主Service(纯委托) + QueryService(查询专业) + BusinessService(业务逻辑)
- 数据访问: Repository模式 + 统一AppDbContext + 零SQL注入(LINQ)
- 要求: 避免过度抽象，职责清晰分离

TR-ARCH-002: 前端架构模式  
- 架构类型: MVVM模式
- 框架选择: Prism.DryIoc模块化
- 调用方式: ViewModel直接调用Service
- 要求: 移除Coordinator抽象层
```

## 🔧 性能需求

### TR-PERF-001: 响应时间需求
```
- API响应时间: < 2秒 (95%请求)
- 页面加载时间: < 3秒 (首次加载)
- 页面切换时间: < 1秒 (模块间切换)
- 数据库查询: < 1秒 (常规查询)
```

### TR-PERF-002: 并发性能需求
```
- 同时在线用户: 支持10个用户
- 数据库连接池: Max=20, Min=2
- 内存使用: 客户端 < 500MB
- CPU使用率: 正常运行 < 20%
```

### TR-PERF-003: 数据处理需求
```
- 患者数据: 支持10,000条记录
- 医案数据: 支持50,000条记录

- 导入导出: 支持1,000条/次批量操作
```

## 🛡️ 安全需求

### TR-SEC-001: 身份认证需求
```
- 认证方式: JWT Bearer Token
- Token有效期: 8小时 (普通) / 30天 (记住登录)
- 密码策略: 大小写+数字+特殊字符，8位以上
- 登录失败: 5次失败后锁定账户30分钟
```

### TR-SEC-002: 数据安全需求
```
- 数据库访问: 参数化查询，零SQL注入风险
- 密码存储: AspNetCore Identity标准哈希
- 敏感数据: 加密存储关键业务数据
- 数据传输: HTTPS强制加密
```

### TR-SEC-003: 访问控制需求
```
- 权限模型: RBAC (基于角色的访问控制)
- 角色定义: Admin(管理员) / Doctor(医生)
- 权限粒度: 接口级别权限验证
- 操作审计: 关键操作日志记录
```

## 📋 技术约束

### TR-CONST-001: 技术选择约束
```
❌ 禁止使用的技术:
- 微服务架构 (过度设计)
- 容器化部署 (增加运维复杂度)
- NoSQL数据库 (增加技术复杂度)
- 复杂缓存方案 (Redis等分布式缓存)
- 消息队列 (同步调用已足够)

✅ 必须使用的技术:
- .NET 8长期支持版本
- SQL Server关系数据库
- WPF桌面应用框架
- IIS传统Web部署
- MemoryCache内存缓存
```

### TR-CONST-002: 架构约束
```
- 单体应用架构 (避免分布式复杂度)
- 统一数据上下文 (AppDbContext)
- 异步优先模式 (async/await用于数据库操作)
- 传统部署方式 (IIS + Windows Server)
```

### TR-CONST-003: 团队约束
```
- 开发团队规模: 1-2人
- 技术维护能力: 中级.NET开发水平
- 学习时间限制: 新技术学习时间 < 1周
- 维护时间限制: 日常维护时间 < 2小时/周
```
