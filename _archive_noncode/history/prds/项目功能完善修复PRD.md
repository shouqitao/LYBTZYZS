## 需求背景

基于Phase 3业务流程验证和TODO替换进度评估的深度分析，发现LYBTZYZS中医诊所系统存在两大类关键问题，严重影响系统的生产可用性和用户体验：

### 核心问题识别
1. **🔴 前端功能人为限制** - 系统致命缺陷，导致核心医疗功能不可用
2. **🟡 UI用户体验优化** - 用户友好性不足，影响使用满意度

### 问题严重性
- **系统整体可用性**: 仅25%
- **完整诊疗流程**: 0%可用（3个关键断点）
- **医案管理功能**: 15%可用（7个功能被禁用）
- **中医四诊专业**: 5%可用（核心专业功能缺失）

## 需求目标

### 主要目标
- **系统可用性提升**: 从25%提升到90%
- **核心医疗功能**: 从不可用变为完全可用
- **用户体验优化**: 从困惑不解变为专业满意

## 详细需求规格

### P0级需求：前端功能限制修复

#### 需求描述
**严重问题**: 系统后端提供95%完整的企业级API，但前端被"简单诊所版本暂不支持"人为限制到30%可用性，导致核心医疗流程完全不可用。

#### 修复范围

**1. MedicalCase模块功能恢复**
```csharp
// 当前问题代码
public async Task<ServiceResult<MedicalCaseDto>> CreateAsync(MedicalCaseCreateDto dto)
    => ServiceResult<MedicalCaseDto>.Failure("简单诊所版本暂不支持创建医疗案例");

// 修复目标
public async Task<ServiceResult<MedicalCaseDto>> CreateAsync(MedicalCaseCreateDto dto)
{
    try
    {
        var result = await _apiManager.MedicalCaseApi.CreateAsync(dto);
        return ServiceResult<MedicalCaseDto>.Success(result, "医案创建成功");
    }
    catch (Exception ex)
    {
        return ApiExceptionHandler.HandleApiException<MedicalCaseDto>(ex, "创建医案", dto);
    }
}
```

**需要恢复的方法**:
- ✅ `CreateAsync` - 医案创建功能
- ✅ `UpdateAsync` - 医案更新功能
- ✅ `SuspendAsync` - 医案暂停功能
- ✅ `ResumeAsync` - 医案恢复功能
- ✅ `ArchiveAsync` - 医案归档功能
- ✅ `CompleteAsync` - 医案完成功能
- ✅ `SearchAsync` - 医案搜索功能

**2. Consultation模块功能恢复**
- ✅ `StartAsync` - 开始看诊功能
- ✅ `SaveFourDiagnosisAsync` - 四诊数据保存功能
- ✅ `GetFourDiagnosisByMedicalCaseIdAsync` - 四诊数据查询功能

**3. 其他模块全面审查**
- Formula模块: 验方分析、推荐、复制功能
- Users模块: 高级用户管理功能
- Prescriptions模块: 高级处方功能
