## 📝 使用方法

### 阶段1：需求分析阶段
1. 填写 `requirements-checklist.md` 的"1-4节"（需求定义、范围管理、Constitution合规、技术可行性）
2. 根据MVP需求定义验收标准
3. 识别依赖关系和影响范围

### 阶段2：设计阶段
1. 更新 `requirements-checklist.md` 的"5-6节"（文档质量、可追溯性）
2. 填写 `security-checklist.md` 的设计相关检查项
3. 评估安全风险并制定缓解措施

### 阶段3：实施阶段
1. 开发过程中参考Checklist要求
2. 确保代码符合Constitution约束
3. 实施安全措施（加密、权限控制、审计日志）

### 阶段4：测试验证阶段
1. 完成所有Checklist检查项
2. 填写"质量检查总结"部分
3. 计算通过率（必选清单≥90%）

### 阶段5：PR审查阶段
1. 在PR描述中附上Checklist验证结果摘要
2. 说明未通过项的原因和计划
3. 获得审批后才能合并

## ✅ MVP验收标准映射

根据 `docs/tasks/mvp-task-checklist-2025-10-16.md` 定义的验收标准：

### 1. 完整诊疗流程可执行（P0）
- [x] 用户可以登录系统（已实现）
- [ ] 用户可以查找或创建患者
- [ ] 用户可以为患者创建医案
- [ ] 用户可以录入四诊合参（望闻问切）
- [ ] 用户可以录入辨证论治（中医诊断、治疗原则）
- [ ] 用户可以开具处方（添加药材、设置剂数）
- [ ] 系统可以自动计算处方价格
- [ ] 用户可以保存诊疗记录和处方

### 2. 数据持久化正确（P0）
- [ ] 四诊合参数据正确保存到数据库
- [ ] 处方和药材关联正确
- [ ] 医案状态正确流转
- [ ] 价格计算结果正确保存

### 3. 用户体验基本流畅（P1）
- [ ] 界面响应速度可接受（<2秒）
- [ ] 表单验证提示清晰
- [ ] 错误提示友好

### 4. 代码质量符合标准（P1）
- [ ] 编译无错误
- [ ] 单元测试通过率>80%
- [ ] 无明显过度设计代码
- [ ] 遵循架构设计标准
