### 2. 异常分支/边界值/极端条件测试体系化

**测试分类体系**:

```csharp
// 1. 业务失败分支测试模板
[Fact]
public async Task Method_Should_Return_Failure_When_Service_Fails()
{
    // 标准异常分支验证模式
    _mockService.Setup().ReturnsAsync(ServiceResult<T>.Failure("错误信息"));
    var result = await _service.Method();
    result.IsSuccess.Should().BeFalse();
}

// 2. 边界值测试模板
[Fact]  
public async Task Method_With_Boundary_Value_Should_Handle_Gracefully()
{
    // 空值、极值、边界条件测试
    var result = await _service.Method(Guid.Empty);
    result.Should().NotBeNull();
}

// 3. 极端条件测试模板
[Fact]
public async Task Method_With_Extreme_Value_Should_Handle_Gracefully()
{
    // 大数值、长字符串、高并发等极端条件
    var result = await _service.Method(999999);
    result.Data.PageSize.Should().Be(999999);
}
```

**覆盖效果**: 46个新测试用例，100%覆盖异常、边界、极端三大分类

### 3. Mock架构模板化

**UltraThink双层架构Mock标准**:

```csharp
public class SimpleServiceTests
{
    private readonly Service _service;                           // 主Service委托层
    private readonly Mock<IQueryService> _mockQueryService;      // 查询层Mock
    private readonly Mock<IBusinessService> _mockBusinessService; // 业务层Mock
    
    public SimpleServiceTests()
    {
        _mockQueryService = new Mock<IQueryService>();
        _mockBusinessService = new Mock<IBusinessService>();
        _service = new Service(_mockQueryService.Object, _mockBusinessService.Object);
    }
}
```

**模板应用**: 8个模块100%采用统一Mock架构，零架构偏差

### 4. 接口验证与兼容性修复流程

**标准流程**:
1. **接口分析**: 读取IService接口定义，确认方法签名和参数类型
2. **类型匹配**: 验证测试用例中的DTO类型与接口参数一致性
3. **方法存在性**: 确认测试的方法在接口中确实存在
4. **兼容性修复**: 发现不匹配时，以接口定义为准进行修复
5. **验证测试**: 确保修复后编译通过且测试成功

**典型案例**: Herbs模块`HerbQueryDto` → `HerbPagedQueryDto`修复，`GetByCategoryAsync`不存在方法移除
