# WebAPI CORS治理规则

## 🎯 总则

基于WebAPI CORS审计与清理任务（2025-09-15），建立以下治理规则以防止未来引入不必要的CORS配置。

## 📋 架构决策规则

### 规则001: CORS使用适用性判断

**决策点**: 是否需要CORS功能

**判断标准**:
- ✅ **需要CORS**: 浏览器+Web服务器架构（如React/Vue+WebAPI、Angular+WebAPI等）
- ❌ **禁止CORS**: 桌面应用架构（WPF+WebAPI、WinForms+WebAPI、Console+WebAPI等）
- ❌ **禁止CORS**: 服务间调用（Microservices架构中的API-to-API调用）
- ❌ **禁止CORS**: 移动应用架构（iOS/Android App + WebAPI）

**本项目状态**: WPF+WebAPI架构，**禁止使用CORS**

### 规则002: 问题诊断优先级

**适用场景**: API调用失败问题诊断

**诊断顺序**:
1. **架构确认** (最高优先级)
   - 确认客户端类型：浏览器 vs 桌面应用 vs 移动应用
   - 桌面/移动应用跳过CORS相关检查

2. **路由配置** (高优先级)
   - 检查API版本约束注册
   - 检查路由模板匹配
   - 检查控制器名称和方法映射

3. **认证授权** (中等优先级)
   - 检查JWT Token有效性
   - 检查用户权限和角色

4. **业务逻辑** (低优先级)
   - 检查业务层异常
   - 检查数据库连接

**禁止行为**: 桌面应用架构中优先怀疑CORS问题

## 🔍 代码审查规则

### 规则003: CORS代码审查检查点

**触发条件**: PR中包含以下代码模式

**检查模式**:
```csharp
// 🚨 需要审查的代码模式
services.AddCors(...)           // 服务注册中的CORS配置
app.UseCors(...)               // 中间件中的CORS使用
[EnableCors]                   // 控制器或方法上的CORS特性
config.Cors                    // 配置文件中的CORS节点
CrossOriginResourceSharing     // 任何CORS相关命名
```

**审查要求**:
1. **架构合理性**: 确认当前架构是否真的需要CORS
2. **业务必要性**: 确认CORS配置解决的具体跨域场景
3. **安全性评估**: 确认CORS配置不会引入安全风险
4. **文档完整性**: 要求提供CORS使用的架构说明

**审查结果**:
- ✅ **通过**: 浏览器架构且有明确跨域需求
- ❌ **拒绝**: 桌面/移动应用架构无正当理由
- 🔄 **要求修改**: 需要提供更多架构说明

### 规则004: 配置文件检查

**检查范围**: 所有appsettings.*.json文件

**禁止配置** (本项目):
```json
{
  "Cors": {                    // 🚨 禁止
    "AllowedOrigins": [...],
    "AllowedMethods": [...],
    "AllowedHeaders": [...]
  }
}
```

**检查频率**: 每次配置文件变更

## 🛠️ 开发流程规则

### 规则005: 新项目模板规则

**要求**: 项目模板标准化

**桌面应用模板**:
- ❌ 不包含任何CORS相关代码
- ❌ 不包含CORS相关NuGet包引用
- ✅ 包含架构说明文档，明确说明无需CORS

**Web应用模板**:
- ✅ 包含CORS配置示例
- ✅ 包含安全CORS配置指导
- ✅ 包含CORS使用场景说明

### 规则006: 问题报告规则

**适用**: 用户报告"跨域问题"或"CORS问题"

**标准响应流程**:
1. **架构确认** (必须)
   - 询问客户端类型和技术栈
   - 确认是否为浏览器环境

2. **日志收集** (必须)
   - 要求提供服务器启动日志
   - 要求提供具体错误信息
   - 要求提供网络请求日志

3. **诊断顺序** (按规则002执行)
   - 桌面应用: 直接跳过CORS检查
   - Web应用: 按标准CORS问题排查

## ⚠️ 违规处理

### 规则009: 违规检测

**自动检测**: CI/CD流水线集成

**检测规则**:
```yaml
# .github/workflows/cors-check.yml
- name: Check CORS Usage
  run: |
    # 检查桌面应用项目中是否误用CORS
    if grep -r "AddCors\|UseCors\|EnableCors" src/Desktop/ ; then
      echo "❌ 桌面应用项目中发现CORS代码，违反治理规则003"
      exit 1
    fi
```

**人工检测**: 代码审查中执行

### 规则010: 违规处理流程

**处理级别**:
1. **警告级别**: 配置文件中出现CORS节点
   - 要求提供使用理由
   - 要求架构说明

2. **阻塞级别**: 桌面应用代码中出现CORS使用
   - 拒绝PR合并
   - 要求移除相关代码

3. **升级级别**: 重复违规或安全风险
   - 技术负责人介入
   - 架构评审
