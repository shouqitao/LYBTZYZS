# 批量操作部分成功模式

**批量操作部分成功模式**是一种 API 设计策略，用于处理涉及多个实体的批量请求（如批量删除、启用、禁用）。与传统的事务性“全有或全无”（All-or-Nothing）不同，该模式允许部分操作成功，部分操作失败，并通过结构化的响应体透明地反馈每一项的执行结果。

## 核心动机

在用户管理等运维场景中，管理员可能需要一次性处理数十个用户的状态变更。如果采用严格的事务回滚，任何一个用户的权限冲突或业务规则违规（如最后管理员保护）都会导致整个批次失败，极大降低运维效率。部分成功模式通过隔离每项操作的异常，确保了最大程度的执行成功率。

## 实现机制

1.  **逐项执行与异常捕获**：服务端遍历请求中的 ID 列表，对每一项独立执行业务逻辑。使用 `try-catch` 块捕获特定业务异常（如 `AppException`），将其转换为失败记录，而非中断整个流程。
2.  **资源级权限校验**：在循环内部，对每个目标实体执行细粒度的权限检查（如 `CanManageUser`）。SuperAdmin 可管理所有角色，而普通 Admin 仅能管理 Doctor/Receptionist。
3.  **结果汇总 DTO**：使用 `BatchOperationResultDto` 作为统一响应格式，包含：
    *   `successCount`: 成功执行的数量。
    *   `failureCount`: 失败的数量。
    *   `failedItems`: 包含失败项 ID 及具体失败原因（如“不能禁用当前登录用户”、“无权限禁用该用户”）的列表。

## 业务规则集成

在用户管理 API 中，该模式集成了以下关键安全约束：
*   **自身保护**：自动跳过或标记当前登录用户为失败，防止管理员误删自己。
*   **最后管理员保护**：在批量禁用时，若某项操作会导致系统失去最后一名活跃管理员，该项将被标记为失败，但不影响其他用户的禁用操作。
*   **Token 联动失效**：对于成功禁用的用户，立即触发 Token Family 撤销，确保安全性无延迟。

## 前端交互规范

前端在接收到 `BatchOperationResultDto` 后，应根据 `failureCount` 采取不同的通知策略：
*   **全部成功**：显示绿色 Toast 提示“操作成功”。
*   **部分成功**：显示黄色警告对话框，列出所有失败项及其原因，供管理员逐一排查。
*   **全部失败**：显示红色错误提示，并建议检查权限或业务规则。
