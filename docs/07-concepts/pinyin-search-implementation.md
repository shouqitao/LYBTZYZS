# 拼音码检索实现

## 定义

拼音码检索是一种基于中文姓名自动生成拼音首字母或全拼索引，从而实现毫秒级模糊搜索的技术方案。在凌隐宝堂系统中，它解决了医生接诊时快速查找患者档案的核心痛点，将查找耗时从分钟级（翻找纸质病历）降至秒级。

## 实现机制

### 1. 拼音码生成
*   **触发时机**：在创建或更新患者姓名时，系统自动调用拼音转换库生成 `PinYinCode` 字段。
*   **存储方式**：作为独立字段存储在数据库中，支持索引优化。
*   **多音字处理**：默认采用常用读音，支持手动修正以应对特殊姓氏或名字。

### 2. 双模式下的搜索策略

| 模式 | 搜索实现 | 性能特征 |
|------|----------|----------|
| **远程模式** | SQL `LIKE '%keyword%'` 查询 `PinYinCode` 字段 | 高效，利用数据库索引，支持分页和 OutputCache 缓存。 |
| **本地模式** | 内存中解密敏感字段后，对集合进行 LINQ 过滤 | **性能瓶颈风险**。由于 L1 敏感字段（如身份证、手机号）在 SQLite 中加密存储，无法直接使用 SQL 搜索。若搜索条件涉及敏感字段或需全量加载，需在客户端内存中解密所有记录后进行搜索。 |

## 性能优化与挑战

*   **内存搜索限制**：在本地模式下，如果患者数据积累至数万条，每次搜索都加载并解密所有敏感字段可能导致 UI 卡顿。
*   **优化建议**：
    *   为非敏感搜索（如仅按姓名/拼音）建立独立的轻量级索引表。
    *   限制本地模式下的单次加载数量，或采用异步后台加载策略。
    *   优先使用 `PinYinCode` 进行前缀匹配而非全量模糊搜索。

## 与其他模块的对比

虽然 [[herb-cache-strategy|药材内存缓存策略]] 也使用了拼音索引，但药材数据通常全量预加载且无敏感加密限制，搜索效率极高。患者模块因涉及隐私加密和更大的数据潜在体量，其本地搜索实现更为复杂，需特别注意内存占用和解密开销。
