## 二、关键设计决策

### 2.1 架构风格
- 采用**分层架构 + 模块化设计**
- 避免过度设计，遵循KISS和YAGNI原则
- 三层架构：Controller → Service → Repository

### 2.2 核心设计
- **MedicalCase作为聚合根**：管理整个诊疗流程
- **读写分离**：QueryService负责查询，BusinessService负责业务操作
- **软删除机制**：所有实体支持软删除
- **权限控制**：基于角色的权限控制（管理员/医生）

### 2.3 技术选型
- **后端**：.NET 8 + ASP.NET Core Web API + EF Core
- **前端**：WPF + Prism.DryIoc + Material Design
- **数据库**：SQL Server 2019+
- **缓存**：MemoryCache（不使用Redis）
- **认证**：JWT Token + RefreshToken

### 2.4 禁用技术
明确禁止使用：
- CQRS/MediatR（过度设计）
- 微服务架构（系统规模不需要）
- Redis（部署维护成本高）
- 消息队列（无异步处理需求）
- Docker/K8s（增加运维复杂度）

## 三、特色设计

### 3.1 四种开方方式
1. **表格直接编辑**：4列×N行表格，双击编辑
2. **快速输入弹窗**：纯键盘操作
3. **方剂导入**：支持多次导入，重复药材取最小剂量
4. **历史处方复制**：从患者历史处方复制

### 3.2 拼音码支持
- 自动生成拼音码（如：张三→ZS）
- 支持拼音码快速查询
- 提高输入效率

### 3.3 病历修改规则
- 当天可改，过期锁定
- 医生只能修改自己当天的病历
- 管理员可修改所有病历

### 3.4 Excel批量导入
- 2000条患者数据
- 300种药材
- 200个经验方剂

## 四、性能优化设计

### 4.1 缓存策略
- 三层缓存：客户端缓存 → API缓存 → 数据库缓存
- 不同数据类型不同缓存时间
- 病历/处方不缓存，保证数据实时性

### 4.2 查询优化
- 使用投影减少数据传输
- AsNoTracking提高只读查询性能
- 合理使用Include避免N+1问题
- 实现分页查询

### 4.3 索引设计
- 患者查询索引（拼音码、手机号）
- 病历查询索引（PatientId + CreatedAt）
- 处方查询索引（MedicalCaseId）
