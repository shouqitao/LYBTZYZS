## 📋 讨论背景

**现有实现**：
- 单列表布局（只有全部患者列表）
- 搜索功能（姓名/拼音码/手机号）
- 分页功能（每页50条）
- 双击或点击"选择"按钮进入看诊
- 新建患者快速对话框
- EventAggregator事件发布机制

**设计方案要求**：
- 双列表布局（待看诊队列 + 全部患者列表）
- 患者信息详情模块
- "当前选中患者"概念（两个列表都可选中）
- 三选一对话框（继续看诊/新建医案/关闭医案）
- 智能路由逻辑

### 补充讨论：判断逻辑位置和参数设计

**✅ 判断逻辑位置：患者选择界面（PatientSelectionViewModel）**

**流程设计**：

| 入口 | 判断逻辑 | 导航参数 |
|-----|---------|---------|
| **待看诊队列双击** | 无需判断（明确意图=继续看诊） | `PatientId` + `MedicalCaseId` + `Action="Continue"` |
| **全部患者列表双击/按钮** | 查询未完成医案 → 有则弹窗三选一，无则直接新建 | 继续：`Action="Continue"` <br> 新建：`Action="CreateNew"` <br> 关闭：不导航，刷新队列 |

**Action枚举值**：
- `Continue` - 继续看诊（加载已有医案）
- `CreateNew` - 新建医案（创建新医案）
- `CloseOnly` - 仅关闭医案（不导航，停留在患者选择界面）

**为什么在患者选择界面判断？**
- ✅ 避免无效导航（用户选择"关闭医案"时，不需要跳转到看诊界面）
- ✅ MedicalCaseFlowViewModel职责单一（只负责加载/创建医案，不负责业务判断）
- ✅ 利用待看诊队列=快捷通道（明确意图，无需再判断）

### 补充讨论：效率优化（避免重复查询）

**✅ 选择：方案A（本地缓存）**

**核心思路**：
- 待看诊列表加载时，建立内存字典：`Dictionary<Guid PatientId, Guid MedicalCaseId>`
- 全部患者列表选择时：
  - 先查字典 → 有 → 直接弹窗三选一
  - 查不到 → 调API确认 → 无未完成医案 → 新建

**缓存失效时机**：
- 用户点击"关闭医案" → 从字典删除该患者
- 用户点击"新建医案" → 从字典删除该患者
- 刷新待看诊列表 → 重建字典

**效率提升**：
- 待看诊列表有10个患者 → 这10个患者选择时，0次额外API调用
- 搜索其他患者 → 仅1次API调用

### Q5: 两个DataGrid的选中状态联动

**✅ 确认：允许同时选中**

**逻辑**：
- 两个列表各自维护选中状态（互不影响）
- **患者信息详情区** 显示"最后一次点击的患者"（CurrentPatient）
- 单击任一列表 → 更新CurrentPatient → 刷新患者信息详情区
- 双击任一列表 → 更新CurrentPatient + 开始诊断

**实现方式**：
- 各自绑定独立的SelectedItem属性
- 在SelectionChanged事件中更新CurrentPatient

## 📊 实施影响总结

### XAML调整

| 区域 | 调整内容 |
|-----|---------|
| **Grid布局** | 改为双列布局（左侧300px + 右侧自适应） |
| **左侧上方** | 新增患者信息详情模块（姓名/手机/年龄/地址/过敏史） |
| **左侧下方** | 新增待看诊队列DataGrid（姓名/手机/状态） |
| **右侧搜索区** | 增加"开始诊断"按钮，移除每行"选择"按钮 |
| **右侧DataGrid** | 保留现有列，移除操作列 |
| **分页控件** | 调整PageSize为20 |

### ViewModel调整

| 类别 | 调整内容 |
|-----|---------|
| **属性** | `SelectedPatient` → `CurrentPatient` |
| **新增属性** | `PendingQueue`（待看诊队列）<br>`PendingCaseCache`（PatientId→MedicalCaseId字典） |
| **新增命令** | `StartDiagnosisCommand`（开始诊断按钮）<br>`RefreshPendingQueueCommand`（刷新队列） |
| **调整常量** | `PageSize = 20`（从50调整） |
| **新增方法** | 查询未完成医案<br>三选一对话框<br>关闭旧医案<br>导航参数构建 |

### Server端API（新增）

| API | 说明 |
|-----|------|
| `GetPendingCasesAsync()` | 获取待看诊队列（Status=Active的医案） |
| `GetUnfinishedCaseByPatientIdAsync(Guid patientId)` | 查询患者是否有未完成医案 |
| `CloseAsync(Guid medicalCaseId)` | 关闭医案（级联删除Consultation和Prescription） |
