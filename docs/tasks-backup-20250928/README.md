# 任务管理说明

- **维护人**：Thinker（任务发布）、Coder（总结归档）
- **最后更新**：2025-09-25

## 目录结构
- `pending/`：待执行任务（命名：`YYYY-MM-DD-任务名称.md`）。
- `completed/`：已完成任务总结，命名与原任务一致，可使用 `-summary.md` 后缀。

## 编写要求
1. 任务模板需包含：背景、目标、工作拆解、验收标准、相关 PRD/报告链接。
2. 完成后在总结中标注：实现要点、测试结果、遗留风险、关联报告/PRD。
3. 若任务关闭后仍有后续事项，请在总结中添加“待续清单”，方便生成下一步任务。

## 索引与交叉链接
- 每周更新一次任务索引（见即将创建的自动化脚本），短期内可手动维护 `pending/` 与 `completed/` 列表。
- 新建任务时，请检查 `docs/reports/INDEX.md`、`docs/prd/` 是否已有相关背景资料，并在正文中引用。

## 维护节奏
- Thinker 发布任务前需确认最新架构/报告内容；
- Coder 完成任务后 24 小时内提交总结，并更新关联文档链接；
- 任务数量超过 30 条时，需进行归档或合并，并在 `docs/ARCHIVE.md` 记录。
