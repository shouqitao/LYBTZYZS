# 2025-09-24 Users 模块单元测试核心修复任务

## 任务背景
- `2025-09-24-users-模块单元测试契约同步-summary.md` 显示当前 `LYBT.Module.Users.Tests` 仍有 65 项失败，主要集中在仓储缓存实现、业务服务返回契约、批量操作约束与数据持久化流程。
- 最近一次测试执行（2025-09-24 15:15）确认失败原因：
  - `MemoryCache` 触发 “Cache entry must specify a value for Size” 异常，阻断仓储层多项测试。
  - 用户创建/批量操作相关测试仍与业务实现不符，导致成功/失败判定反向。
  - 仍缺少统一的测试基建，真实行为与生产差异较大。
- 本任务旨在以最小范围修复核心阻塞，推动 Users 模块单测接近 0 失败，为 Server 端“测试全覆盖、测试全通过”目标扫清主要障碍。

## 问题清单
1. **缓存实现不兼容 SizeLimit**
   - `UserRepository.GetPagedAsync/GetByIdAsync/GetByUsernameAsync/ExistsByUsernameAsync` 直接调用 `_cache.Set`，未设置 `Size`，在测试环境 `MemoryCacheOptions.SizeLimit = 100` 下触发异常。
   - `OptimizedBaseRepository` 已提供 `SetCacheSafely`，但子类未复用。

2. **用户创建流程缺少持久化与唯一性验证**
   - `CreateUserAsync` 创建实体后未调用 `_userRepository.SaveChangesAsync()`，导致测试无法查询到新用户。
   - 未验证手机号唯一性，`CreateUserAsync_Should_Fail_When_Phone_Already_Exists` 期望失败但实际成功。
   - `ServiceResult` 消息仍需统一（成功返回 Data、失败返回错误码/消息）。

3. **批量操作约束未落实**
   - 当前实现未检查 `_options.MaxBatchOperationSize`，导致超过上限时仍返回成功。
   - 对重复 ID、空集合、部分已禁用/启用的处理与测试期望不符，需要明确业务规则并同步实现与断言。

4. **测试基建缺口**
   - 仓储与业务测试各自重新创建 `MemoryCache`/`DbContext`，缺乏统一 Fixture，缓存策略、默认配置、`DefaultPasswordService` 等重复定义。
   - 缺少辅助断言/测试数据构建器，导致大量重复代码和易错点。

## 任务目标
- 消除 MemoryCache SizeLimit 异常，使仓储层测试恢复执行能力。
- 统一用户创建、批量操作的业务行为与测试断言，确保核心功能路径的 ServiceResult 契约一致。
- 建立基础的测试 Fixture/Builder，降低后续修改成本并提升测试稳定性。
- 将 `LYBT.Module.Users.Tests` 失败数由 65 降至 <20（理想为 0），并生成完整测试日志。

## 工作项
1. **缓存兼容性修复**
   - 重构 `UserRepository`，使用 `SetCacheSafely` 或统一的缓存辅助方法，确保所有缓存写入均设置 `Size`。
   - 审核并更新 `InvalidateCache/InvalidateListCache` 逻辑，如需引入缓存键命名规范需同步测试。
   - 更新仓储单测，保留 `SizeLimit` 配置以验证兼容性。

2. **用户创建/唯一性校验**
   - 在 `CreateUserAsync` 中调用 `_userRepository.SaveChangesAsync()`，并在失败时返回明确错误。
   - 补充手机号唯一性校验（可在仓储层新增 `ExistsByPhoneNumberAsync`，或通过查询实现）。
   - 调整相关测试断言，验证 `ServiceResult` 的 `IsSuccess/Data/ErrorMessage`。

3. **批量操作业务规则对齐**
   - 在 `BatchEnableAsync/BatchDisableAsync` 中加入数量上限、空集合、重复 ID 的校验逻辑，与 `UserOptions.MaxBatchOperationSize` 一致。
   - 重新定义批量操作返回值：成功时给出实际受影响数量，失败时返回明确错误消息。
   - 更新对应单测，覆盖超上限、部分重复、已有状态一致等场景。

4. **测试基建增强**
   - 新建 `UsersTestFixture`（集中提供 `AppDbContext`、真实 `MemoryCache`、AutoMapper Profile、默认配置）。
   - 引入 `UserBuilder`/`ServiceResultAssertions` 等辅助工具，减少重复构造与断言。
   - 调整现有测试以复用 Fixture，保证缓存/上下文配置一致。
