# 任务：执行项目综合评审

- **状态**: 待处理
- **发布日期**: 2025-09-25
- **负责人**: GEMINI
- **关联PRD**: [PRD-20250925-Project-Comprehensive-Review](../../prd/PRD-20250925-Project-Comprehensive-Review.md)

## 1. 任务目标

根据关联PRD的要求，完成对项目的架构、成本和性能的综合分析，并撰写分析报告。

## 2. 任务分解

### Phase 1: 架构分析

- [ ] **1.1. 模块与边界分析**:
    - [ ] 检视 `src` 目录结构，评估模块划分是否清晰、高内聚、低耦合。
    - [ ] 分析各项目（`.csproj`）之间的引用关系，绘制高阶模块依赖图。

- [ ] **1.2. 核心组件与设计模式分析**:
    - [ ] 抽样审查数据访问层、服务层、API层的实现，评估其设计模式是否恰当。
    - [ ] 检查跨领域问题（如日志、缓存、异常处理）的解决方案是否统一。

### Phase 2: 成本分析

- [ ] **2.1. 构建与部署流程评估**:
    - [ ] 审查 `build.bat`, `run-webapi.ps1` 等构建/运行脚本，评估其效率和可靠性。
    - [ ] 检查 `.github/workflows` 中的CI/CD流程，寻找潜在的优化点。

- [ ] **2.2. 开发迭代成本评估**:
    - [ ] 理论上模拟一个典型的小功能（如增加一个API端点和相关服务），评估所需修改的文件范围和复杂度。

### Phase 3: 性能分析

- [ ] **3.1. 关键路径识别与评估**:
    - [ ] 识别核心业务场景（如患者创建、开具处方）的代码路径。
    - [ ] 静态分析关键路径代码，寻找明显的性能隐患（如循环内DB查询、过多的对象分配等）。

- [ ] **3.2. 资源消耗初步评估**:
    - [ ] 分析项目启动代码，评估应用启动时加载的资源和配置。
    - [ ] 检查是否存在已知的、可能导致内存或CPU高消耗的库或模式。

### Phase 4: 报告撰写

- [ ] **4.1. 汇总分析结果**: 整理前三阶段的发现和数据。
- [ ] **4.2. 撰写报告**: 按照PRD验收标准，完成综合分析报告的撰写。
- [ ] **4.3. 归档报告**: 将最终报告存入 `docs/reports/` 目录。
