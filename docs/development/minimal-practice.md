# 最小实践指南（Issue → 清单 → PR → 交付）

目标：以最小成本完成任务，保持流程可追踪、可验证。

## 1) 提交 Issue（使用模板）
- 路径：GitHub → New issue → Feature Request（模块化功能清单）
- 填写：背景、目标/范围、约束、影响、AC、模块、风险、参考
- 结果：AI 生成“模块化功能清单 + 实施计划”，固定在 Issue 顶部并追踪

## 2) 实施与 PR（引用编号 + 编译验证）
- PR 标题示例：`feat(server): unify default port to 5001 [SRV-1]`
- 描述需包含：
  - 引用功能清单编号（如 `[SRV-1], [CLI-1]`）
  - 编译命令与结果摘要：`dotnet build LYBT.All.sln -c Release`
  - 按 AC 的验证步骤与结果
  - 风险与回滚
- CI：执行编译守门与编号校验

## 3) 合并与跟踪
- 合并后：自动尝试勾选 Issue 清单项；必要时自动留言提示
- 后续增强：当所有条目勾选且编译守门通过时自动关闭 Issue

## 4) 风格与约束（与 CLAUDE.md 一致）
- 完成导向，够用即好；避免超前设计
- 推荐与重构建议仅在“代码分析阶段”提出
- 方案需参考 Issue 中的既有思路/约束，并给出取舍依据
