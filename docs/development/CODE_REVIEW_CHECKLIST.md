# UltraThink代码审查清单

基于UltraThink重构经验制定的全面代码审查标准，涵盖所有发现的问题类型和最佳实践。

## 🚨 P0级别检查项（必须通过）

### 1. 字段更新完整性
- [ ] **AutoMapper映射**: 所有DTO映射是否使用AutoMapper？
- [ ] **禁止手动映射**: 是否存在 `model.Field = dto.Field` 模式？
- [ ] **禁止条件映射**: 是否存在 `if (!string.IsNullOrWhiteSpace(dto.Field))` 模式？
- [ ] **映射配置验证**: AutoMapper配置是否通过 `AssertConfigurationIsValid()`？

**重点关注**：MedicalCase模块曾经只更新2/15个字段的严重问题

### 2. 文件大小控制
- [ ] **Helper类限制**: 是否超过500行？（基于User:534行, Patient:521行, Prescription:649行的教训）
- [ ] **Service类限制**: 是否超过300行？
- [ ] **Controller类限制**: 是否超过200行？

**触发重构的阈值**：Helper类接近450行时应考虑重构

## ⚠️ P1级别检查项（强烈建议）

### 3. 架构设计
- [ ] **单一职责**: 类是否只负责一个职责？
- [ ] **依赖注入**: 是否正确使用构造函数注入？
- [ ] **接口抽象**: 是否定义了清晰的接口？
- [ ] **服务分离**: 大型类是否按功能分离为专业服务？

### 4. 异常处理
- [ ] **统一异常**: 是否使用 `ServiceResult<T>` 返回模式？
- [ ] **异常日志**: 是否记录了详细的异常信息？
- [ ] **业务异常**: 是否区分了业务异常和系统异常？
- [ ] **异常传播**: 是否正确处理了异常传播？

### 5. 数据访问安全
- [ ] **LINQ查询**: 是否使用LINQ而非原生SQL？
- [ ] **参数化查询**: 是否避免SQL注入风险？
- [ ] **批量操作**: 是否使用 `ExecuteUpdate` 替代内存加载？
- [ ] **事务处理**: 是否正确处理数据库事务？

## 📊 P2级别检查项（建议改进）

### 6. 性能优化
- [ ] **异步操作**: 数据库操作是否使用async/await？
- [ ] **缓存使用**: 是否合理使用缓存机制？
- [ ] **查询优化**: 是否避免N+1查询问题？
- [ ] **资源释放**: 是否正确释放资源？

### 7. 代码规范
- [ ] **命名约定**: 是否遵循C#命名规范？
- [ ] **代码格式**: 是否使用一致的代码格式？
- [ ] **注释完整**: 关键逻辑是否有详细注释？
- [ ] **TODO清理**: 是否清理了临时TODO标记？

### 8. 测试覆盖
- [ ] **单元测试**: 是否有对应的单元测试？
- [ ] **集成测试**: 复杂流程是否有集成测试？
- [ ] **边界测试**: 是否测试了边界条件？
- [ ] **映射测试**: DTO映射是否有验证测试？

- [ ] 清理调试代码和注释

### 2. 同级审查阶段

- [ ] 确认测试覆盖充分

### 3. 资深审查阶段
- [ ] 架构设计合理性
- [ ] 性能影响评估

## ❌ 常见问题参考

### 严重问题（阻止合并）
1. **字段遗漏**: 手动映射导致字段更新不完整
2. **SQL注入**: 使用字符串拼接SQL查询
3. **内存泄漏**: 未正确释放资源
4. **安全漏洞**: 敏感信息泄露

### 一般问题（要求修复）
1. **性能问题**: 同步调用阻塞线程
2. **代码重复**: 相似逻辑未抽取
3. **命名混乱**: 变量/方法命名不清晰
4. **测试缺失**: 缺少对应单元测试

### 建议改进（可选修复）
1. **代码优化**: 算法效率可以改进
2. **注释补充**: 复杂逻辑需要说明
3. **异常细化**: 异常信息可以更详细
4. **日志完善**: 关键操作可记录日志
