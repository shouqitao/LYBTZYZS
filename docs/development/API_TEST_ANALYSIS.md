## 问题分析

### 1. 用户模块PATCH方法返回404
**原因**：虽然我们修改了代码，但运行的WebAPI仍然是旧版本。用户模块的启用/禁用操作仍在使用旧的POST路由：
- 旧路由：`POST /users/enable/{id}`
- 新路由：`PATCH /users/{id}/enable`

### 2. 其他模块新增接口返回405
**原因**：405表示"方法不允许"，说明这些模块的新增操作仍然使用标准REST路由：
- 当前路由：`POST /patients` (标准REST)
- 期望路由：`POST /patients/add` (项目规范)

## 根本原因
WebAPI运行的是编译修改前的版本。虽然我们：
1. 修改了控制器代码
2. 成功编译了项目
3. 发布了Release版本

但实际运行的WebAPI进程没有更新到最新代码。

## 解决方案

### 立即解决步骤
1. 停止当前运行的WebAPI进程
2. 从最新编译的版本启动WebAPI
3. 重新运行测试验证修复

### 验证方法
可以通过以下方式验证是否运行最新版本：
1. 检查Swagger文档中的路由定义
2. 查看启动日志中的编译时间戳
3. 直接测试新路由是否可用
