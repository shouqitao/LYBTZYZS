## 📋 长期维护建议

### 1. 开发规范建立

#### 共享内容优先原则
```markdown
🔥 重要规则：新增以下类型的内容时，优先考虑放入 LYBT.Shared.Models 项目

✅ 应放入Shared的内容：
- 枚举类型（前后端都会使用的业务枚举）
- 扩展方法（通用的类型扩展功能）
- 常量定义（API路由、消息、格式等）
- DTO模型（API契约模型）
- 工具类（前后端都需要的通用功能）
- 验证规则（数据验证相关）

❌ 不应放入Shared的内容：
- 后端专用服务（数据库访问、缓存、日志等）
- 前端专用功能（UI绑定、视图模型等）
- 框架特定实现（EF实体、WPF控件等）
- 环境特定配置（连接字符串、文件路径等）
```

#### 命名规范
```csharp
// 命名空间规范
LYBT.Shared.Models.Extensions     // 扩展方法
LYBT.Shared.Models.Constants      // 常量定义
LYBT.Shared.Models.Enums         // 枚举类型
LYBT.Shared.Models.Common        // 通用模型
LYBT.Shared.Models.Auth          // 认证相关
LYBT.Shared.Models.{ModuleName}   // 业务模块特定

// 文件命名规范
{TypeName}Extensions.cs           // 扩展方法
{ModuleName}Constants.cs          // 模块常量
{BusinessName}Enums.cs           // 业务枚举
```

### 2. 定期代码审查规范

#### 审查要点清单
```markdown
📝 每次代码提交前检查：

□ 是否有新的重复代码？
  - 检查是否在多个项目中实现了相同功能
  - 确认是否应该提取到Shared项目

□ 是否正确使用了共享功能？
  - 优先使用Shared项目中的扩展方法
  - 使用统一的常量定义，避免硬编码

□ 命名空间是否正确？
  - using LYBT.Shared.Models.Extensions;
  - using LYBT.Shared.Models.Constants;
  - using LYBT.Shared.Models.Enums;

□ 注释是否完整？
  - 新增的共享内容必须有完整的中文注释
  - 包含参数说明、返回值说明、使用示例
```

#### 月度审查任务
```markdown
🗓️ 每月第一周执行：

1. 扫描重复代码
   - 使用工具检测项目间的代码重复
   - 识别可以统一的新功能

2. 评估Shared项目使用情况
   - 统计各扩展方法的使用频率
   - 识别未被使用的功能（考虑删除）

3. 更新文档
   - 更新本指南文档
   - 记录新增的共享功能
```
