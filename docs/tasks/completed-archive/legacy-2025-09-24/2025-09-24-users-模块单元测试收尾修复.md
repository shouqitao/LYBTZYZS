# 2025-09-24 Users 模块单元测试收尾修复任务

## 任务背景
- `2025-09-24-users-模块单元测试重对齐` 已修复首批阻塞问题，但 `LYBT.Module.Users.Tests` 仍有 72 项失败用例（总 238），阻碍服务器端测试体系恢复。
- 当前失败集中在 AutoMapper 配置、DTO/实体字段差异、服务返回约定、错误消息与软删除策略等方面，属于上一轮重构后遗留的断裂点。

## 当前问题审计
- **AutoMapper 映射缺口**：`UserMappingProfileTests.MappingConfiguration_Should_BeValid` 报未映射字段（`LastLoginTime/Remark/CreatedBy/UpdatedBy/RowVersion/IsDeleted`），且创建/更新映射未忽略 BaseEntity 默认值，导致 `Guid.Empty` 断言失效。
- **服务返回语义不一致**：`SimpleUserServiceTests.GetByIdAsync_Should_Return_Null_When_User_Not_Exists` 等测试仍假定失败返回 `null`；实际实现返回 `ServiceResult`，需统一约定。
- **业务异常消息变更**：如 `ChangePasswordAsync_Should_Return_Failure_When_Old_Password_Wrong` 期望 “原密码错误”，但密码策略先行报 “密码不符合复杂度要求”；多处断言需根据新校验顺序调整或重构逻辑。
- **软删除与缓存逻辑差异**：`DeleteUserAsync_Should_Delete_User_Successfully` 仍期望实体被物理删除（`null`），实际实现为软删除 + 禁用状态；缓存失效后返回禁用用户，与旧断言冲突。
- **批量操作结果不符**：`BatchDisableAsync_Should_Disable_Multiple_Users` 等用例期望受影响数量与旧实现一致；现回退逻辑（InMemory 下 SaveChanges 返回受影响实体数）与断言不匹配，需要校准。
- **DTO 基类命名滞后**：`StatusDto.CreateTime/UpdateTime` 仍使用旧命名，造成映射/断言与新实体（`CreatedAt/UpdatedAt`）频繁转换，建议统一。

## 任务目标
1. 补齐 Users 模块 AutoMapper 配置：忽略 BaseEntity 扩展字段或补充映射，确保 `AssertConfigurationIsValid` 通过，并根据领域规则更新 DTO 映射断言。
2. 统一服务层返回契约：梳理 `UserService` / `UserBusinessService` 对外行为，更新测试用例以使用 `ServiceResult` 断言（成功/失败/消息/数据），必要时调整实现以满足领域预期。
3. 调整业务异常与软删除测试：根据当前密码策略、软删除策略与批量操作实现，重写或拆分对应用例，使断言匹配真实业务流程；如需保留旧行为需在实现中恢复并记录理由。
4. 统一 DTO 时间字段命名与映射：在共享模型与 Users 模块测试中统一使用 `CreatedAt/UpdatedAt`，移除遗留的 `CreateTime/UpdateTime` 断言，保证 Mapper 与测试口径一致。
5. 建立测试基础设施：提取公共 Fixture（真实 `MemoryCache`、InMemory `AppDbContext` 工厂、默认用户构造器等），降低重复代码并确保缓存/事务行为可观测。
