## 当前问题审计
- **DI 注册测试直接失败**：`tests/UnitTests/Modules/Users.UnitTests/UsersModuleTests.cs:31-47` 构建 `ServiceProvider` 时未注册 `AppDbContext`、`IMemoryCache` 等依赖，解析 `IUserRepository` 时抛出 `Unable to resolve service for AppDbContext`。
- **服务层空参校验缺失**：`src/Server/Modules/LYBT.Module.Users/Services/UserService.cs:59` 直接访问 `dto.Id`，导致 `UpdateAsync` 在 `dto == null` 时抛出 `NullReferenceException`，与测试期望的 `ArgumentNullException` 不符。
- **AutoMapper 映射未更新**：`src/Server/Modules/LYBT.Module.Users/Mapping/UserMappingProfile.cs:20-37` 缺少 `CreatedAt/UpdatedAt -> CreateTime/UpdateTime` 映射，触发 `AutoMapperConfigurationException`（`UserDto.CreateTime` 未映射）。
- **缓存桩件误用导致 NullReference**：`tests/UnitTests/Modules/Users.UnitTests/Services/UserBusinessServiceTests.cs:46-49` 使用 `Mock<IMemoryCache>` 却未设置 `CreateEntry`，`GetByIdAsync` 写缓存时抛出 `NullReferenceException`，返回错误信息 “修改个人信息失败: Object reference…”。
- **密码复杂度策略变更未同步**：`UserBusinessServiceTests.cs:348` 仍使用 `NewPassword456!`，但新密码策略（`PasswordPolicyValidator`）禁止连续数字序列，导致测试期望的“原密码错误”被“密码不符合复杂度要求”取代。
- **批量启停用逻辑与 InMemory 提供程序不兼容**：`src/Server/Modules/LYBT.Module.Users/Repositories/UserRepository.cs:288-304` 使用 `ExecuteUpdateAsync`，在 EF InMemory 提供程序下返回 0 或抛出 `NotSupportedException`，使 `BatchDisableAsync`/`BatchEnableAsync` 用例（`UserBusinessServiceTests.cs:234-273`）失败。
- **批量操作 & 删除测试期望滞后**：多处用例仍假定旧的业务流程/错误文案（例如 `ChangeProfileAsync_Should_Return_Failure_When_User_Not_Found`、`DeleteUserAsync_Should_Delete_User_Successfully`），需根据新架构重新校准。

3. 更新 `UserMappingProfile` 及相关 DTO，完成 `CreatedAt/UpdatedAt` 与 `CreateTime/UpdateTime` 的映射与断言调整。
4. 修订 Users 模块单元测试：
