# 2025-09-24 Users 模块单元测试契约同步任务

## 任务背景
- 任务总结 `2025-09-24-users-模块单元测试收尾修复` 已将首批阻塞点梳理完毕，但 `LYBT.Module.Users.Tests` 仍存在 69 个失败用例，集中于映射契约、依赖注入注册与业务提示语更新。
- 当前阶段的大目标是“Server 端就当前功能实现测试全覆盖，测试全通过”。Users 模块的测试偏差已成为 Server 层测试体系收敛的主阻塞。

## 问题清单
1. **AutoMapper 映射断言失真**：`Map_UserCreateDto_To_User_Should_Success`、`Map_UserUpdateDto_To_User_Should_Success` 仍强制断言 `Guid.Empty` 与默认审计字段，和 `BaseEntity` 的 `Guid.NewGuid()` / 自动审计策略冲突。
2. **DI 注册缺口**：`UsersModuleTests.AddUsersModuleServices_Should_Register_All_Services` 无法解析 `IMapper`，模块注册缺少 AutoMapper 配置或测试未补齐模块依赖。
3. **密码策略提示语变更**：`ResetPasswordAsync_Should_Reset_Password_Successfully`、`ChangePasswordAsync` 系列因启用 `PasswordPolicyValidator` 的新错误消息而失败，测试断言仍引用旧提示或未覆盖复杂度校验分支。
4. **业务结果契约未统一**：`CreateUserAsync_Should_Fail_When_Phone_Already_Exists` 等用例仍使用旧的错误消息与返回形态（期望 `null` 或特定字符串），与 `ServiceResult<T>` 新语义不匹配。
5. **批量操作回退逻辑断言偏差**：`BatchDisableAsync_Should_Disable_Multiple_Users` 等测试在 InMemory Provider 上期望旧的影响行数，未对 `UpdateActiveStatusAsync` 的回退算法（仅统计状态发生变更的实体）进行适配。
6. **测试基建缺失**：当前测试通过 `new Mock<IMapper>`、`InMemoryDatabase` 异构配置运行，缺乏统一 Fixture，导致缓存、副作用、默认值等行为与生产实现不一致。

## 任务目标
- 同步 Users 模块映射、依赖、业务提示语与测试断言，使 `LYBT.Module.Users.Tests` 全量通过，并确保核心服务契约与生产逻辑完全一致。
- 完成后可用于解锁 Server 侧更大范围测试收敛（集成测试、架构测试）。

## 工作项
1. **映射契约校准**：
   - 审核 `UserMappingProfile`，确认哪些字段需要 `Ignore()`、哪些字段应显式映射；修正单元测试断言，改为校验业务语义（ID 非默认、审计字段为空或保持默认由业务层负责）。
   - 复核 `UserDto` 等共享契约命名（`CreateTime/UpdateTime` -> `CreatedAt/UpdatedAt`），必要时同步 DTO 与断言。
2. **模块依赖补齐**：
   - 在模块注册或测试 Fixture 中注入 AutoMapper Profile；`UsersModuleTests` 必须模拟真实启动流程，验证 DI 图完整可解析。
   - 清理测试中手工 `Mock<IMapper>` 的分支，统一改为真实映射或集中封装。
3. **密码策略测试更新**：
   - 梳理 `PasswordPolicyValidator` 的复杂度和禁用规则，调整服务实现与测试断言；针对成功路径与失败路径分别断言 `ServiceResult` 的 `ErrorMessage` 与 `ErrorCode`（若存在）。
   - 针对管理员重置、用户自助修改两条路径，各自覆盖成功、复杂度失败、历史密码冲突（若实现）等关键场景。
4. **业务结果一致化**：
   - 对 `ServiceResult<T>` 返回值进行快照，厘清成功/失败场景应包含的字段，并批量更新现有断言。
   - 若实现仍返回旧语义（例如直接返回 `null`），需补齐实现使其返回标准化的 `ServiceResult`，同时更新相关模块调用链。
5. **批量操作断言调和**：
   - 基于 `UpdateActiveStatusAsync` 的真实行为，重新定义批量启用/禁用用例的期望值（统计成功变更的条目，同时验证状态写回）。
   - 新增针对空集合、包含重复 ID、包含禁用/启用混合状态的测试，覆盖边界条件。
6. **测试基建重构**：
   - 新建 `UsersTestFixture`（提供 `AppDbContext`、真实 `MemoryCache`、AutoMapper 配置），集中管理测试数据构造与缓存清理。
   - 引入统一的测试数据构建器（例如 `UserBuilder`），减少冗余初始化逻辑。
   - 评估是否需要将 InMemory Provider 替换为 SQLite In-Memory，以获得更接近生产的行为；如需更换须在任务内一次性完成。
