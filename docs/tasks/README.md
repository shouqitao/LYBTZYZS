```
tasks/
├── 📋 active/              # 活跃任务（合并原 pending/ + plan/）
│   ├── 当前进行中的任务
│   ├── 待处理的任务
│   └── 计划中的任务
│
├── ✅ completed-archive/   # 完成归档（合并原 completed/ + closed/ + archived/）

```

## 📝 使用指南

### 活跃任务管理（active/）
- **新任务创建**：直接在 `active/` 目录创建
- **文件命名**：`YYYY-MM-DD-任务名称.md`
- **优先级标记**：可使用文件名前缀（P0-、P1-、P2-）

### 完成任务归档（completed-archive/）
- **任务完成**：将文件从 `active/` 移动到 `completed-archive/`
- **命名约定**：保持原名称，可添加 `-summary.md` 后缀
- **总结要求**：包含实现要点、测试结果、遗留风险

## 📋 任务模板要求

### 新建任务必须包含
1. **背景说明**：任务来源和必要性
2. **目标描述**：明确的完成目标
3. **工作拆解**：具体的实施步骤
4. **验收标准**：可量化的完成标准
5. **相关链接**：关联的Issues、PRD、报告

### 完成总结必须包含
1. **实现要点**：关键技术实现和决策
2. **测试结果**：验证和测试情况
3. **遗留风险**：未完成部分和潜在问题
4. **关联产出**：生成的文档、代码位置
5. **待续清单**：后续需要处理的事项

## 🔗 系统集成

### 与GitHub Issues联动
- **需求讨论** → GitHub Issues（权威讨论区）
- **实施计划** → `tasks/active/`（执行层）
- **完成总结** → `tasks/completed-archive/`（经验沉淀）

### 与项目文档联动
- **架构决策** → `docs/architecture/decisions/`
- **开发标准** → `docs/development/standards.md`
- **模块文档** → `docs/architecture/modules/`

## 🛠 维护规则

1. **定期检查**：每周检查 `active/` 中长期未更新的任务
2. **及时归档**：任务完成后24小时内归档
3. **交叉引用**：检查相关背景资料并建立引用链接
4. **数量控制**：活跃任务超过30个时进行合并或拆分
