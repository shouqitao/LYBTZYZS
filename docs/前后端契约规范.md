# 前后端契约规范

## 1. 概述

本文档定义了凌隐宝堂中医诊所诊疗系统前后端之间的接口契约，确保前后端开发的一致性和兼容性。

## 2. 通用约定

### 2.1 API 版本管理
- 所有 API 使用版本控制：`/api/v{version}/[controller]`
- 当前版本：v1
- 版本升级策略：保持向后兼容，新版本不影响旧版本

### 2.2 数据格式
- 请求和响应均使用 JSON 格式
- 日期时间格式：ISO 8601 (例：2024-01-29T15:30:00)
- 编码：UTF-8

### 2.3 HTTP 方法语义
- `GET`: 查询资源
- `POST`: 创建资源
- `PUT`: 完整更新资源
- `PATCH`: 部分更新资源
- `DELETE`: 删除资源

## 3. 认证与授权

### 3.1 认证方式
使用 JWT Bearer Token 认证

#### 登录请求
```http

Content-Type: application/json

{
    "username": "sysadmin",
    "password": "Admin@123456",
    "rememberMe": false
}
```

#### 登录响应
```json
{
    "success": true,
    "data": {
        "token": "eyJhbGci...",
        "expiresIn": 28800,
        "user": {
            "id": "64d9b4c5-26ab-4648-90cb-9234f75924f2",
            "username": "sysadmin",
            "realName": "系统管理员",

        }
    }
}
```

### 3.2 请求头
所有需要认证的 API 请求必须包含：
```http

```


#### POST 请求（创建资源）

```json

    "name": "张三",
    "createTime": "2024-01-29T15:30:00",

```

#### PUT/PATCH/DELETE 请求
```json
{
    "message": "操作成功"
}
```

### 4.2 错误响应 (ProblemDetails)
```json
{
    "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
    "title": "参数验证失败",
    "status": 400,
    "detail": "患者姓名不能为空",
    "instance": "/api/v1/patients"
}
```

### 4.3 状态码使用
- `200 OK`: 成功
- `400 Bad Request`: 客户端错误（参数验证失败等）
- `401 Unauthorized`: 未认证
- `403 Forbidden`: 无权限
- `404 Not Found`: 资源不存在
- `500 Internal Server Error`: 服务器错误

## 5. 数据传输对象 (DTO) 规范

### 5.1 基础 DTO
用于列表显示的简化对象：
```csharp
public class PatientDto
{
    public Guid Id { get; set; }
    public string Name { get; set; }
    public string Gender { get; set; }
    public int Age { get; set; }
    public string PhoneNumber { get; set; }
    public bool IsActive { get; set; }
}
```

### 5.2 详情 DTO
用于显示完整信息：
```csharp
public class PatientDetailDto : PatientDto
{
    public string IdNumber { get; set; }
    public DateTime? BirthDate { get; set; }
    public string Address { get; set; }
    public string EmergencyContact { get; set; }
    public string EmergencyPhone { get; set; }
    public string Allergies { get; set; }
    public string MedicalHistory { get; set; }
    public DateTime CreateTime { get; set; }
    public DateTime? UpdateTime { get; set; }

```

### 5.3 创建 DTO
用于创建新资源：
```csharp
public class PatientCreateDto
{
    [Required(ErrorMessage = "姓名不能为空")]
    public string Name { get; set; }
    
    [Required(ErrorMessage = "性别不能为空")]
    public string Gender { get; set; }
    
    [Required(ErrorMessage = "手机号不能为空")]
    [Phone(ErrorMessage = "手机号格式不正确")]
    public string PhoneNumber { get; set; }
    
    public string? IdNumber { get; set; }
    public DateTime? BirthDate { get; set; }
    public string? Address { get; set; }
}
```

### 5.4 更新 DTO
用于更新资源：
```csharp

{
```

## 7. 特殊业务规则

### 7.1 软删除策略
- 所有业务数据不进行物理删除
- 使用 `IsActive` 或 `IsDeleted` 标记
- 删除操作实际执行状态更新

### 7.2 权限控制
- 管理员查询包含所有数据（含禁用）
- 普通用户只能查询启用的数据
- 通过 `UserRole` 参数控制查询范围

### 7.3 数据验证
- 前端进行基础验证（必填、格式等）
- 后端进行完整的业务验证
- 验证失败返回 400 状态码和详细错误信息

### 7.4 并发控制
- 使用乐观并发控制
- 更新时检查时间戳或版本号
- 冲突时返回 409 Conflict

## 8. 前端服务层规范

### 8.1 API 服务接口 (Refit)
```csharp
public interface IPatientApiService
{
    [Get("/api/v1/patients")]
    Task<ApiResponse<List<PatientDto>>> GetPatientsAsync();

    [Post("/api/v1/patients")]
    Task<ApiResponse<PatientDto>> CreatePatientAsync([Body] PatientCreateDto dto);

```

### 8.2 服务包装层
```csharp
public interface IPatientService
{
    Task<ServiceResult<List<PatientInfo>>> GetPatientsAsync();
    Task<ServiceResult<PatientInfo>> CreateAsync(PatientCreateDto dto);
}
```

### 8.3 ServiceResult 定义
```csharp
public class ServiceResult<T>
{
    public bool IsSuccess { get; set; }
    public T? Data { get; set; }
    public string? ErrorMessage { get; set; }
    public Exception? Exception { get; set; }
    
    public static ServiceResult<T> Success(T data) => new() 
    { 
        IsSuccess = true, 
        Data = data 
    };
    
    public static ServiceResult<T> Failure(string error, Exception? ex = null) => new() 
    { 
        IsSuccess = false, 
        ErrorMessage = error, 
        Exception = ex 
    };
}
```
