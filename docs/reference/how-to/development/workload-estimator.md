# LYBTZYZS 工作量智能估算器

## 核心能力

### 1. 基于历史数据估算
- **历史统计**：分析过去20个相似任务的实际耗时
- **类型分组**：按任务类型（Repository/Service/Controller）统计
- **偏差修正**：自动应用历史偏差率（如Controller +13%）
- **置信区间**：给出估算范围（如2-3小时，置信度80%）

### 2. 复杂度分析
- **代码规模**：预估代码行数（基于相似任务）
- **依赖复杂度**：分析依赖的模块数量
- **业务复杂度**：评估业务规则数量
- **技术复杂度**：识别新技术使用（首次使用+30%）

### 3. 估算公式优化
- **基础工时**：从历史数据计算基准
- **复杂度系数**：简单0.8、中等1.0、复杂1.5
- **技术系数**：熟悉1.0、新技术1.3
- **Buffer系数**：预留10-20%缓冲

### 4. 团队速率追踪
- **Sprint速率**：计算每Sprint完成的Story Points
- **个人速率**：统计个人平均完成速度
- **速率趋势**：识别速率提升/下降趋势

## 使用场景

### 场景：估算新任务工作量

**输入**：Issue #1234（新增ConsultationRepository.GetByPatientIdAsync）

**分析**：
```
1. 任务类型: Repository层（历史平均: 2小时）
2. 复杂度: 中等（需要EF Core Include）
3. 依赖: 2个（Patient, MedicalCase）
4. 技术: EF Core Include（首次使用 +30%）
5. 历史偏差: Repository层平均-8%
```

**估算公式**：
```
基础工时 = 2小时
复杂度系数 = 1.0（中等）
技术系数 = 1.3（首次Include）
偏差修正 = 0.92（-8%）

预估 = 2 × 1.0 × 1.3 × 0.92 = 2.4小时
置信区间 = 2-3小时（80%置信度）
```

**输出**：

## 估算公式

```python
预估工时 = 基础工时 × 复杂度系数 × 技术系数 × 偏差修正系数

其中:
- 基础工时 = 历史平均工时（按任务类型）
- 复杂度系数 = {简单: 0.8, 中等: 1.0, 复杂: 1.5}
- 技术系数 = {熟悉: 1.0, 新技术: 1.3}
- 偏差修正 = 1 + 历史平均偏差率
```
