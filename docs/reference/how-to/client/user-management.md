> **文档类型**: How-to Guide
> **目标读者**: 管理员、开发人员
> **前置阅读**: [Users模块架构设计](../../explanation/architecture/server/modules/users.md)

## 1. 概述

本指南介绍用户管理模块的完整操作功能，包括基础CRUD操作、状态管理、密码管理、批量删除等。

**核心功能**：
- ✅ 新建用户（双轨认证支持、BCrypt密码哈希）
- ✅ 编辑用户（更新信息、角色管理）
- ✅ 查看用户详情（只读模式）
- ✅ 删除用户（软删除）
- ✅ **状态管理**（Toggle启用/禁用，Issue #1162）
- ✅ **密码管理**（Admin重置、用户修改密码）
- ✅ **个人资料管理**（Issue #1888）
- ✅ **批量删除**（≤100用户，Issue #1169）

**技术亮点**：
- 双轨认证（Username/Email登录）
- BCrypt密码哈希（安全存储）
- 超级管理员特殊处理（Guid.Empty）
- 软删除机制（IsDeleted标志）
- Prism MVVM模式（Region Navigation + 事件驱动）

## 2. 新建用户

### 2.1 操作步骤

1. **进入新建页面**
   - 在用户列表页面，点击"新建"按钮
   - 系统导航到用户新建页面（`UserCreateView`）

2. **填写基本信息**

   **必填字段**：
   - **用户名**（3-50字符，唯一）
     - 用于登录系统
     - 示例：zhangsan、lisi
     - **业务规则**：用户名必须唯一（BR-001）

   - **真实姓名**（1-50字符）
     - 用户的真实姓名
     - 示例：张三、李四

   - **密码**（6-100字符）
     - 使用BCrypt哈希存储
     - 建议包含字母、数字、特殊字符

   - **角色**（下拉选择）
     - Admin（管理员）
     - Doctor（医生）
     - Nurse（护士）
     - Pharmacist（药师）

   **可选字段**：
   - **邮箱**（有效邮箱格式）
     - 用于双轨认证（可使用Email登录）
     - 示例：zhangsan@example.com
   - **手机号**（11位数字）
     - 示例：13800138000
   - **状态**（启用/禁用）
     - 默认：启用

3. **提交创建**
   - 点击"保存"按钮
   - 系统验证必填字段和唯一性约束
   - 密码使用BCrypt哈希后存储
   - 创建成功后，自动返回用户列表

### 2.2 字段说明

#### 双轨认证（BR-002）

**功能说明**：
- 用户可以使用**用户名**或**邮箱**登录
- 两种方式均支持，提升用户体验

**使用示例**：
```
登录方式1：用户名 + 密码
- 用户名：zhangsan
- 密码：Password123

登录方式2：邮箱 + 密码
- 邮箱：zhangsan@example.com
- 密码：Password123
```

**代码位置**：
- 后端：`UserService.cs`（CreateAsync方法）
- 验证器：`UserInputDtoValidator.cs`

#### BCrypt密码哈希（BR-003）

**安全机制**：
- 使用BCrypt.Net-Next库进行密码哈希
- 哈希结果存储到`PasswordHash`字段
- 原始密码不存储，确保安全

**哈希示例**：
```
原始密码：Password123
哈希结果：$2a$11$abc123...（60字符）
```

**代码位置**：
- 后端：`UserService.cs:123-130`（CreateAsync）
- 后端：`UserService.cs:215-220`（ChangePasswordAsync）

### 2.3 验证规则

| 字段 | 验证规则 | 错误提示 |
|-----|---------|---------|
| 用户名 | 必填，3-50字符，唯一性（BR-001） | "用户名不能为空" / "用户名已存在" |
| 真实姓名 | 必填，1-50字符 | "真实姓名不能为空" |
| 密码 | 必填，6-100字符 | "密码不能为空" / "密码长度6-100字符" |
| 角色 | 必填，有效枚举值 | "角色不能为空" |
| 邮箱 | 可选，有效邮箱格式 | "邮箱格式不正确" |
| 手机号 | 可选，11位数字 | "手机号格式不正确（11位数字）" |

## 3. 编辑用户

### 3.1 操作步骤

1. **进入编辑页面**
   - 在用户列表页面，点击某个用户的"编辑"按钮
   - 系统导航到用户编辑页面
   - 页面自动加载用户数据

2. **修改信息**

   **可编辑字段**：
   - 用户名（修改后需确保唯一性）
   - 真实姓名
   - 邮箱
   - 手机号
   - 角色
   - 状态（启用/禁用）

   **只读字段**：
   - 密码（通过"修改密码"功能单独修改）
   - 创建时间
   - 更新时间

3. **提交更新**
   - 点击"保存"按钮
   - 系统验证必填字段和唯一性约束（排除自身ID）
   - 更新成功后，返回用户列表

### 3.2 用户名唯一性检查

**更新逻辑**：
- Server端检测用户名是否与其他用户重复
- 排除自身ID（允许保持原用户名不变）

**代码位置**：
- 后端：`UserService.cs:165-180`（UpdateAsync）

## 5. 删除用户（软删除）

### 5.1 操作步骤

1. **触发删除操作**
   - 在用户列表页面，点击某个用户的"删除"按钮
   - 或在用户详情页面，点击"删除"按钮

2. **确认删除**
   - 系统弹出确认对话框："确定要删除该用户吗？"
   - 点击"确定"继续删除
   - 点击"取消"放弃删除

3. **删除完成**
   - 删除成功后，系统显示成功提示
   - 用户列表自动刷新，被删除的用户不再显示

### 5.2 软删除机制（BR-005）

**实现方式**：
- 设置`IsDeleted = true`，而不是物理删除
- 查询时自动过滤已删除用户（`!IsDeleted`）
- 保留历史数据，支持数据恢复

**优势**：
- 数据可追溯，支持审计
- 避免外键约束问题
- 支持数据恢复（需通过数据库操作）

**代码位置**：
- 后端：`UserRepository.cs:45-52`（GetPagedAsync过滤）
- 后端：`UserService.cs:235-250`（DeleteAsync设置标志）

## 6. 状态管理（Issue #1162核心功能）

### 6.1 功能概述

状态管理功能允许管理员快速启用或禁用用户，无需进入编辑页面。

**状态选项**：
- **启用**（Enabled）：用户可正常登录和使用系统
- **禁用**（Disabled）：用户无法登录，但数据保留

### 6.2 操作步骤

1. **Toggle状态**
   - 在用户列表页面，点击用户的"启用/禁用"按钮
   - 或在用户详情页面，点击"Toggle状态"按钮

2. **确认操作**
   - 系统弹出确认对话框
   - 启用用户："确定要启用该用户吗？"
   - 禁用用户："确定要禁用该用户吗？"

3. **状态变更**
   - 点击"确定"执行变更
   - 系统调用API `PUT /api/v1/users/{id}/toggle-status`
   - 状态变更成功后，列表自动刷新

### 6.3 应用场景

**临时禁用**：
- 用户休假期间临时禁用
- 用户离职前临时禁用
- 安全问题临时禁用账户

**重新启用**：
- 用户休假结束重新启用
- 安全问题解决后重新启用

**代码位置**：
- 后端：`UserService.cs:255-270`（ToggleStatusAsync）
- API：`UsersController.cs:180-200`（ToggleStatus端点）

## 7. 密码管理

### 7.1 管理员重置密码（Admin功能）

**功能概述**：
- 管理员可以为任何用户重置密码
- 支持自动生成密码或手动指定密码

**操作步骤**：

1. **进入密码重置页面**
   - 在用户列表或详情页面，点击"重置密码"按钮
   - 系统弹出密码重置对话框

2. **选择重置方式**

   **方式1：自动生成密码**
   - 选择"自动生成"选项
   - 系统生成随机密码（8位，包含字母+数字）
   - 示例：`Abc12345`

   **方式2：手动指定密码**
   - 选择"手动指定"选项
   - 输入新密码（6-100字符）
   - 确认新密码

3. **提交重置**
   - 点击"确定"按钮
   - 系统调用API `POST /api/v1/users/{id}/reset-password`
   - 密码使用BCrypt哈希后存储
   - 显示新密码（自动生成模式）或成功提示

4. **通知用户**
   - 管理员需手动通知用户新密码
   - 建议用户首次登录后修改密码

**代码位置**：
- 后端：`UserService.cs:275-295`（ResetPasswordAsync）
- API：`UsersController.cs:205-230`（ResetPassword端点）

### 7.2 用户修改密码（User功能）

**功能概述**：
- 用户可以自行修改密码
- 需要验证旧密码

**操作步骤**：

1. **进入修改密码页面**
   - 在用户个人资料页面，点击"修改密码"按钮
   - 系统弹出修改密码对话框

2. **填写密码信息**
   - **旧密码**（必填）：当前密码
   - **新密码**（必填）：新密码（6-100字符）
   - **确认新密码**（必填）：再次输入新密码

3. **提交修改**
   - 点击"确定"按钮
   - 系统验证旧密码是否正确
   - 验证新密码与确认密码是否一致
   - 密码使用BCrypt哈希后存储
   - 修改成功后，提示用户重新登录

**验证规则**：
- 旧密码必须正确（BR-006）
- 新密码长度6-100字符
- 新密码与确认密码必须一致
- 新密码不能与旧密码相同（建议）

**代码位置**：
- 后端：`UserService.cs:300-325`（ChangePasswordAsync）
- API：`UsersController.cs:235-260`（ChangePassword端点）

## 8. 个人资料管理（Issue #1888）

### 8.1 功能概述

个人资料管理功能允许用户更新自己的基本信息（不包括角色和状态）。

**可修改字段**：
- 真实姓名
- 邮箱
- 手机号

**不可修改字段**：
- 用户名
- 角色
- 状态
- 密码（通过"修改密码"功能单独修改）

### 8.2 操作步骤

1. **进入个人资料页面**
   - 点击右上角用户头像或用户名
   - 选择"个人资料"菜单项
   - 系统导航到个人资料页面

2. **修改信息**
   - 修改真实姓名、邮箱、手机号
   - 字段验证规则与新建用户相同

3. **提交更新**
   - 点击"保存"按钮
   - 系统调用API `PUT /api/v1/users/{id}/profile`
   - 更新成功后，显示成功提示

### 8.3 业务规则

**权限控制**：
- 用户只能修改自己的资料（BR-007）
- 管理员可以通过"编辑用户"修改所有信息

**字段限制**：
- 用户名不可修改（确保登录稳定性）
- 角色不可自己修改（防止权限提升）
- 状态不可自己修改（防止自己禁用自己）

**代码位置**：
- 后端：`UserService.cs:330-355`（ChangeProfileAsync）
- API：`UsersController.cs:265-290`（ChangeProfile端点）

## 9. 批量删除（Issue #1169核心功能）

### 9.1 功能概述

批量删除功能允许管理员一次性删除多个用户（最多100个）。

**性能要求**：
- 单次最多删除100个用户
- 使用事务确保原子性（全部成功或全部失败）

### 9.2 操作步骤

1. **选择用户**
   - 在用户列表页面，勾选需要删除的用户
   - 最多选择100个用户

2. **触发批量删除**
   - 点击"批量删除"按钮
   - 系统显示确认对话框："确定要删除选中的 X 个用户吗？"

3. **确认删除**
   - 点击"确定"继续删除
   - 系统调用API `POST /api/v1/users/batch-delete`
   - 传输用户ID数组

4. **查看结果**
   - 删除成功后，显示成功提示："成功删除 X 个用户"
   - 列表自动刷新

### 9.3 业务规则

**数量限制**：
- 单次最多删除100个用户
- 超过100个时，系统提示分批删除

**事务处理**：
- 使用数据库事务确保原子性
- 如果某个用户删除失败，所有操作回滚
- 避免部分删除导致数据不一致

**软删除**：
- 批量删除也使用软删除机制
- 设置`IsDeleted = true`
- 保留历史数据

**代码位置**：
- 后端：`UserService.cs:360-385`（BatchDeleteAsync）
- API：`UsersController.cs:295-320`（BatchDelete端点）

### 9.4 使用场景

**批量清理**：
- 清理测试账户
- 清理过期账户
- 批量禁用离职员工

**注意事项**：
- ⚠️ 批量删除操作不可逆（软删除可恢复，但需数据库操作）
- ⚠️ 建议先使用"批量禁用"而非"批量删除"
- ⚠️ 确认选择的用户正确后再执行删除

## 10. 常见问题

### Q1: 用户名已存在错误？

**可能原因**：
1. 用户名与已有用户重复
2. 用户名与已删除用户重复（软删除导致）

**解决方法**：
1. 更换用户名
2. 如果是与已删除用户重复，联系管理员处理

### Q2: 密码重置后无法登录？

**可能原因**：
1. 新密码未正确记录
2. 密码中包含特殊字符导致输入错误

**解决方法**：
1. 确认新密码正确
2. 使用自动生成密码功能，避免复杂密码
3. 联系管理员重新重置密码

### Q3: 修改密码时提示旧密码错误？

**可能原因**：
1. 旧密码输入错误
2. 密码已被管理员重置

**解决方法**：
1. 确认旧密码正确
2. 如果忘记旧密码，联系管理员重置

### Q4: 批量删除失败？

**可能原因**：
1. 选择的用户数量超过100个
2. 某些用户有关联数据（外键约束）
3. 网络问题导致请求失败

**解决方法**：
1. 减少选择的用户数量（≤100个）
2. 先删除关联数据（如：该用户创建的患者、医案等）
3. 重新尝试删除

### Q5: 邮箱登录失败？

**可能原因**：
1. 邮箱未填写或格式不正确
2. 邮箱与用户名不匹配

**解决方法**：
1. 确认邮箱已在用户资料中填写
2. 使用用户名登录，然后更新邮箱
3. 联系管理员检查邮箱设置
