# 凌隐宝堂中医诊所诊疗系统开发规范

## 1. 项目架构规范

### 1.1 整体架构
- **后端**: ASP.NET Core Web API (.NET 8)
- **前端**: WPF 桌面应用 (.NET 8)
- **数据库**: SQL Server
- **通信**: RESTful API + JWT 认证

### 1.2 项目结构

```

├── src/
│   ├── Backend/
│   │   ├── Core/                    # 核心层

│   │   │   └── LYBT.Models/         # 领域模型
│   │   ├── Modules/                 # 业务模块
```

### 2.4 服务层规范

#### 服务接口定义
```csharp
public interface IPatientService
{
    // 创建操作 - 返回创建的对象或 null
    Task<PatientDto?> AddAsync(PatientCreateDto dto, Guid operatorId, string operatorName);
    
    // 更新操作 - 返回 bool
    Task<bool> UpdateAsync(PatientUpdateDto dto, Guid operatorId, string operatorName);
    
    // 删除操作 - 返回 bool（软删除）
    Task<bool> DeleteAsync(Guid id, Guid operatorId, string operatorName);
    
    // 查询操作
    Task<PatientDto?> GetByIdAsync(Guid id, UserRole currentUserRole);
    Task<List<PatientDto>> GetListAsync(UserRole currentUserRole);
    Task<PaginatedResult<PatientDto>> GetPagedAsync(QueryDto query, UserRole currentUserRole);
}
```

#### 服务实现原则
1. 业务逻辑放在服务层，不在控制器
2. 参数验证在服务层进行
3. 权限检查根据 currentUserRole 参数
4. 记录操作日志
5. 使用事务保证数据一致性

### 2.5 数据访问规范

#### 仓储接口
```csharp
public interface IPatientRepository
{
    Task<PatientModel?> GetByIdAsync(Guid id, bool includeDeleted = false);
    Task<List<PatientModel>> GetListAsync(bool includeDeleted = false);
    Task<bool> AddAsync(PatientModel model);
    Task<bool> UpdateAsync(PatientModel model);
    Task<bool> ExistsAsync(Guid id);
}
```

#### Entity Framework 使用规范
1. 使用 `AsNoTracking()` 进行只读查询
2. 使用 `Include()` 显式加载关联数据
3. 避免 N+1 查询问题
4. 使用投影减少数据传输

```csharp
// 好的做法
var patients = await _context.Patients
    .AsNoTracking()
    .Where(p => p.IsActive)
    .Select(p => new PatientDto {
        Id = p.Id,
        Name = p.Name,
        // ... 只选择需要的字段
    })
    .ToListAsync();
```

#### 服务包装层
```csharp
public class PatientService : IPatientService
{
    private readonly IPatientApiService _apiService;

    public async Task<ServiceResult<PatientInfo>> CreateAsync(PatientCreateDto dto)
    {
        var response = await _apiService.CreatePatientAsync(dto);
        if (response.IsSuccessStatusCode && response.Content != null)
        {
            var patientInfo = ConvertToPatientInfo(response.Content);
            return ServiceResult<PatientInfo>.Success(patientInfo);
        }
        return ServiceResult<PatientInfo>.Failure(response.Error?.Message ?? "创建失败");
    }
}
```

## 5. 数据库规范

### 5.1 表命名
- 使用复数形式：`Patients`, `Doctors`, `Herbs`
- 关联表：`主表_从表`，如 `Patient_Allergies`

### 5.2 字段命名
- 主键：`Id` (GUID)
- 外键：`关联表名Id`，如 `PatientId`, `DoctorId`
- 时间戳：`CreateTime`, `UpdateTime`
- 状态：`Status`, `IsActive`, `IsDeleted`

### 5.3 迁移规范
1. 所有迁移必须在 `LYBT.Infrastructure` 项目中创建
2. 迁移命名：`Add功能描述`，如 `AddPatientAllergies`
3. 迁移前先备份数据库

```bash
# 添加迁移
dotnet ef migrations add AddPatientAllergies --project src/Backend/Core/LYBT.Infrastructure --startup-project src/Backend/Services/LYBT.WebAPI

# 更新数据库
dotnet ef database update --project src/Backend/Core/LYBT.Infrastructure --startup-project src/Backend/Services/LYBT.WebAPI
```

## 6. 异常处理规范

### 6.1 后端异常处理

#### 全局异常处理器
```csharp
public class GlobalExceptionHandler : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(
        HttpContext context,
        Exception exception,
        CancellationToken cancellationToken)
    {
        var problemDetails = new ProblemDetails
        {
            Status = StatusCodes.Status500InternalServerError,
            Title = "服务器内部错误",
            Detail = exception.Message
        };

        context.Response.StatusCode = problemDetails.Status.Value;
        await context.Response.WriteAsJsonAsync(problemDetails, cancellationToken);
        
        return true;
    }
}
```

#### 业务异常

## 10. 安全规范

### 10.1 认证和授权
1. 使用 JWT Bearer Token 认证
2. Token 过期时间：8小时（Remember Me: 30天）
3. 所有 API 都需要 `[Authorize]` 特性（除了登录接口）
4. 基于角色的访问控制 (RBAC)

### 10.2 数据安全
1. 敏感数据加密存储
2. 使用参数化查询防止 SQL 注入
3. 输入验证和清理
4. 不在日志中记录敏感信息

### 10.3 通信安全
1. 使用 HTTPS
2. API 密钥和密码不硬编码
3. 使用环境变量或配置文件管理敏感配置

## 11. 性能规范

### 11.1 数据库查询优化
1. 使用索引优化查询
2. 避免 N+1 查询
3. 使用分页限制数据量
4. 适当使用缓存

### 11.2 API 性能
1. 使用异步操作
2. 实现适当的缓存策略
3. 限制并发请求
4. 响应数据压缩

### 11.3 前端性能
1. 虚拟化长列表
2. 延迟加载
3. 避免频繁的 UI 更新
4. 合理使用数据绑定
