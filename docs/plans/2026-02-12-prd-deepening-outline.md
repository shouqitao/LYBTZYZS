# PRD 深化讨论提纲

## 概述

基于对 14 个 PRD 文档 (120 FR) 的全量深度评估，本提纲将讨论组织为 **3 个系统级主题 + 5 个模块级主题 + 2 个补强主题 = 10 轮讨论**。

讨论顺序: **系统级 (全局影响) -> 薄弱模块 (补缺) -> 已完善模块 (补强)**

每轮讨论的产出: 直接更新对应的 PRD 文档，新增或修订具体内容。

---

## 现状快照

| 指标 | 当前值 |
|------|--------|
| PRD 模块数 | 14 |
| FR 总数 | 120 |
| 错误场景 | 150+ |
| 验收标准 | 240+ 条 |

| 文档质量 | 9 个完善 + 5 个良好 |

## 第一部分: 系统级主题 (3 轮)

> 影响全局的跨模块议题，需先统一共识再深入各模块。

### Round 1: 非功能性需求 (NFR)

**现状**: 完全缺失。无独立 NFR 文档。

**讨论要点**:

1. **性能指标**
   - API 响应时间目标 (P95/P99)
     - 列表查询 (分页) 的目标响应时间?
     - 复杂查询 (医案跨表搜索) 的目标响应时间?
     - 聚合保存 (MedicalCase + Consultation + Prescription) 的目标?
   - 单机并发用户数预期 (诊所场景: 同时操作的医生数)
   - Desktop 客户端启动时间目标
   - Desktop 页面切换响应时间目标

2. **数据量预估**
   - 患者规模 (年新增量 / 总量上限)
   - 医案规模 (日均 / 年累积 / 总量预期)
   - 药材规模 (中药典收录 ~600种，自定义扩展)
   - 验方规模 (个人验方 + 共享验方)
   - 这些规模预估直接影响分页策略和索引设计

3. **可用性与可靠性**
   - 系统可用率要求 (对于单诊所部署)
   - 数据备份策略 (SQL Server 自动备份? 频率?)
   - SQLite 本地数据完整性保障
   - 故障恢复时间目标 (RTO)
   - 数据恢复点目标 (RPO)

4. **安全性 NFR**
   - 密码复杂度当前规则是否满足 (已在 PasswordPolicyValidator 中实现)
   - 是否需要审计日志保留期限?
   - 敏感数据传输加密 (当前 HTTPS? 本地网络环境?)
   - v1.0 SQLite 明文的风险评估与接受声明

**预期产出**: 新建 `docs/02-requirements/nfr.md` 或在 README.md 增加 NFR 章节

---

### Round 2: 核心业务流程与模块交互

**现状**: 各模块 PRD 各自独立，缺少模块间调用关系的全局视图。

**讨论要点**:

1. **端到端业务流程深化**
   - 当前 vision.md 的流程图过于简略 (6 步)
   - 需要展开为完整的用户操作序列:
     - 患者首次就诊的完整流程 (登记 -> 医案 -> 诊断 -> 处方 -> 打印)
     - 患者复诊流程 (选择患者 -> 查看历史 -> 新建医案 -> 复制历史处方)
     - 新药材录入并用于处方的流程
     - 验方创建并共享给其他医生的流程
   - 每个流程标注涉及的模块和 FR 编号

2. **模块依赖矩阵**
   - 14 个模块谁依赖谁的数据?
   - 示例:
     - 医案 -> 患者 (PatientId)
     - 处方 -> 药材 (HerbId, Price)
     - 验方 -> 药材 (HerbId, 延迟绑定)
     - 同步 -> 患者/药材/验方 (可同步实体)
   - 形成完整的模块依赖 Mermaid 图

3. **跨模块事件与通知**
   - Auth 事件体系 (FR-AUTH-013) 的消费者有哪些?
   - 患者数据变更是否需要通知医案模块?
   - 药材价格变更对已有处方的影响链?
   - Desktop 端 IEventAggregator 事件流全景图

4. **数据一致性边界**
   - 哪些场景需要事务保证 (如医案聚合保存)?
   - 哪些场景允许最终一致 (如同步)?
   - 删除患者时，关联医案如何处理 (引用检查)?

**预期产出**:
- 更新 `docs/01-product/vision.md` 补充详细业务流程
- 新增模块交互章节到架构文档或 README

### Round 3: UI/UX 交互模式与规范

**现状**: 仅 auth.md (登录界面)、printing.md (预览窗口)、medical-cases.md (编辑模式) 有 UI 描述。其余 11 个模块无界面规格。

**讨论要点**:

1. **全局 UI 模式确认**
   - 主数据列表页通用模式:
     - 搜索栏位置和行为 (即时搜索 vs 按钮搜索?)
     - 表格列定义原则 (哪些字段必须展示?)
     - 分页控件位置和样式
     - 批量操作按钮的位置和确认机制
   - 主数据编辑页通用模式:
     - 表单布局 (单列 vs 双列?)
     - 必填字段标记方式
     - 校验错误提示位置 (即时 vs 提交时?)
     - 保存/取消按钮位置
   - 对话框规范:
     - 确认对话框样式
     - 导入进度对话框
     - 错误提示样式

2. **关键交互确认**
   - 搜索: 输入即搜还是回车搜索? 防抖时间?
   - 表格排序: 支持多列排序? 默认排序规则?
   - 表单保存: 保存后停留在编辑页还是返回列表?
   - 删除确认: 单条和批量的确认文案差异?
   - 导入完成: 成功/部分成功/失败的 UI 反馈?

3. **工作区模式 (Clinical vs Management)**
   - 两种模式的界面差异具体体现在哪些模块?
   - Clinical 模式下隐藏哪些管理功能?
   - 模式切换的入口和交互方式

**预期产出**:
- 新建 `docs/02-requirements/ui-patterns.md` 定义全局 UI 规范
- 或在各模块 PRD 中补充 UI 章节

## 第二部分: 薄弱模块深化 (5 轮)

> 评级为 "良好" 的 5 个模块，需要补充缺失的维度。

### Round 4: 数据同步 (sync.md) -- 最薄弱

**当前评级**: 良好 (8 FR)
**核心缺口**: DTO 未定义、冲突 UI 缺失、模式切换策略不完整

**讨论要点**:

1. **同步数据传输格式 (DTO)**
   - 同步元数据 DTO 的完整字段定义 (SyncMetadataDto)
   - 差异比对结果 DTO (SyncDiffResultDto)
   - 上传/下载数据包 DTO (SyncDataPackageDto)
   - 同步日志/进度报告 DTO

2. **冲突解决流程深化**
   - 冲突场景枚举 (同时修改 / 一方删除 / 新增同名)
   - 冲突解决界面设计:
     - 如何展示 "本地版本 vs 远程版本" 对比?
     - 逐条解决 vs 批量解决?
     - "保留本地" / "使用远程" / "手动合并" 三种选项?
   - 自动解决规则 (如果有，哪些冲突可自动)

3. **完整同步工作流 (FR-SYNC-007) 深化**
   - 同步前检查清单 (网络连通性? 认证有效性?)
   - 同步进度 UI (步骤指示器? 进度百分比? 当前实体类型?)
   - 同步失败的恢复策略 (断点续传? 全量重试?)
   - 同步完成后的结果汇总 UI

4. **模式切换 (FR-SYNC-008) 深化**
   - 切换前的数据一致性检查 (是否有未同步的本地变更?)
   - 切换失败的回退策略
   - 切换过程中的用户引导 (向导式?)
   - 远程 -> 本地: 是否需要先同步?
   - 本地 -> 远程: 认证如何恢复?

**预期产出**: 更新 `docs/02-requirements/sync.md`，补充 DTO/UI/流程章节

### Round 6: 打印模块 (printing.md)

**当前评级**: 良好 (4 FR)
**核心缺口**: 模板排版细节缺失、无样例

**讨论要点**:

## 第三部分: 核心模块补强 (2 轮)

> 评级已为 "完善" 或 "最完善" 的模块，查找盲点和边界条件。

### Round 9: 医案管理 (medical-cases.md) -- 核心流程深化

**当前评级**: 最完善 (17 FR, 29 错误场景)
**目的**: 作为系统核心，需确保无遗漏的边界条件

**讨论要点**:

1. **医案生命周期边界**
   - 患者被删除后，其历史医案如何处理? (保留? 标记为孤立?)
   - 医案创建后未填写任何内容，直接关闭系统，状态如何?
   - 草稿医案的最大存活时间? (自动清理还是永久保留?)
   - 一个患者同时存在多个草稿医案是否允许?

2. **处方与药材的联动边界**
   - 处方中引用的药材被禁用后，已有处方如何展示?
   - 药材价格变更后，历史处方是否保持原价?
   - 处方导入验方时，验方中有"未绑定药材"(延迟绑定)如何处理?

3. **并发与锁定深化**
   - 两个医生同时打开同一医案的行为?
   - 锁定 (隔天自动锁定) 的精确时间计算 (0 点? 还是下次登录?)
   - 管理员解锁医案后，原医生正在编辑的场景?

4. **搜索与筛选**
   - 跨医案搜索 (FR-MC-010) 的搜索范围 (哪些字段?)
   - 搜索结果的排序规则 (最近? 相关度?)
   - 高级筛选: 日期范围 / 状态 / 医生?

**预期产出**: 更新 `docs/02-requirements/medical-cases.md`，补充边界条件

## 讨论规则

1. **每轮聚焦一个主题**，避免发散
2. **讨论结果即时写入 PRD**，不积压
3. **用"已确定"格式记录决策**，与现有风格一致
4. **新增 FR 追加到对应模块末尾**，保持编号连续
5. **允许跨轮回溯**，前面的讨论结论影响后续时可回调
