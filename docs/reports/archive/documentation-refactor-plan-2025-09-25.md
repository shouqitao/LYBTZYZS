# 文档重构建议计划（2025-09-25）

- **目标**：建立统一、可维护、可追溯的项目文档体系，为后续开发迭代提供可靠支撑。
- **编写人**：Thinker（ChatGPT）

## 1. 重构愿景
构建“三层文档体系”：
1. **导航层**：`docs/index.md` + 主题索引，提供快速入口；
2. **主题层**：架构、开发、需求、测试等分册，结构稳定、命名统一；
3. **记录层**：任务、报告、PRD 等历史资料归档，可按时间/阶段追溯。

## 2. 整体路线图
| 阶段 | 时间 | 目标 | 关键产出 |
|------|------|------|----------|
| Phase 1 | T+2 天 | 清理冗余、统一命名、搭建目录索引 | 新版 `docs/index.md`、归档/删除清单 |
| Phase 2 | T+5 天 | 建立交叉链接与模板规范 | 文档责任人列表、索引脚本、模板库 |
| Phase 3 | T+10 天 | 引入版本管理与发布节奏 | 文档版本说明、变更日志、审阅流程 |

## 3. 立即行动项（Phase 1）
1. **冗余文件治理**
   - 删除或迁移：`docs/index.md.bak`、历史阶段报告（2025-01-19 系列）转入 `docs/reports/archive/`。
   - `docs` 根目录新增 `ARCHIVE.md`，记录归档策略与入口。
2. **命名规范统一**
   - 采用 `yyyy-mm-dd-主题.md` 命名；为现有文件建立映射表，批量重命名。
   - 以 `reports/INDEX.md` 维护最新报告清单（按日期降序）。
3. **导航更新**
   - 扩充 `docs/index.md`：“架构决策”“任务索引”“阶段报告”三个新章节，各提供链接到专题索引。
   - 在每个分册目录下新增 README/INDEX，说明结构与维护人（如 `architecture/README.md`、`reports/INDEX.md`）。

## 4. 中期建设（Phase 2）
1. **交叉链接机制**
   - 任务文档模板增加“相关 PRD/报告”字段；PRD/报告反向记录“派生任务”。
   - `docs/tasks/README.md` 增加按主题/日期的汇总表，自动化脚本（PowerShell/Node）每次重构后更新。
2. **模板与约束**
   - Consolidate 模板到 `docs/templates/`（PRD、任务、报告、总结、ADR）。
   - 统一引用格式：文件路径 + 行号格式 `docs/path.md:12`，避免链接失效。
3. **责任制与审阅流程**
   - 为主要分册指定 Owner（如 Server、Client、测试、任务）。
   - 建立“文档变更审阅清单”：大规模重构需 Thinker + Coder 联审；一般更新由 Owner 自审。

## 5. 长期制度化（Phase 3）
1. **版本与发布**
   - 引入 `docs/CHANGELOG.md` 或纳入项目 `CHANGELOG.md`，记录关键文档变更。
   - 建立季度文档复审会议（输出复审报告）。
2. **自动化支持**
   - 脚本：生成目录索引、检测孤立文档、检查命名规范。
   - CI 集成：变更影响 `docs/` 时触发 markdown lint、链接检查（MarkdownLint + remark-lint/hyperlink 验证）。
3. **知识回收**
   - 定期（每月）评估过期报告，归档或更新；
   - 建立“最佳实践”专题，将重复出现的结论整理为简化版指南。

## 6. 角色分工（建议）
| 角色 | 责任 | 主要目录 |
|------|------|----------|
| Thinker | 架构决策、任务发布、索引维护 | `index.md`、`architecture/`、`reports/` |
| Coder | 实施总结、模板使用、任务归档 | `docs/tasks/`、`development/` |
| QA（如有） | 测试文档、用例、覆盖报告 | `testing/` |
| PM/BA（如有） | PRD、需求跟踪 | `prd/`、`prds-summary/` |

## 7. 风险与缓解
- **风险**：大规模重命名影响历史链接。
  - **缓解**：提供映射表、更新索引、在 README 中列“迁移公告”。
- **风险**：文档 Owner 未及时更新。
  - **缓解**：每周例会检查“文档行动项”清单，必要时指派代理。
- **风险**：自动化脚本维护成本。
  - **缓解**：脚本纳入 `scripts/docs/` 并配套 README，限制脚本类型（PowerShell/Node 二选一）。

## 8. 验收标准
1. 导航层可在 2 步内找到任一关键文档；
2. 所有报告、任务、PRD 均在索引中可检索，命名统一；
3. 文档模板、责任人、审阅流程形成固定制度，并写入 `docs/styleguide.md` 或 `docs/development/documentation-guidelines.md`；
4. 文档变更在 CI 中通过 Markdown lint 与链接检查；
5. 至少一次归档操作完成（历史报告入档）。
