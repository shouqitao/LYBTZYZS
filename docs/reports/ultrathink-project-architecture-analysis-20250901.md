## 🏗️ 架构分析

### 1. 整体架构设计

#### 技术架构模式
```
前端层 (WPF + Prism.DryIoc)
    ├── Shell (主应用外壳)
    ├── 4个专业工作台 (角色化界面)
    ├── 8个业务模块 (患者、诊疗、处方等)
    └── 基础设施 (Core, Infrastructure, Services)

服务层 (.NET 8 + ASP.NET Core Web API)
    ├── 8个业务模块 (UltraThink双层/三层架构)
    ├── 共享基础 (Models, Interfaces, Utilities)
    └── 数据访问层 (EF Core + SQL Server)

数据层 (统一AppDbContext)
    ├── 业务实体 (Entities项目)
    ├── 数据迁移 (Infrastructure项目)
    └── SQL Server数据库
```

#### 架构优势
1. **清晰分层**：严格的前后端分离，职责边界明确
2. **模块化设计**：高内聚低耦合，支持独立开发和部署
3. **技术统一**：单一.NET生态系统，降低学习成本
4. **可扩展性**：Prism模块化前端，服务化后端架构

### 2. 服务层架构深度分析

#### UltraThink双层架构 (7个标准模块)
```
主Service (纯委托层)
    ├── QueryService (查询专业层)    # 搜索、筛选、统计、报表
    └── BusinessService (业务逻辑层) # CRUD、业务流程、事务管理
```

**适用模块**：Users, Patients, Consultation, Formula, Herbs, MedicalCase, Prescriptions

**架构特点**：
- **职责清晰**：查询与业务逻辑明确分离
- **代码精简**：主Service仅负责委托路由
- **易于维护**：修改某类功能只需关注对应层次

#### UltraThink三层架构 (1个特殊模块)

```
AuthService (纯委托层)
    ├── AuthServiceCore (核心操作层)    # 密码验证、管理员处理
    ├── AuthQueryService (查询专业层)   # Token验证、会话查询
    └── AuthBusinessService (业务逻辑层) # 登录流程、业务编排
```

**特殊原因**：Auth模块承担系统安全核心，需要额外的核心操作层处理敏感认证逻辑
