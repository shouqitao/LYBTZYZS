## 需求概述

### 背景
Epic #2210 Phase 4 实现了4:6统一诊疗界面，左侧40%为诊断面板(ConsultationPanel)，右侧60%为处方面板(PrescriptionEditorPanel)。当前处方面板的药材录入功能需要重构，参考经验方编辑器(EditFormulaDialog)的实现模式，复用现有的HerbCardControl控件。

### 需求描述
重构处方编辑器的药材录入区域，使用ItemsControl + UniformGrid + HerbCardControl模式替代原有DataGrid模式，并提供以下录入方式：
1. **手工录入** - 在主面板逐个添加药材卡片（默认方式）
2. **验方导入** - 点击按钮打开弹窗，从经验方库搜索并选择验方批量导入药材
3. **历史复制** - 点击按钮打开弹窗，从患者历史处方搜索并选择复制药材

### 交互方式说明（v1.1更新）
- **手工录入**: 直接在处方面板操作，无需弹窗
- **验方导入**: 通过"从验方导入"按钮打开FormulaImportDialog弹窗
- **历史复制**: 通过"从历史处方复制"按钮打开HistoryCopyDialog弹窗

弹窗设计要求：
- 支持搜索/查询功能
- 显示列表供用户选择
- 选择后预览内容
- 确认导入到当前处方

### 与经验方编辑器的差异
| 功能 | 经验方编辑器 | 处方编辑器 |
|------|-------------|-----------|
| 价格计算 | 不需要 | **需要**（单剂价格、总价格） |
| 剂数设置 | 不需要 | **需要** |
| 用法说明 | 不需要 | **需要** |
| 验方导入 | 不适用 | **需要** |
| 历史复制 | 不适用 | **需要** |

## 功能性需求

### FR-001: 手工录入（已完成UI重构）
- **描述**: 使用HerbCardControl卡片式布局录入药材
- **UI模式**: ItemsControl + UniformGrid(Columns=4)
- **交互流程**:
  1. 输入药材名称或拼音码
  2. 7级拼音过滤算法匹配
  3. 选择药材后自动跳转到剂量输入
  4. Enter确认后自动添加新卡片
- **验收标准**:
  - [x] 药材卡片4列布局显示
  - [x] 支持拼音码搜索

### FR-004: 价格计算（已实现）
- **描述**: 处方特有功能，计算单剂价格和总价格
- **计算公式**:
  - 单剂价格 = Σ(药材单价 × 剂量)
  - 总价格 = 单剂价格 × 剂数
- **验收标准**:

  - [x] 总价格实时计算显示

## 业务规则

### BR-001: 重复药材检测
- 同一处方中不允许添加重复药材
- 检测到重复时显示警告，但允许用户确认添加

### BR-002: 验方导入规则
- 导入验方时保留原药材剂量
- 如果当前处方已有药材，追加而非替换
- 重复药材提示用户处理

### BR-003: 历史复制规则
- 只显示当前患者的历史处方
- 复制时保留原药材剂量
- 如果当前处方已有药材，追加而非替换

## 技术评估

### 影响范围
- **Client端**:
  - PrescriptionEditorPanel.xaml（UI布局 - 添加导入按钮）
  - PrescriptionPanelViewModel.cs（业务逻辑 - 添加弹窗命令）
  - **新增** FormulaImportDialog.xaml + FormulaImportDialogViewModel.cs（验方导入弹窗）
  - **新增** HistoryCopyDialog.xaml + HistoryCopyDialogViewModel.cs（历史复制弹窗）

### 依赖分析
- 依赖FormulaRepository获取经验方列表
- 依赖MedicalCaseRepository获取历史处方
- 复用HerbCardControl和PrescriptionItemViewModel

### 技术风险
- **风险1**: 验方导入后价格计算可能需要额外API调用获取药材单价
  - 缓解: 确保药材信息包含单价字段
- **风险2**: 历史处方数据量大时性能问题
  - 缓解: 分页加载，限制显示最近N条
