# 凌隐宝堂中医诊所系统 - 项目管理规范

**生效日期**: 2025年1月8日  
**版本**: 1.0

## 一、项目结构规范

### 1.1 目录结构
```
LYBTZYZS/
├── src/                    # 源代码
│   ├── Backend/           # 后端代码
│   ├── Frontend/          # 前端代码
│   └── Shared/            # 共享代码
├── docs/                   # 项目文档
│   ├── 01-项目管理/       # 管理文档
│   ├── 02-需求分析/       # 需求文档
│   ├── 03-架构设计/       # 架构文档
│   ├── 04-模块实现/       # 实现文档
│   ├── 05-开发指南/       # 开发文档
│   ├── 08-用户文档/       # 用户文档
│   ├── 09-项目记录/       # 历史记录
│   └── 10-项目规范/       # 规范文档
├── scripts/                # Python脚本
├── tests/                  # 测试代码
├── PRPs/                   # PRP文档
└── 根目录仅保留必要配置文件
```

### 1.2 文件命名规范
- 文档：`功能描述-日期.md`（如：`项目实现状态报告-20250108.md`）
- 脚本：`功能_描述.py`（如：`database_manager.py`）
- 使用小写字母和下划线，避免空格和特殊字符

## 二、脚本管理规范

### 2.1 脚本语言
- **统一使用 Python 3** 编写所有脚本
- 临时脚本使用后必须删除
- 所有脚本统一放在 `scripts/` 目录

### 2.2 脚本要求
```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
脚本功能说明
"""
```
- 必须包含文档字符串
- 使用 UTF-8 编码
- 遵循 PEP 8 规范
- 包含错误处理和中断处理

### 2.3 禁止事项
- ❌ 不在根目录创建脚本
- ❌ 不使用批处理(.bat)、PowerShell(.ps1)或Shell(.sh)脚本
- ❌ 不保留临时脚本

## 三、文档管理规范

### 3.1 文档位置
- 所有报告和总结必须生成到 `docs/` 对应子目录
- 根目录只保留：
  - README.md
  - LICENSE
  - CLAUDE.md
  - INITIAL.md
  - 配置文件（.sln、Directory.Build.props等）

### 3.2 文档分类
| 类别 | 目录 | 内容 |
|------|------|------|
| 项目管理 | 01-项目管理 | 计划、里程碑、团队协作 |
| 需求分析 | 02-需求分析 | 业务需求、功能需求 |
| 架构设计 | 03-架构设计 | 系统架构、模块设计 |
| 模块实现 | 04-模块实现 | 实现总结、进度追踪 |
| 开发指南 | 05-开发指南 | 开发规范、环境搭建 |
| 用户文档 | 08-用户文档 | 用户手册、操作指南 |
| 项目记录 | 09-项目记录 | 历史文档、会议记录 |
| 项目规范 | 10-项目规范 | 管理规范、编码规范 |

### 3.3 文档更新
- 定期文档（如任务清单）：创建新版本，标注日期
- 临时文档：完成后移至历史文档文件夹
- 过期文档：定期清理或归档

## 四、代码管理规范

### 4.1 提交规范
```
<type>: <subject>

<body>

<footer>
```

类型（type）：
- feat: 新功能
- fix: 修复bug
- docs: 文档更新
- style: 代码格式
- refactor: 重构
- test: 测试
- chore: 构建过程或辅助工具

### 4.2 分支策略
- master: 主分支，稳定版本
- develop: 开发分支
- feature/*: 功能分支
- bugfix/*: 修复分支

## 五、开发流程规范

### 5.1 任务管理
1. 使用 TODO 文档跟踪任务
2. 任务分为：紧急、高、中、低优先级
3. 定期更新任务状态

### 5.2 测试要求
- 单元测试覆盖率目标：50%
- 新功能必须包含测试
- API 必须有集成测试

### 5.3 代码审查
- 重要功能需要代码审查
- 遵循编码规范
- 确保文档完整

## 六、部署规范

### 6.1 环境管理
- 开发环境：本地 Visual Studio
- 测试环境：内部服务器
- 生产环境：客户服务器

### 6.2 发布流程
1. 运行 `publish_production.py` 生成发布包
2. 测试发布包功能
3. 更新部署文档
4. 执行部署

## 七、工具使用

### 7.1 推荐工具
- IDE: Visual Studio 2022
- 数据库: SQL Server Management Studio
- API测试: Postman / Swagger
- 版本控制: Git

### 7.2 脚本工具
- `dev_manager.py`: 开发环境管理
- `database_manager.py`: 数据库管理
- `publish_production.py`: 生产发布

## 八、质量标准

### 8.1 代码质量
- 无编译警告
- 遵循命名规范
- 适当的注释
- 合理的错误处理

### 8.2 文档质量
- 结构清晰
- 内容完整
- 及时更新
- 格式统一

## 九、安全规范

### 9.1 敏感信息
- 不提交密码、密钥到代码库
- 使用配置文件管理敏感信息
- 生产配置与开发配置分离

### 9.2 权限管理
- 最小权限原则
- 定期审查权限
- 记录权限变更

## 十、持续改进

### 10.1 定期回顾
- 每周回顾任务进度
- 每月回顾技术债务
- 每季度回顾架构设计

### 10.2 知识分享
- 记录解决方案
- 分享最佳实践
- 维护知识库
