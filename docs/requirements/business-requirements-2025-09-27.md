# LYBT中医诊所管理系统 - 业务需求规范书

**版本**：v1.0  
**日期**：2025-09-27  
**编制**：基于项目经理访谈整理  
**状态**：已确认  

## 一、系统定位

### 1.1 目标用户
- **主要用户**：中小型中医诊所
- **系统规模**：单诊所版本（预留多诊所扩展）
- **用户规模**：2-3名医生，日均就诊20-100人

### 1.2 核心价值
- 规范中医诊疗流程
- 提高处方开具效率
- 完整的病历管理
- 支持诊疗经验积累

## 二、核心业务模型

### 2.1 业务实体关系

```
一次就诊 = 一个病历(MedicalCase) = 一个诊断(Consultation) = 0或1个处方(Prescription)
```

**关键原则**：
- **MedicalCase是设计中心**：每次就诊创建新病历
- **一对一关系**：病历、诊断、处方之间是一对一关系
- **复诊处理**：复诊创建新病历，但可查看历史记录

### 2.2 诊疗流程

```mermaid
graph LR
    A[患者到诊] --> B[选择/新建患者]
    B --> C[创建病历MedicalCase]
    C --> D[填写诊断Consultation]
    D --> E{是否开方?}
    E -->|是| F[创建处方Prescription]
    E -->|否| G[结束诊疗]
    F --> G
    
    style C fill:#f9f,stroke:#333,stroke-width:4px
```

### 2.3 诊疗状态管理

- **暂存**：临时保存，可继续编辑（应对临时离开、急诊插队）
- **结束**：正常完成诊疗
- **取消**：放弃本次诊疗

## 三、功能需求详述

### 3.1 用户与权限

#### 当前版本角色
| 角色 | 权限说明 |
|------|----------|
| 管理员 | - 所有模块增删查改<br>- 修改过期病历（0点后）<br>- 维护公用方剂<br>- 系统配置管理 |
| 医生 | - 当天病历/诊断/处方的增删查改<br>- 查看所有历史记录<br>- 维护个人方剂（可选共享） |

**注**：医生之间无级别差异，权限相同

#### 预留扩展
- 前台/挂号员
- 药房管理员
- 财务人员

### 3.2 患者管理

#### 基本信息
- 姓名、性别、年龄、身份证
- 联系电话、地址
- 拼音码（自动生成，如：张三→ZS）

#### 查询功能
- 支持：姓名、电话、身份证、拼音码
- 模糊查询
- 按最近就诊时间排序

### 3.3 诊断记录（Consultation）

#### 必填内容
- 主诉
- 现病史
- 四诊信息：
  - 望诊
  - 闻诊
  - 问诊
  - 切诊
- 中医辨证
- 治疗原则

#### 查询支持
- 症状关键字
- 中医证型
- 患者姓名
- 时间范围

### 3.4 处方管理（Prescription）

#### 开方方式（可组合使用）
1. **逐个添加**：一味一味添加药材
2. **方剂导入**：
   - 可多次导入不同方剂
   - 重复药材取最小剂量
3. **历史复制**：从患者历史处方复制

#### 处方要素
- 药材组成（名称、剂量）
- 剂数（默认7剂）
- 用法用量
- 医嘱
- 来源追踪（记录导入的方剂或历史处方）

#### 价格计算
```
单味药价格 = 药材单价 × 剂量(克) × 剂数 × 折扣
处方总价 = 所有药材价格之和
```

#### 打印显示
- 每副价格
- 副数
- 总价

### 3.5 药材管理（Herbs）

#### 基础信息
- 名称、规格、单位
- 单价（用于处方计算）
- 拼音码（自动生成，如：黄芪→HQ）

#### 当前版本不包含
- 库存管理
- 进销存
- 供应商管理

### 3.6 方剂管理（Formula）

#### 方剂特性
- 经验方模板
- 常见症状标签（便于快速查找）
- 组成药材及剂量

#### 权限管理
- 管理员方剂：全员可见，作为诊所公用
- 医生方剂：
  - 个人使用
  - 可选择共享（IsShared字段）
  - 共享后其他医生可见

### 3.7 病历修改规则

**核心规则**：当天可改，过期锁定

| 时间 | 医生权限 | 管理员权限 |
|------|----------|------------|
| 当天（0点前） | 可修改 | 可修改 |
| 过期（0点后） | 只读 | 可修改 |

适用范围：病历、诊断、处方

## 四、非功能需求

### 4.1 性能要求
- 历史数据查询：<1秒响应
- 常用数据（患者、药材、方剂）：建议缓存
- 并发用户：支持10-15人同时在线

### 4.2 数据量预估
- 患者档案：万级
- 历史处方：十万级
- 药材种类：500-1000种
- 总数据量：<50GB

### 4.3 易用性要求

#### 拼音码快速输入
自动生成规则：取中文首字母大写
- 患者：张三→ZS
- 药材：黄芪→HQ  
- 方剂：小柴胡汤→XCHT

应用场景：
- 快速查找患者
- 快速添加药材
- 快速导入方剂

#### 查询便利性
- 所有查询支持模糊匹配
- 支持拼音码查询
- 查询结果分页
- 支持Excel导出

### 4.4 扩展性设计

#### 预留接口
- 多租户（TenantId）
- 数据共享机制
- 统计分析字段
- API版本控制

#### 未来功能
- 多诊所管理
- 库存管理
- 财务结算
- 统计报表
- 移动端支持

## 五、技术约束

### 5.1 开发原则
- **KISS原则**：保持简单，避免过度设计
- **YAGNI原则**：只实现当前需要的功能
- **增量迭代**：小步快跑，逐步完善

### 5.2 技术选型
- 前端：WPF + Prism
- 后端：ASP.NET Core Web API
- 数据库：SQL Server
- 缓存：内存缓存（MemoryCache）

### 5.3 明确禁止
- 不使用CQRS/MediatR
- 不使用微服务
- 不使用分布式架构
- 不使用消息队列
