# 桌面端界面流程需求（草案）

> 版本：2025-09-23

## 登录与启动

- 应用启动后默认呈现登录界面（`LoginRegion`）。
- 登录成功后根据用户角色切换到对应工作台：
  - 管理员（或用户名 `sysadmin`）→ 系统管理工作台（`SystemWorkbenchMainView`）。
- 医生/普通用户 → 诊疗工作台（当前代码名 `MedicalWorkbenchMainView`，待后续更名为诊疗/Treatment 语义）。
- 登录流程成功时自动加载角色所需模块，确保导航目标可用。

## 管理员工作台

- 进入后显示左侧导航菜单，可随时切换模块，无需返回上一级。
- 默认管理模块包括：
- 用户管理、患者管理、医案管理、诊疗管理、药材管理、验方管理、处方管理。
- 菜单可按需求增减（如系统设置、库存管理等）。
- 右侧内容区域为所选模块的主界面，支持独立导航。

## 医生工作台

- 顶部提供快捷操作：新增患者、快速开始诊疗。
- 导航菜单至少包含：
  - 诊疗（默认入口，包含问诊/诊断/处方等全流程）、患者档案、我的处方、常用验方、病历查询。
- 菜单项可扩展（例如历史统计、随访管理等）。
- 切换菜单直接在工作台内部完成，无需返回登录或主菜单。

## 角色设定

- 用户实体包含一个 `Role` 字段，用于驱动工作台与权限判断。
- 目前定义的角色：
  - `sysadmin`：超级管理员，隶属管理员范围，拥有全部模块权限。
- `doctor`（或默认 `user`）：医生角色，对应诊疗工作台（当前实现仍沿用 `Consultation` 前缀，后续需统一更名为 Diagnosis/Treatment）。
  - 其他角色（如 `admin`）可按诊所规模在未来版本补充。
- 初期版本假设：诊所规模较小，仅 `sysadmin` 与普通医生两类用户；`sysadmin` 即管理员，其余用户默认视为医生，优先保证临床使用。
- 后续若引入更多角色或精细权限，需要与后端角色/Claims 对齐并扩展 `WorkbenchRouter` 配置。
