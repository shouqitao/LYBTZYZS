# LYBT中医诊所管理系统 - MVP需求规范书（终版）

**版本**：v2.0  
**日期**：2025-09-27  
**编制**：基于需求复审和模块深化整理  
**状态**：已确认  

## 一、项目概述

### 1.1 系统定位
- **目标用户**：中小型中医诊所
- **部署方式**：云端服务器部署
- **客户端**：WPF桌面程序（需安装）
- **用户规模**：2-3名医生，日均就诊20-100人
- **版本策略**：MVP单诊所版本，预留多租户扩展

### 1.2 核心价值
- 规范中医诊疗流程
- 提高处方开具效率  
- 完整的病历管理
- 支持诊疗经验积累

### 1.3 技术架构
- **前端**：WPF + Prism.DryIoc
- **后端**：ASP.NET Core Web API + EF Core
- **数据库**：SQL Server
- **缓存**：MemoryCache
- **认证**：JWT

## 二、核心业务模型

### 2.1 业务实体关系

```
一次就诊 = 一个病历(MedicalCase) = 一个诊断(Consultation) = 0或1个处方(Prescription)
```

**关键原则**：
- **MedicalCase是设计中心**：每次就诊创建新病历
- **一对一关系**：病历、诊断、处方之间是一对一关系
- **复诊处理**：复诊创建新病历，但可查看历史记录
- **取消规则**：只有未完成病历可取消，取消不保存到数据库

### 2.2 诊疗流程

```mermaid
graph LR
    A[选择患者] --> B[自动创建病历]
    B --> C[填写诊断]
    C --> D[暂存/保存]
    D --> E{是否开方?}
    E -->|是| F[创建处方]
    E -->|否| G[完成诊疗]
    F --> G
```

### 2.3 状态管理

#### 病历状态
- **草稿/暂存**：可多次编辑保存
- **完成**：当天仍可修改，0点后锁定
- **取消**：不保存到数据库

#### 修改权限
| 时间 | 医生权限 | 管理员权限 |
|------|----------|------------|
| 当天（0点前） | 可修改自己的 | 可修改所有 |
| 过期（0点后） | 只读 | 可修改所有 |

## 三、用户角色与权限

### 3.1 角色定义

| 角色 | 权限说明 |
|------|----------|
| **管理员** | - 所有模块增删查改<br>- 修改过期病历<br>- 重置其他用户密码<br>- 管理公用方剂<br>- 查看操作日志<br>- 病历共享设置 |
| **医生** | - 查看自己的病历（+被共享的）<br>- 修改自己当天的病历<br>- 查看所有患者档案<br>- 维护个人方剂 |

### 3.2 登录认证
- **登录方式**：用户名密码
- **记住功能**：支持记住用户名和密码
- **失败锁定**：5次失败永久锁定，需管理员解锁
- **密码策略**：可配置复杂度（含不限制选项）
- **默认密码**：新用户使用配置的默认密码

### 3.3 病历共享机制
- 管理员可将病历共享给所有医生或指定医生
- 共享后权限与原医生相同（当天可编辑）
- 通过医生名字区分病历归属

## 四、功能模块详细设计

### 4.1 患者管理模块

#### 基本信息
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 姓名 | 文本 | ✅ | 自动生成拼音码 |
| 手机号 | 文本 | ✅ | 11位手机号 |
| 身份证号 | 文本 | ✅ | 18位身份证 |
| 家庭住址 | 文本 | ✅ | 详细地址 |
| 出生日期 | 日期 | ✅ | 用于计算年龄 |
| 年龄 | 数字 | - | 自动计算显示 |
| 拼音码 | 文本 | - | 自动生成（如：张三→ZS） |

#### 功能特性
- **快速查询**：支持姓名、拼音码、手机号、身份证查询
- **智能排序**：精确匹配优先，模糊匹配按最近就诊时间排序
- **Excel导入**：支持批量导入2000条患者数据
- **新建流程**：新建患者后自动选中并创建病历

### 4.2 病历管理模块（核心）

#### 病历要素
- **编号生成**：UUID
- **关联关系**：自动关联当前登录医生
- **生命周期**：草稿→完成/取消
- **列表显示**：默认显示今天，可全库搜索

#### 列表字段
- 患者姓名
- 就诊日期时间
- 病历状态
- 主治医生
- 电话号码（脱敏：138****1234）

#### 特殊逻辑
- 同时只能有一个未完成病历
- 新建时检查未完成病历并提示
- 预留挂号模块关联接口

### 4.3 诊断模块（Consultation）

#### 界面布局（14寸屏幕优化）
```
┌─────────────┬─────────────┐
│   望诊      │    闻诊     │  第1-2行（2×2）
├─────────────┼─────────────┤
│   问诊      │    切诊     │
├─────────────┼─────────────┤
│   主诉      │   现病史    │  第3行
├─────────────┴─────────────┤
│         诊断（大输入框）      │  第4行
├───────────────────────────┤
│       备注/医嘱            │  第5行
└───────────────────────────┘
```

#### 字段属性
- **必填**：诊断
- **选填**：四诊、主诉、现病史、备注
- **输入方式**：全部多行文本框
- **后期扩展**：常用语库（MVP不实现）

### 4.4 处方管理模块

#### 界面布局
```
上部：患者信息
中部：药材表格（6行×4列，超24味自动增行）
     每格显示：药名 + 剂量
下部：剂数 | 单副价格 | 总价 | 备注
```

#### 四种开方方式

##### 方式1：表格直接编辑
- 4列×N行表格
- 双击单元格进入编辑
- Tab键横向导航
- 支持拼音码/中文匹配

##### 方式2：快速输入弹窗
- 纯键盘操作
- 药名→回车→剂量→回车→循环
- 连续录入无需鼠标

##### 方式3：方剂导入
- 查找方剂→导入
- 支持多次导入
- 重复药材取最小剂量
- 弹窗提示重复项

##### 方式4：历史处方复制
- 从患者历史处方复制
- 逻辑同方剂导入

#### 价格计算
```
单味药价格 = 药材单价 × 剂量 × 剂数 × 折扣
处方总价 = Σ(所有药材价格)
```

#### 处方打印（A5横向）
```
============诊所名称============
            处方笺
姓名:___ 性别:___ 年龄:___ 日期:___
--------------------------------
诊断：_________________________
--------------------------------
Rp:
药材1 剂量  药材2 剂量  药材3 剂量  药材4 剂量
...（4列显示）
--------------------------------
剂数：__ 剂    用法：每日一剂，分两次服
--------------------------------
医师：______  每副：￥___ 总价：￥___
```

### 4.5 药材管理模块

#### 数据结构
| 字段 | 必填 | 说明 |
|------|------|------|
| 名称 | ✅ | 药材名称 |
| 拼音码 | 自动 | 根据名称生成 |
| 单位 | ✅ | 默认"克" |
| 单价 | ✅ | 用于处方计算 |
| 产地 | ❌ | 可选 |
| 规格 | ❌ | 可选 |
| 功效 | ❌ | 可选 |
| 状态 | ✅ | 启用/禁用 |

#### 核心功能
- **Excel导入**：300种药材批量导入
- **价格管理**：支持价格调整，处方锁定历史价格
- **快速查询**：拼音码+中文模糊匹配
- **状态控制**：禁用的药材不能开方

### 4.6 方剂管理模块

#### 数据结构
| 字段 | 说明 |
|------|------|
| 方剂名称 | 必填，自动生成拼音码 |
| 组成药材 | 药材列表+剂量 |
| 功效主治 | 文本描述 |
| 分类 | 解表剂、清热剂等 |
| 创建者 | 医生/管理员 |
| 共享状态 | 个人/共享/公用 |

#### 权限规则
- 管理员方剂：全员可见（公用）
- 医生方剂：可选择共享
- 共享方剂：其他医生可见可用

#### 核心功能
- **Excel导入**：200个经验方
- **分类管理**：按功效分类
- **快速搜索**：名称+功效+症状

### 4.7 用户管理模块

#### 用户信息
| 字段 | 必填 | 说明 |
|------|------|------|
| 登录账号 | ✅ | 唯一标识 |
| 密码 | - | 新建时用默认密码 |
| 真实姓名 | ✅ | 显示名称 |
| 角色 | ✅ | 医生/管理员 |
| 手机号 | ✅ | 联系方式 |
| 所属诊所 | ✅ | 预留多租户 |

#### 密码管理
- 新用户使用配置的默认密码
- 管理员可重置其他用户为默认密码
- 管理员自己通过技术手段重置

### 4.8 系统日志

#### 后端日志
- **API日志**：所有API调用记录
- **错误日志**：Service和Repository层错误
- **登录日志**：登录成功/失败记录

#### 前端日志（根据时间决定是否实现）
- **本地存储**：%AppData%/LYBT/Logs/
- **日志级别**：Error/Warning/Info/Debug
- **关键操作**：登录、模块切换、数据保存
- **性能监控**：超时、卡顿、内存告警

## 七、非功能需求

### 7.1 性能要求
- **响应时间**：1-2秒（可根据成本调整）
- **查询性能**：历史数据<1秒
- **并发支持**：10-15人同时在线
- **数据量**：患者万级，处方十万级

### 7.2 可用性要求
- **屏幕适配**：优化14寸笔记本显示
- **键盘操作**：处方录入支持纯键盘
- **进度提示**：超时显示加载状态
- **拼音输入**：所有查询支持拼音码

### 7.3 安全要求
- **认证机制**：JWT Token
- **密码策略**：可配置复杂度
- **操作日志**：记录关键操作
- **数据保护**：软删除，不物理删除

### 7.4 并发处理
- 患者档案修改采用乐观锁（开发成本高则按序保存）
- 病历中的患者信息为快照，不受档案修改影响
