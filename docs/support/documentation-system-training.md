# LYBTZYZS 文档系统培训材料

**培训目标**: 使团队成员掌握新的文档结构和维护方法
**培训时长**: 30分钟
**适用人群**: 全体开发人员

## 📚 培训大纲

### 1. 新文档系统介绍 (5分钟)

#### 背景说明
- **问题**: 原文档系统包含大量过程记录，文档膨胀至584个
- **目标**: 状态vs过程分离，提升维护效率50%
- **结果**: 文档数量减少83%，查找效率提升

#### 新结构概览
```
docs/
├── state/      - 系统状态文档 (130个)
├── reference/  - 参考资料 (113个)
├── support/    - 支持文档 (27个)
└── process/    - 过程归档 (314个)
```

### 2. 各目录使用指南 (10分钟)

#### state/ - 系统状态文档
**用途**: 了解系统当前状态和架构设计

**什么时候使用**:
- 新成员入职了解系统架构
- 开发时参考架构设计
- 代码审查时检查一致性

**重要文件**:
- `state/index.md` - 系统总览
- `state/architecture/client/README.md` - Client端架构
- `state/architecture/server/README.md` - Server端架构

#### reference/ - 参考资料
**用途**: 开发过程中的技术参考

**什么时候使用**:
- 查询API接口规范
- 学习技术框架使用
- 参考代码示例

**重要文件**:
- `reference/api/` - API接口文档
- `reference/how-to/` - 操作指南
- `reference/tutorials/` - 教程文档

#### support/ - 支持文档
**用途**: 开发支持和工具使用

**什么时候使用**:
- 使用文档模板
- 运行自动化工具
- 查看开发指南

**重要文件**:
- `support/templates/` - 文档模板
- `support/tools/` - 工具使用指南
- `support/guides/` - 开发指南

### 3. 状态vs过程分离原则 (5分钟)

#### 状态文档标准
✅ **应该包含**:
- 当前系统架构设计
- 功能使用说明
- API接口规范
- 开发配置要求

❌ **不应该包含**:
- "以前"、"过去"等时间标记
- 架构演变历史过程
- Phase 1/2等阶段性描述
- 具体日期和实施时间

#### 过程信息获取
**重要历史信息保存在**:
1. **Serena记忆系统**: Epic执行、架构决策、技术选型
2. **Git历史**: 完整的变更历史和决策讨论
3. **Process目录**: 归档的历史分析报告

### 4. 文档维护操作 (5分钟)

#### 日常维护任务
1. **每周检查**: 运行文档健康检查脚本
```powershell
.\scripts\docs-maintenance-check.ps1 -Verbose
```

2. **代码变更时同步更新文档**:
- 修改API时更新`reference/api/`
- 架构变更时更新`state/architecture/`
- 新功能时更新相关功能文档

3. **新增文档时**:
- 确定文档归属类别
- 使用标准模板
- 更新相关链接

#### 自动化工具使用
```powershell
# 文档健康检查
.\scripts\docs-maintenance-check.ps1

# 代码同步检查
.\scripts\docs-code-sync-check.ps1

# 自动修复（如果支持）
.\scripts\docs-maintenance-check.ps1 -Fix
```

### 5. 最佳实践 (3分钟)

#### 文档编写规范
- 使用标准Markdown语法
- 文件名使用小写字母和连字符
- 提供完整可执行的代码示例
- 使用描述性的链接文本

#### 质量标准
- **文档一致性**: 与代码一致性 ≥95%
- **更新及时性**: 代码变更7天内更新文档
- **链接有效性**: 失效链接 ≤1%

#### 常见问题避免
- 不要在状态文档中记录过程信息
- 不要创建重复内容
- 不要使用失效的外部链接
- 不要忘记更新相关链接

### 6. 实践演练 (2分钟)

#### 场景1: 新成员入职
**路径**: `state/index.md` → `state/architecture/` → `reference/how-to/`

#### 场景2: 修改API接口
1. 修改代码实现
2. 更新`reference/api/`中的对应文档
3. 运行同步检查脚本验证

#### 场景3: 查询历史决策
1. 搜索Serena记忆系统
2. 查看Git提交历史
3. 参考`process/`目录归档
