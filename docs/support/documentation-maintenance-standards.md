# LYBTZYZS 文档维护规范

**版本**: v1.0
**生效日期**: 2025-11-21
**适用范围**: 全项目文档维护

## 📋 维护原则

### 1. 状态vs过程分离原则
- **状态文档**: 只反映当前系统状态，不包含历史演变过程
- **过程记录**: 保存到Serena记忆系统，Git历史保留详细信息
- **时间标记**: 避免在状态文档中使用具体时间标记

### 2. 最小维护成本原则
- **准确性优先**: 文档必须与实际代码保持一致
- **简洁明了**: 移除冗余信息，保持文档精炼
- **易于更新**: 建立清晰的更新流程和标准

### 3. 用户导向原则
- **按需组织**: 按用户使用场景组织文档结构
- **快速定位**: 30分钟内找到需要的信息
- **实用有效**: 文档内容必须具有实际指导价值

## 📁 目录维护标准

### state/ 目录维护
**用途**: 系统状态文档，反映当前架构和功能

**维护标准**:
1. **时间无关性**: 不包含"以前"、"过去"、"Phase 1"等时间标记
2. **版本明确**: 只包含当前版本信息
3. **功能导向**: 按用户功能需求组织内容
4. **链接准确**: 内部链接指向当前有效文档

**检查清单**:
- [ ] 无历史过程描述
- [ ] 无过时版本信息
- [ ] 链接全部有效
- [ ] 与实际代码一致

### reference/ 目录维护
**用途**: 开发参考资料和指南

**维护标准**:
1. **技术准确**: 技术内容准确无误
2. **版本匹配**: 与当前技术栈版本匹配
3. **示例有效**: 代码示例可以正常运行
4. **最佳实践**: 体现当前最佳实践方法

**检查清单**:
- [ ] API文档与代码一致
- [ ] 代码示例可执行
- [ ] 技术栈版本正确
- [ ] 最佳实践最新

### support/ 目录维护
**用途**: 开发支持和工具文档

**维护标准**:
1. **模板有效**: 模板格式正确，可直接使用
2. **工具可用**: 工具指南与实际工具版本匹配
3. **流程清晰**: 开发流程步骤清晰可执行
4. **检查完整**: 检查清单覆盖完整场景

**检查清单**:
- [ ] 模板可直接使用
- [ ] 工具指南准确
- [ ] 流程步骤清晰
- [ ] 检查清单完整

### process/ 目录维护
**用途**: 历史过程记录归档

**维护标准**:
1. **只读归档**: 不再修改，只供查阅
2. **信息完整**: 重要信息已保存到记忆系统
3. **结构清晰**: 按时间或主题组织
4. **访问引导**: 包含如何获取最新信息的引导

## 🔄 更新流程

### 日常维护
1. **每周检查**: 运行自动化检查脚本
2. **问题修复**: 及时修复发现的问题
3. **版本同步**: 代码变更时同步更新文档
4. **定期清理**: 清理过时和冗余内容

### 重大更新
1. **影响评估**: 评估变更对文档的影响
2. **更新计划**: 制定文档更新计划
3. **分步实施**: 按优先级分步更新
4. **验证检查**: 验证更新后文档准确性

### 新增文档
1. **分类确定**: 确定文档归属类别
2. **模板使用**: 使用标准模板创建
3. **链接更新**: 更新相关链接
4. **检查验证**: 运行自动化检查

## 🔧 自动化工具

### 检查脚本 (scripts/docs-maintenance-check.ps1)
**功能**: 自动化文档健康检查

**检查项目**:
- 目录结构完整性
- 状态文档纯净度
- 链接有效性
- 文档大小异常
- 重复文件检测

**使用方法**:
```powershell
# 基本检查
.\scripts\docs-maintenance-check.ps1

# 详细输出
.\scripts\docs-maintenance-check.ps1 -Verbose

# 自动修复（如果支持）
.\scripts\docs-maintenance-check.ps1 -Fix
```

### CI/CD集成
**建议**: 将文档检查集成到CI/CD流程

**配置示例**:
```yaml
# .github/workflows/docs-check.yml
name: Documentation Check
on: [push, pull_request]
jobs:
  docs-check:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v2
      - name: Check Documentation
        run: .\scripts\docs-maintenance-check.ps1
```

## 📊 质量指标

### 健康评分标准
- **优秀 (90-100分)**: 无错误，少量警告
- **良好 (70-89分)**: 无错误，中等数量警告
- **需改进 (50-69分)**: 少量错误，多个警告
- **不合格 (<50分)**: 多个错误，需要立即修复

### 关键指标
- **文档一致性**: 与代码一致性 ≥95%
- **链接有效性**: 失效链接 ≤1%
- **更新及时性**: 代码变更后7天内更新文档
- **用户满意度**: 开发者反馈满意度 ≥85%

## 🎯 最佳实践

### 写作规范
1. **Markdown标准**: 遵循标准Markdown语法
2. **命名规范**: 文件名使用小写字母和连字符
3. **标题层次**: 合理使用标题层次，不超过4级
4. **代码示例**: 提供完整可执行的代码示例

### 链接管理
1. **相对链接**: 优先使用相对路径链接
2. **链接描述**: 使用描述性的链接文本
3. **定期检查**: 定期检查外部链接有效性
4. **避免死链**: 删除文档时处理相关链接

### 图片管理
1. **图片格式**: 优先使用PNG和SVG格式
2. **文件大小**: 控制图片文件大小
3. **路径管理**: 使用相对路径引用图片
4. **替代文本**: 提供有意义的替代文本
