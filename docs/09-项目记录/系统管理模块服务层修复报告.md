# 系统管理模块服务层修复报告

## 修复概览

**修复日期**: 2025年8月7日  
**修复目标**: 解决系统管理模块违反分层架构的问题  
**影响范围**: 3个 ViewModel（用户管理、验方管理、药材管理）

## 问题描述

### 发现的架构违规

```
错误的架构:
ViewModel → ApiService → API (跳过了Service层)

正确的架构:
ViewModel → Service → ApiService → API
```

### 受影响的 ViewModels

1. **UserManagementViewModelSimple**
   - 继承: `BaseManagementViewModel<UserInfo, IUserApiService>`
   - 问题: 直接使用 IUserApiService

2. **FormulaManagementViewModel**
   - 继承: `BaseManagementViewModel<FormulaInfo, IFormulaApiService>`
   - 问题: 虽有 IFormulaService 但基类使用 IFormulaApiService

3. **HerbManagementViewModelRefactored**
   - 继承: `BaseManagementViewModel<HerbInfo, IHerbApiService>`
   - 问题: 直接使用 IHerbApiService

## 修复方案实施

### 1. 创建新基类

**文件**: `BaseServiceManagementViewModel.cs`
```csharp
public abstract class BaseServiceManagementViewModel<TModel, TService> : NavigationViewModel
    where TModel : class, new()
    where TService : class
```

**特点**:
- 使用服务层接口而不是 API 服务接口
- 保持与原基类相同的功能
- 提供抽象方法供子类实现
- 统一的分页、搜索、CRUD 操作

### 2. 修改 UserManagementViewModelSimple

**修改前**:
```csharp
public class UserManagementViewModelSimple : BaseManagementViewModel<UserInfo, IUserApiService>
{
    public UserManagementViewModelSimple(IUserApiService service, ...)
}
```

**修改后**:
```csharp
public class UserManagementViewModelSimple : BaseServiceManagementViewModel<UserInfo, IUserService>
{
    public UserManagementViewModelSimple(
        IUserService userService,
        IUserApiService userApiService, // 仍保留用于特殊场景
        ...)
}
```

**主要更改**:
- 继承新基类
- 使用 IUserService 作为主要服务
- 简化数据加载逻辑
- 添加额外功能（重置密码、切换状态）

### 3. 修改 FormulaManagementViewModel

**修改前**:
```csharp
public class FormulaManagementViewModel : BaseManagementViewModel<FormulaInfo, IFormulaApiService>
```

**修改后**:
```csharp
public class FormulaManagementViewModel : BaseServiceManagementViewModel<FormulaInfo, IFormulaService>
```

**主要更改**:
- 使用 IFormulaService 替代 IFormulaApiService
- 调整服务调用方法
- 简化数据转换逻辑

### 4. 修改 HerbManagementViewModelRefactored

**修改前**:
```csharp
public class HerbManagementViewModelRefactored : BaseManagementViewModel<HerbInfo, IHerbApiService>
```

**修改后**:
```csharp
public class HerbManagementViewModelRefactored : BaseServiceManagementViewModel<HerbInfo, IHerbService>
```

**主要更改**:
- 使用 IHerbService 进行数据操作
- 优化库存统计逻辑
- 改进异步操作处理

## 注意事项

### 1. 依赖注入更新

需要确保所有服务正确注册：
```csharp
// 服务层
containerRegistry.RegisterSingleton<IUserService, UserService>();
containerRegistry.RegisterSingleton<IFormulaService, FormulaService>();
containerRegistry.RegisterSingleton<IHerbService, HerbService>();

// API 服务（仍需要保留）
containerRegistry.RegisterSingleton<IUserApiService>(...);
containerRegistry.RegisterSingleton<IFormulaApiService>(...);
containerRegistry.RegisterSingleton<IHerbApiService>(...);
```

### 2. 兼容性考虑

- 保留了 API 服务的引用，用于特殊场景
- 基类方法签名有变化（void → Task）
- 需要更新相关的单元测试

### 3. 性能影响

- 增加一层抽象，理论上有微小性能损耗
- 实际使用中影响可忽略不计
- 可通过服务层添加缓存优化

1. **符合架构规范**: 100% 遵循分层架构原则
