# 前端编译错误修复总结

## 修复时间
2025-08-07

## 问题概述
SystemManagement 模块存在28个编译错误，主要涉及：
- PaginationRequest 缺少 ExtensionData 属性
- ServiceResult 属性名称不匹配（IsSuccessStatusCode vs IsSuccess）
- API 方法参数不匹配
- 架构设计问题

## 修复详情

### 1. PaginationRequest 扩展问题
**问题**: FormulaManagementViewModel 试图使用 PaginationRequest.ExtensionData 属性，但该属性不存在
**解决方案**: 创建 ExtendedPaginationRequest 类继承 PaginationRequest 并添加 ExtensionData 字典

### 2. ServiceResult 属性不匹配
**问题**: 代码使用了错误的属性名：
- `IsSuccessStatusCode` → `IsSuccess`
- `Error?.Content` → `ErrorMessage`
- `Content` → `Data`

**影响文件**:
- PrescriptionService.cs
- ViewPrescriptionDialogViewModel.cs
- PrescriptionManagementViewModel.cs
- EditPrescriptionDialogViewModel.cs
- HerbManagementViewModelRefactored.cs
- FormulaManagementViewModel.cs
- UserManagementViewModelSimple.cs

### 3. API 方法参数问题
**问题**: 方法调用时缺少必需的参数
- UpdateHerbAsync 需要 (Guid id, HerbUpdateDto dto)
- UpdateUserAsync 需要 (Guid id, UserUpdateDto dto)

### 4. ICommonDialogService 方法名称问题
**问题**: 使用了错误的方法名 ShowConfirmAsync
**解决方案**: 改为正确的方法名 ShowConfirmationAsync

### 5. 药材库存管理设计
**问题**: HerbInfo 模型不包含 Stock 和 MinStock 属性
**解决方案**: 根据业务需求，药材管理不涉及库存，只记录可用药材信息，相关代码已注释

### 6. ApiResponse vs ServiceResult
**问题**: 一些 ViewModel 直接使用了 Refit 的 ApiResponse 而不是封装后的 ServiceResult
**解决方案**: 使用 ApiErrorHandler.HandleApiResponseAsync 进行统一封装

## 架构改进建议

1. **统一响应模型**: 确保所有服务层方法返回 ServiceResult<T> 而不是原始的 ApiResponse<T>
2. **扩展机制**: 为需要额外参数的查询创建专门的请求类
3. **依赖注入**: 确保 ViewModel 注入正确的服务接口
