## 1. 概述

本指南介绍患者管理模块的完整操作功能，包括基础CRUD操作、批量导入/导出等（Epic #1934）。

**核心功能**：
- ✅ 新建患者（自动生成拼音码、身份证号验证）
- ✅ 编辑患者（更新信息、同步拼音码）
- ✅ 查看患者详情（只读模式）
- ✅ 删除患者
- ✅ 年龄自动计算（基于出生日期）
- ✅ **批量导入**（Server主导模式，Excel导入）
- ✅ **批量导出**（Server主导模式，支持关键词筛选）

**技术亮点**：
- 拼音码自动生成（使用hyjiacan.pinyin4net库）
- 年龄实时计算（前端+后端）
- FluentValidation条件验证（创建/更新统一DTO）
- Prism MVVM模式（Region Navigation + 事件驱动）
- **Server主导批量导入**（EPPlus在Server端，上传IFormFile）
- **Server主导批量导出**（EPPlus在Server端，下载File）

## 2. 新建患者

### 2.1 操作步骤

1. **进入新建页面**
   - 在患者列表页面，点击"新建"按钮
   - 系统导航到患者新建页面（`PatientCreateView`）

2. **填写基本信息**

   **必填字段**：
   - **患者姓名**（最大50字符）
     - 输入姓名后，拼音码会自动生成并显示
     - 示例：输入"张三" → 拼音码自动生成"ZS"

   - **身份证号**（18位）
     - 必填，最大18字符
     - 系统会进行格式验证

   **可选字段**：
   - **性别**（下拉选择：未知/男/女）
   - **出生日期**（日期选择器）
     - 选择后，年龄会自动计算并显示
   - **手机号码**（最大20字符）
   - **地址**（最大200字符）

3. **提交创建**
   - 点击"保存"按钮
   - 系统验证必填字段
   - 创建成功后，自动返回患者列表
   - 列表会实时刷新，显示新创建的患者

### 2.2 字段说明

#### 拼音码自动生成

**工作原理**：
- 前端：当用户输入姓名时，`Name`属性的setter会自动调用`PinYinHelper.GetPinYinCode()`
- 后端：Server端在创建时也会同步生成拼音码，确保数据一致性

**代码位置**：
- 前端：`PatientCreateViewModel.cs:51`
- 后端：`PatientService.cs:109-116`

**示例**：
```
输入姓名：李明
自动生成拼音码：LM

输入姓名：王小红
自动生成拼音码：WXH
```

#### 年龄自动计算

**计算规则**：
```csharp
if (BirthDate.HasValue)
{
    var today = DateTime.Today;
    var age = today.Year - BirthDate.Value.Year;
    if (BirthDate.Value.Date > today.AddYears(-age))
    {
        age--;
    }
    return age;
}
```

**示例**：
- 出生日期：1990-05-15
- 今天：2025-11-09
- 计算年龄：35岁

**显示位置**：
- 列表页面：年龄列
- 详情页面：年龄字段
- 新建/编辑页面：年龄字段（只读，自动更新）

### 2.3 验证规则

| 字段 | 验证规则 | 错误提示 |
|-----|---------|---------|
| 患者姓名 | 必填，最大50字符 | "患者姓名不能为空" / "患者姓名长度不能超过50个字符" |
| 身份证号 | 必填，最大18字符 | "身份证号不能为空" / "身份证号长度不能超过18个字符" |
| 手机号码 | 可选，最大20字符 | "手机号码长度不能超过20个字符" |
| 地址 | 可选，最大200字符 | "地址长度不能超过200个字符" |

**提交条件**：
- 所有必填字段已填写
- 所有字段验证通过（无错误）
- 系统未处于加载状态

## 3. 编辑患者

### 3.1 操作步骤

1. **进入编辑页面**
   - 在患者列表页面，点击某个患者的"编辑"按钮
   - 系统导航到患者编辑页面（`PatientEditView`）
   - 页面自动加载患者数据

2. **修改信息**

   **可编辑字段**：
   - 患者姓名（修改后拼音码自动更新）
   - 性别
   - 出生日期（修改后年龄自动更新）
   - 身份证号
   - 手机号码
   - 地址
   - 状态（启用/禁用）

   **只读字段**：
   - 拼音码（自动生成，不可手动编辑）
   - 年龄（自动计算，不可手动编辑）

3. **提交更新**
   - 点击"保存"按钮
   - 系统验证必填字段
   - 更新成功后，自动返回患者列表
   - 列表会实时刷新，显示更新后的患者信息

### 3.2 拼音码同步更新

**更新逻辑**：
- 当用户修改患者姓名时，拼音码会自动更新
- Server端会检测姓名是否变化，只在变化时更新拼音码

**代码位置**：
- 前端：`PatientEditViewModel.cs:67`
- 后端：`PatientService.cs:136-152`

**示例**：
```
原姓名：张三 → 拼音码：ZS
修改为：张三丰 → 拼音码自动更新为：ZSF
```

### 3.3 状态管理

**状态选项**：
- **启用**（Enabled）：患者可正常使用
- **禁用**（Disabled）：患者被禁用，但数据保留

**注意事项**：
- 编辑页面新增了"状态"字段（新建时默认为"启用"）
- 禁用患者不会删除数据，只是标记为不可用状态

## 5. 删除患者

### 5.1 操作步骤

1. **触发删除操作**
   - 在患者列表页面，点击某个患者的"删除"按钮
   - 或在患者详情页面，点击"删除"按钮

2. **确认删除**
   - 系统弹出确认对话框："确定要删除该患者吗？"
   - 点击"确定"继续删除
   - 点击"取消"放弃删除

3. **删除完成**
   - 删除成功后，系统显示成功提示
   - 患者列表自动刷新，被删除的患者不再显示

### 5.2 删除策略

**当前实现**：
- 硬删除：直接从数据库中删除患者记录
- 不支持恢复：删除后无法恢复（请谨慎操作）

**注意事项**：
- ⚠️ 删除操作不可逆，请确认后再执行
- 如果患者有关联的病案、处方等数据，删除可能会失败（取决于外键约束）
- 建议：对于需要保留历史记录的患者，使用"禁用"状态而非删除

## 6. 特殊功能说明

### 6.1 拼音码生成

**技术实现**：
- 使用库：`hyjiacan.pinyin4net`
- 工具类：`LYBT.Shared.Utilities.Text.PinYinHelper`
- 方法：`PinYinHelper.GetPinYinCode(string name)`

**生成规则**：
- 提取每个汉字的拼音首字母
- 示例：
  - "张三" → "ZS"
  - "王小红" → "WXH"
  - "李明" → "LM"

**生成时机**：
- 新建：用户输入姓名时自动生成（前端） + 提交时生成（后端）
- 编辑：用户修改姓名时自动更新（前端） + 提交时同步（后端）
- 批量导入：导入时自动生成（后端）

**代码位置**：
```

- PatientEditViewModel.cs:67

后端：
- PatientService.cs:109-116 (CreateAsync)
- PatientService.cs:136-152 (UpdateAsync)
- PatientService.cs:254 (BatchImportAsync)
```

### 6.2 年龄计算

**计算位置**：
- **前端**：ViewModel的`Age`属性（getter）
- **后端**：Entity的`Age`属性（`[NotMapped]`标记）

**数据流**：
1. 用户选择出生日期
2. 前端ViewModel立即计算年龄并显示
3. 提交到后端时，只传输`BirthDate`字段
4. 后端Entity在查询时计算`Age`属性
5. Service层手动复制`Age`到DTO（因为AutoMapper不支持computed属性）
6. 返回前端显示

**代码位置**：
```

- PatientCreateViewModel.cs:96-112
- PatientEditViewModel.cs:112-128

后端计算：
- Patient.cs (Entity的Age属性)

后端复制：
- PatientService.cs:53-63 (GetPagedAsync)
- PatientService.cs:91-92 (GetByIdAsync)
```

### 6.3 FluentValidation条件验证

**应用场景**：
- 统一使用`PatientInputDto`进行创建和更新
- 通过`Id`字段判断是创建（Id为null）还是更新（Id有值）

**验证规则示例**（参考UserInputDtoValidator）：
```csharp
public class UserInputDtoValidator : AbstractValidator<UserInputDto>
{
    public UserInputDtoValidator()
    {
        // 用户名：创建时必填（Id为null），更新时可选
        RuleFor(x => x.UserName)
            .NotEmpty()
            .When(x => x.Id == null || x.Id == Guid.Empty);
    }
}
```

**关键点**：
- 使用`.When()`谓词进行条件验证
- 创建时：`Id == null || Id == Guid.Empty` → 必填
- 更新时：`Id`有值 → 可选

**代码位置**：
- `UserInputDtoValidator.cs:10-13`（参考示例）

## 7. 批量导入患者（Epic #1934核心功能）

### 7.1 功能概述

批量导入功能允许用户通过Excel文件快速导入大量患者数据。

**技术模式**：
- ⭐ **Server主导模式**（与Herbs的Desktop主导模式不同）
- Server端负责Excel文件解析（使用EPPlus库）
- Desktop端仅上传文件和接收导入结果

**性能要求**：
- **BR-004**: 单次最多导入10000条
- **BR-005**: 1000条记录 < 10秒

### 7.2 操作步骤

#### 步骤1：下载导入模板

1. 在患者列表页面，点击"📄 导出模板"按钮
2. 系统调用API `/api/v1/patients/import-template`
3. 保存Excel模板到本地（`患者导入模板_日期.xlsx`）

**模板结构**：

| 列名 | 是否必填 | 数据类型 | 长度限制 | 示例 |
|-----|---------|---------|---------|------|
| 姓名 | ✅ | 文本 | 1-50字符 | 张三 |
| 性别 | ✅ | 文本 | 男/女/未知 | 男 |
| 出生日期 | ✅ | 日期 | yyyy/M/d格式 | 1980/5/15 |
| 手机号 | ❌ | 文本 | 11位数字 | 13800138000 |
| 地址 | ❌ | 文本 | 最大200字符 | 北京市朝阳区XX路XX号 |

**模板特点**：
- 第一行为列标题
- 第2-4行为示例数据（可删除）
- 拼音码无需填写（系统自动生成）

#### 步骤2：填写Excel数据

1. 打开导出的模板文件
2. 从第2行开始填写数据（第1行是标题，不要修改）

**填写要求**：
- ✅ **姓名**必须填写，1-50字符
- ✅ **性别**必须填写，固定值：男/女/未知
- ✅ **出生日期**必须填写，格式：yyyy/M/d（如：1980/5/15）
- ✅ 手机号可选，11位数字（如：13800138000）
- ✅ 地址可选，最大200字符
- ❌ 不要填写拼音码列（系统会自动生成）

**常见错误**：
- ❌ 姓名为空或超过50字符
- ❌ 性别填写了"男/女/未知"以外的值
- ❌ 出生日期格式不正确（如：1980-05-15，应为1980/5/15）
- ❌ 出生日期晚于当前日期
- ❌ 出生日期早于150年前
- ❌ 手机号不是11位数字或格式不正确
- ❌ 地址超过200字符

**示例数据**：

| 姓名 | 性别 | 出生日期 | 手机号 | 地址 |
|------|-----|---------|--------|------|
| 张三 | 男 | 1980/5/15 | 13800138000 | 北京市朝阳区XX路XX号 |
| 李四 | 女 | 1985/8/20 | 13900139000 | 上海市浦东新区YY路YY号 |
| 王五 | 未知 | 1990/12/25 | 13700137000 | 广州市天河区ZZ路ZZ号 |

#### 步骤3：上传导入

1. 在患者列表页面，点击"📥 批量导入"按钮
2. 在弹出窗口中：
   - 点击"选择文件"按钮
   - 选择填写好的Excel文件（.xlsx格式，≤10MB）
3. 点击"开始导入"按钮
4. 系统显示导入进度

**导入过程**（Server主导模式）：
```
1. Desktop层：选择Excel文件 → 上传IFormFile
2. Desktop层：调用API POST /api/v1/patients/import
3. Server层：接收IFormFile → EPPlus解析Excel
4. Server层：逐行验证（FluentValidation） → 生成拼音码
5. Server层：手机号去重检查 → 数据库批量写入
6. Server层：返回BatchImportResultDto（成功/失败/跳过统计）
7. Desktop层：显示导入结果
```

**与Herbs Desktop主导模式的差异**：

| 对比项 | Patients（Server主导） | Herbs（Desktop主导） |
|-------|---------------------|-------------------|
| Excel解析位置 | Server端（EPPlus） | Desktop端 |
| 数据传输方式 | IFormFile上传 | DTO数组传输 |
| 重复策略 | 手机号去重（跳过） | 3种策略（Skip/Update/Error） |
| 适用场景 | 简单业务规则 | 复杂业务规则 |
| 性能 | 网络传输小，解析在Server | 网络传输大，解析在Desktop |

### 7.3 失败数据修复流程（6步流程）

如果导入过程中有失败记录，可按以下步骤修复：

**步骤1：识别失败记录**
- 在导入结果窗口，查看失败详情列表
- 记录失败的行号和原因

**示例**：
```
失败记录：
- 第12行：姓名不能为空
- 第35行：姓名超过50字符
- 第58行：出生日期格式不正确
```

**步骤2：导出失败清单**
- 点击"导出失败数据"按钮（如果系统提供）
- 或手动记录失败的行号和原因

**失败清单格式**：

| 原始行号 | 姓名 | 性别 | 出生日期 | 失败原因 | 修复建议 |
|---------|------|-----|---------|---------|---------|
| 12 | （空） | 男 | 1980/5/15 | 姓名不能为空 | 请填写姓名（1-50字符） |
| 35 | 张三丰李四王五赵六钱七孙八周九吴十郑十一王十二冯十三陈十四褚十五 | 男 | 1980/5/15 | 姓名超过50字符 | 请简化姓名，如："张三" |
| 58 | 李四 | 女 | 1980-05-15 | 出生日期格式不正确 | 请使用yyyy/M/d格式，如：1980/5/15 |

**步骤3：Excel修复数据**
- 打开原始Excel文件
- 根据失败行号定位到对应行
- 按"修复建议"修正数据

**修正示例**：
```
第12行：补充姓名 "张三"
第35行：简化姓名 "张三丰..." → "张三"
第58行：修正日期格式 "1980-05-15" → "1980/5/15"
```

**步骤4：重新导入**
- 保存修正后的Excel文件
- 重新执行导入操作（步骤3）
- 系统会跳过已成功导入的记录（基于手机号去重）

**注意事项**：
- ⚠️ 如果修正的记录有手机号，且该手机号已存在，会被跳过
- ⚠️ 建议只导入失败的记录（删除已成功的行），提高效率

**步骤5：验证成功**
- 查看新的导入结果
- 确认失败数为0
- 检查成功导入的记录数

**验证示例**：
```
✅ 导入完成！

总数：5条（修复后的记录）
成功：5条
跳过：0条
失败：0条
```

**步骤6：最终确认**
- 在患者列表中搜索验证
- 确认所有数据已正确导入
- 检查拼音码是否正确生成
- 检查年龄是否正确计算

**验证要点**：
- ✅ 姓名正确
- ✅ 性别正确
- ✅ 出生日期正确，年龄自动计算正确
- ✅ 拼音码自动生成正确
- ✅ 手机号和地址正确

### 7.4 最佳实践

**数据准备**：
- ✅ 导入前先备份现有数据
- ✅ 使用模板文件，不要自己创建Excel
- ✅ 姓名使用规范格式（1-50字符）
- ✅ 出生日期使用yyyy/M/d格式（如：1980/5/15）
- ✅ 手机号使用11位数字，无空格和符号
- ✅ 确保手机号唯一（重复手机号会被跳过）

**数据验证**：
- ✅ 导入前手动检查几行数据，确保格式正确
- ✅ 使用Excel的数据验证功能限制输入（如：性别限制为"男/女/未知"）
- ✅ 确保所有必填字段都已填写

**性能优化**：
- ✅ 单次导入不超过10000条（BR-004限制）
- ✅ 如果数据量超过10000条，分批导入
- ✅ 导入大批量数据（>5000条）时，建议在非业务高峰期进行
- ✅ 使用手机号去重，避免重复导入

**失败恢复**：
- ✅ 导入前记录现有患者总数，导入后对比确认
- ✅ 保留原始Excel文件，便于失败后重新导入
- ✅ 仅重新导入失败的记录，避免重复

## 8. 批量导出患者（Epic #1934核心功能）

### 8.1 功能概述

批量导出功能允许用户将患者数据导出为Excel文件，支持关键词筛选。

**技术模式**：
- **Server主导模式**（与Herbs的Desktop主导模式不同）
- Server端负责数据查询和Excel生成（使用EPPlus库）
- Desktop端仅发起请求和接收文件

**性能要求**：
- **BR-005**: 10000条记录 < 2秒

### 8.2 操作步骤

#### 步骤1：选择导出范围

1. 在患者列表页面，点击"📤 导出患者"按钮
2. 在弹出窗口中选择导出范围：
   - **全部患者**：导出所有有效患者（IsDeleted=false）
   - **按关键词筛选**：输入关键词（姓名/手机号/拼音码模糊匹配）

**筛选示例**：
- 关键词："张" → 导出所有姓张的患者
- 关键词："138" → 导出手机号包含138的患者
- 关键词："ZS" → 导出拼音码为ZS的患者

#### 步骤2：执行导出

1. 点击"开始导出"按钮
2. 系统调用API GET `/api/v1/patients/export?keyword=张`
3. Server端生成Excel文件
4. Desktop端接收文件并保存

**导出过程**（Server主导模式）：
```
1. Desktop层：点击导出 → 输入关键词（可选）
2. Desktop层：调用API GET /api/v1/patients/export
3. Server层：AsNoTracking()查询 → EPPlus生成Excel
4. Server层：返回FileContentResult（.xlsx文件）
5. Desktop层：接收文件 → 显示保存对话框
6. Desktop层：保存文件到本地
```

**与Herbs Desktop主导模式的差异**：

| 对比项 | Patients（Server主导） | Herbs（Desktop主导） |
|-------|---------------------|-------------------|
| Excel生成位置 | Server端（EPPlus） | Desktop端 |
| 数据传输方式 | File下载 | JSON→Excel |
| 适用场景 | 数据量大，统一生成 | 需要Desktop端格式化 |
| 性能 | Server端统一生成，高效 | Desktop端生成，灵活 |

#### 步骤3：保存文件

1. 系统弹出文件保存对话框
2. 选择保存位置
3. 默认文件名：
   - 全部导出：`患者数据_日期时间.xlsx`
   - 关键词筛选：`患者数据_关键词_日期时间.xlsx`

**文件名示例**：
- `患者数据_20251110_143000.xlsx`（全部）
- `患者数据_张三_20251110_143000.xlsx`（关键词：张三）

## 9. 常见问题

### Q1: 拼音码显示为空或不正确？

**可能原因**：
1. 姓名中包含非汉字字符（英文、数字、符号）
2. 后端未正确生成拼音码

**解决方法**：
1. 确保使用正确的工具类：`LYBT.Shared.Utilities.Text.PinYinHelper`
2. 检查姓名是否为纯中文
3. 查看后端日志确认生成逻辑是否执行

### Q2: 年龄显示不正确或为空？

**可能原因**：
1. 出生日期未填写
2. 后端未正确复制Age属性到DTO

**解决方法**：
1. 确保已选择出生日期
2. 检查`PatientService`中的Age复制逻辑（4个方法：GetPagedAsync, GetByIdAsync, CreateAsync, UpdateAsync）
3. 查看后端日志确认Age计算是否正确

### Q3: 提交时显示验证错误？

**可能原因**：
1. 必填字段未填写（姓名、身份证号）
2. 字段长度超过限制

**解决方法**：
1. 检查所有必填字段是否已填写
2. 检查字段长度是否符合要求
3. 查看错误提示信息，按提示修改

### Q4: 编辑时拼音码未更新？

**可能原因**：
1. 姓名未实际发生变化
2. 后端更新逻辑未正确检测姓名变化

**解决方法**：
1. 确认姓名确实发生了变化
2. 检查`PatientService.UpdateAsync`中的姓名变化检测逻辑（`existingPatient.Name != input.Name`）
