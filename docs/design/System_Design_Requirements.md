# 凌隐宝堂中医诊所系统设计需求文档

## 一、系统概述

### 1.1 项目定位
- **系统类型**：小型中医诊所管理系统
- **目标用户**：个体或小型中医诊所
- **核心价值**：简化诊疗流程，提高工作效率

### 1.2 设计原则
- **简洁优先**：避免过度设计，功能实用即可
- **流程清晰**：符合中医诊疗习惯
- **操作便捷**：减少不必要的步骤
- **数据安全**：保护患者隐私和诊疗数据

## 二、业务流程设计

### 2.1 核心诊疗流程（简化版）

```
患者选择 → 四诊采集 → 辨证分析 → 处方开具
    ↓           ↓           ↓           ↓
[患者库]    [文本记录]   [诊断结论]   [处方单]
```

### 2.2 流程特点
- **无需挂号**：小诊所不需要复杂的挂号排队系统
- **直接选择**：医生从患者库直接选择患者开始诊疗
- **快速录入**：四诊信息采用纯文本框录入
- **灵活开方**：支持单味药和验方组合

## 三、功能模块设计

### 3.1 患者管理
- **基础信息**：姓名、性别、年龄、联系方式
- **过敏史**：药物过敏记录
- **就诊记录**：历史诊疗记录查看
- **快速检索**：拼音首字母、电话号码搜索

### 3.2 诊疗管理

#### 四诊信息采集
- **望诊**：纯文本描述（面色、舌象等）
- **闻诊**：纯文本描述（声音、气味等）
- **问诊**：纯文本描述（主诉、症状等）
- **切诊**：纯文本描述（脉象、按诊等）

#### 辨证论治
- **证型判断**：文本输入
- **治法方针**：文本输入
- **医嘱建议**：文本输入

### 3.3 处方管理

#### 处方开具
- **单味药模式**：逐个添加药材和剂量
- **验方模式**：选择验方模板快速生成
- **组合模式**：多个验方组合，自动处理重复药材
- **价格计算**：自动计算单付和总价

#### 剂量处理规则
- 相同药材取最小剂量（安全原则）
- 提供手动调整功能
- 超剂量警告提示

### 3.4 验方管理
[详见 Formula_Management_Design.md]

### 3.5 药材管理（管理员功能）
- **基础信息**：药材名称、规格、单位
- **价格设置**：进价、售价管理
- **库存管理**：仅记录可用药材，不做复杂库存
- **分类管理**：按功效分类

- **视觉风格**：原生WPF，简洁专业
- **色彩方案**：以蓝灰色系为主
- **字体大小**：考虑中老年用户，适当加大

### 5.3 交互设计

#### 快捷操作
- **Tab切换**：四诊各项之间
- **回车确认**：快速保存并下一步
- **ESC取消**：退出当前操作
- **F1-F4**：切换四诊标签

#### 历史数据利用
- 每个录入点都可查看历史
- 支持一键导入历史数据
- 支持模板保存和使用

## 六、数据设计原则

### 6.1 数据完整性
- 软删除机制（标记删除）
- 完整的审计日志
- 数据变更追踪

### 6.2 数据关联
```
Patient (患者)
    ↓
MedicalCase (医疗案例)
    ↓
├── Consultation (诊疗记录)
│     ├── FourDiagnosis (四诊)
│     └── Diagnosis (诊断)
└── Prescription (处方)
      ├── PrescriptionHerb (处方药材)
      └── Formula (引用验方)
```

### 6.3 历史数据管理
- 所有诊疗数据永久保存
- 支持按时间范围查询
- 支持导出和备份

## 七、性能要求

### 7.1 响应时间
- 页面加载 < 2秒
- 查询操作 < 1秒
- 保存操作 < 2秒

### 7.2 并发支持
- 支持5-10个并发用户
- 数据锁定机制防冲突

### 7.3 数据容量
- 支持10万+患者记录
- 支持100万+诊疗记录

## 八、特殊考虑

### 8.1 中医特色
- 支持中医术语输入
- 保留传统度量单位（钱、两）
- 支持特殊炮制方法记录

### 8.2 实用性优先
- 不做AI诊断（初期）
- 不做复杂统计分析
- 不做在线预约功能

### 8.3 扩展性预留
- 接口设计考虑未来扩展
- 数据结构预留扩展字段
- 模块化设计便于升级
