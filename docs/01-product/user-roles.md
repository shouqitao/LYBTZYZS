# 用户角色与权限定义

## 概述

本文档定义系统中的用户角色及其在各业务模块中的操作权限。权限通过 ASP.NET Core 授权策略 (Policy) 和资源级检查实现。

---

## 角色定义

| 角色 | 英文 | 枚举值 | 说明 |
|------|------|--------|------|
| 超级管理员 | SuperAdmin | 100 | 最高权限，系统初始化和诊断专用 |
| 管理员 | Admin | 10 | 系统管理、用户管理、全局数据查看与编辑 |
| 医生 | Doctor | 1 | 日常诊疗、开方、患者管理 |
| 前台接待 | Receptionist | 0 | v1.0 仅查看权限。不在 DoctorOrAdmin/AdminOnly 策略中，无任何写操作权限 |

---

## 授权策略

| 策略名 | 允许角色 | 应用范围 |
|--------|----------|----------|
| `AdminOnly` | SuperAdmin, Admin | 用户管理模块 |
| `DoctorOrAdmin` | SuperAdmin, Admin, Doctor | 大部分业务模块 |

## 资源级权限规则

### 医案管理 (核心)

| 操作 | Admin | Doctor | 规则说明 |
|------|-------|--------|----------|
| 创建医案 | 禁止 | 允许 | 仅 Doctor 可创建，`[Authorize(Roles = "Doctor")]` |
| 查看医案列表 | 全部医案 | 仅自己的医案 | 按 UserId 过滤 |
| 编辑医案 | 全部，无时间限制 | 仅自己的 + 当天未完成 | 详见锁定规则 |
| 完成医案 | 全部 | 仅自己的 | 状态变更为 Completed |
| 取消医案 | 全部 | 仅自己的 | 状态变更为 Cancelled |

#### 医案锁定规则

```
锁定条件: IsLocked = IsCompleted && (CompletedAt.Date != Today)
```

| 场景 | Doctor | Admin |
|------|--------|-------|
| 当天自己的未完成医案 | 可编辑 | 可编辑 |
| 当天自己的已完成医案 | 可编辑 (当天内) | 可编辑 |
| 隔天自己的已完成医案 | 不可编辑 (已锁定) | 可编辑 (需填写修改原因) |
| 他人的医案 | 不可查看/编辑 | 可查看/编辑 (需填写修改原因) |

#### 审计要求

| 场景 | 是否需要审计理由 |
|------|-----------------|
| 当天、本人创建的医案 | 不需要 |
| 隔天修改 | 需要 |
| 非本人修改 | 需要 |
| 已完成医案修改 | 需要 |
| 取消医案 (需确认) | 可能需要 |

## 工作区模式

Desktop 客户端根据角色提供不同的工作区入口:

| 工作区 | 角色 | 功能范围 |
|--------|------|----------|
| Clinical (临床工作区) | Doctor | 患者选择 → 创建医案 → 诊断 → 开方 → 完成 |
| Management (管理工作区) | Admin | 医案列表 → 查看/编辑医案 → 审计日志 |

### 工作区行为差异

| 行为 | Clinical | Management |
|------|----------|------------|
| 编辑状态 | 默认 Editing | 默认 ReadOnly，需切换到 Editing |
| 返回导航 | 返回患者选择页 | 返回医案列表页 |
| 保存后状态 | 切换到 ReadOnly，留在当前界面 | 切换到 ReadOnly，留在当前界面 |
| 未保存修改处理 | 自动暂存 | 弹窗确认 (保存/放弃/取消) |
