# 用户画像 (Personas)

> 版本: v2.0 | 日期: 2026-06-15 | 状态: 重建

本文件定义凌隐宝堂中医诊所管理系统的四个核心角色画像。角色权限基于 `PermissionLevel` 枚举值（0/1/10/100），详细权限矩阵见 [`02-requirements/01-prd.md`](../02-requirements/01-prd.md)。

---

## 主要角色：李医生 (Doctor)

> **PermissionLevel = 1** | 授权策略：`DoctorOrAdmin` | 日均使用 6-8 小时

### 背景

52 岁，中医内科主治医师，从业 25 年。在凌隐宝堂坐诊，日均接诊 20 名患者（其中复诊约 40%）。能用 Windows 基本操作，习惯拼音输入法，偏好键盘快捷操作，讨厌频繁点击。Excel 仅用于查看。

### 日常工作流

- 08:00 到诊所，登录系统查看今日待诊列表
- 08:30-12:00 上午门诊（约 12 名患者）：接诊 → 望闻问切 → 辨证论治 → 开方 → 打印处方
- 12:00-14:00 午休，偶尔整理验方、回顾疑难病例
- 14:00-17:30 下午门诊（约 8 名患者）
- 17:30 下班前检查未完成的挂起医案，确认全部处方已打印

### 目标

1. 复诊时 10 秒内调出患者上次诊断和处方，延续治疗方案
2. 常用经验方一键导入处方，不用每次重新输入 8-15 味药
3. 处方费用自动计算准确无误，消除手工算错的尴尬

### 痛点

1. 纸质病历堆积如山，找一个复诊患者的历史记录要翻 5-10 分钟
2. 手写处方字迹潦草，药房配药时经常打电话来确认药名和剂量
3. 外出看诊时断网，回来后手工抄写诊疗记录到系统，费时且容易遗漏

### 成功标准

> "能让我把看病的时间还给病人，而不是花在找资料和算账上。"

### 权限范围

创建医案、中医诊断、开具处方、验方管理（仅自己的）、查看药材、处方打印。仅可见本人创建的医案，已完成医案次日锁定编辑。完整规则见 [`02-requirements/07-medical-cases.md`](../02-requirements/07-medical-cases.md)。

## 管理角色：王主任 (Admin)

> **PermissionLevel = 10** | 授权策略：`AdminOnly` + `DoctorOrAdmin` | 日均使用 1-2 小时

### 背景

45 岁，诊所负责人兼行政管理员。中医科班出身但主要负责运营管理，偶尔坐诊。会用 Excel 做简单表格和数据整理，对系统管理有基本概念。不会写 SQL 或查看日志文件。

### 日常工作流

- 08:00 检查系统运行状态，处理前一天的异常情况
- 09:00-10:00 药材价格更新（每月 1-2 次大批量，日常零星调价）
- 10:00-11:00 审核医案：检查处方金额是否异常、诊断信息是否完整
- 不定时：用户账号管理（新人入职创建账号、离职人员禁用账号，年均 2-3 次）
- 不定时：处理医案修改申请、数据导入导出需求

### 目标

1. 药材库价格批量更新不影响历史处方金额（价格快照机制）
2. 一眼看出哪些医案有异常需要审核（状态筛选）
3. 人员流动时 5 分钟内完成账号创建或禁用，权限立即生效

### 痛点

1. 药材涨价后不知道会不会影响已开的处方金额，改价时心里没底
2. 新诊所初始化要录入 400+ 种药材，逐条录入需要好几天
3. 离职员工账号忘记禁用，发现时已过去两周，期间可能有未授权访问

### 成功标准

> "我最怕的就是数据乱了理不清。"

### 权限范围

用户管理（CRUD）、全局医案查看与编辑（含锁定医案，需填修改原因）、药材验方管理、数据同步。**不可创建医案**（仅 Doctor 可创建）。完整规则见 [`02-requirements/03-users.md`](../02-requirements/03-users.md)。

## 前台角色：小张 (Receptionist)

> **PermissionLevel = 0** | 授权策略：`PatientAccess` | 日均使用 4-6 小时

### 背景

26 岁，前台接待，入职半年。负责患者登记、身份证读卡和分诊引导。对中医术语了解有限，但电脑操作熟练。打字速度快（每分钟 60+ 字），习惯快捷键，能使用读卡器等外设。

### 日常工作流

- 08:00 开机，准备身份证读卡器，确认打印机就绪
- 08:30-12:00 高峰期接待（每 5-10 分钟一位患者）：询问是否来过 → 搜索/登记 → 分诊
- 12:00-14:00 午休，补录上午来不及完善的患者信息
- 14:00-17:00 下午相对轻松，处理零星来访
- 间歇：接听电话咨询、整理患者档案

### 目标

1. 刷身份证 3 秒完成登记，高峰期不让患者等
2. 老患者一搜就出来，不用问"你上次来过吗"然后找不到记录
3. 知道哪位医生在看几号患者，能给等候患者准确的时间预估

### 痛点

1. 高峰期手工填写登记表，排队的患者催得紧，压力大
2. 患者说"来过"但搜不到登记记录，要重新从头填写，浪费时间又尴尬
3. 不确定医生的接诊进度，被患者追问"还要等多久"时只能含糊回答

### 成功标准

> "前台最怕排长队，系统快一秒我就少被催一句。"

### 权限范围

患者管理（CRU，不含删除）、挂号创建与取消、身份证读卡。**不可访问**药材、验方、医案、用户管理等模块。完整规则见 [`02-requirements/04-patients.md`](../02-requirements/04-patients.md)。

## 系统角色：超级管理员 (SuperAdmin)

> **PermissionLevel = 100** | 授权策略：`SuperAdminOnly`（诊断/配置专用） | 使用频率极低（月均 1-2 次）

### 背景

技术运维角色，非业务用户。仅在系统部署、升级或故障排查时使用。熟悉 .NET / SQL Server / Windows 系统管理。

### 典型场景

- **系统首次部署**：创建初始 Admin 账号，验证数据库迁移
- **系统升级**：执行数据库迁移后验证，检查健康端点
- **紧急故障**：访问诊断工具（`/details`、`DiagnosticsController`）排查问题
- **配置管理**：查询/验证系统配置、调整日志级别、启用调试模式

### 目标

1. 快速诊断系统健康状态（数据库连接、磁盘、内存）
2. 无需重启即可动态调整日志级别（≤120 分钟调试窗口）
3. 系统初始化时安全创建首个 Admin 账号

### 成功标准

> "出了问题能快速定位，不需要重启服务就能调日志。"

### 权限范围

全部权限。独占访问：系统配置查询（`ConfigurationController`）、运行时诊断（`DiagnosticsController`）、用户密码重置、软删除用户恢复、日志级别控制。SuperAdmin 凭证统一存储于 Users 表（`Role=100`）。完整规则见 [`02-requirements/11-platform.md`](../02-requirements/11-platform.md)。

## 角色与模块映射

| Persona | 核心使用模块 | 授权策略 | 日均时长 |
|---------|------------|---------|---------|
| 李医生 (Doctor) | 医案、患者、验方、药材（查看）、打印 | `DoctorOrAdmin` | 6-8 小时 |
| 王主任 (Admin) | 药材、用户管理、医案（审核）、同步 | `AdminOnly` + `DoctorOrAdmin` | 1-2 小时 |
| 小张 (Receptionist) | 患者（登记/搜索）、挂号、读卡器 | `PatientAccess` | 4-6 小时 |
| SuperAdmin | 系统健康、配置、诊断、用户管理 | `SuperAdminOnly` | 极低 |

> 完整权限矩阵见 [`02-requirements/01-prd.md`](../02-requirements/01-prd.md)。
