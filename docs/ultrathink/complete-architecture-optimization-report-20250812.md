## 1. 整体架构转型

### 从传统三层架构到DDD+CQRS架构

#### 原架构问题
```
传统三层架构：
Controller → Service → Repository → Database

问题：
- 贫血模型，业务逻辑分散
- 服务层臃肿，职责不清
- 缺少业务边界
- 难以应对复杂业务
```

#### 新架构设计
```
DDD+CQRS架构：
┌─────────────────────────────────────────┐
│          Presentation Layer             │
│     (Controllers / GraphQL / gRPC)      │
├─────────────────────────────────────────┤
│          Application Layer              │
│   (Commands / Queries / DTOs / Events)  │
├─────────────────────────────────────────┤
│           Domain Layer                  │
│  (Aggregates / Entities / Services)     │
├─────────────────────────────────────────┤
│        Infrastructure Layer             │
│   (Repositories / DbContext / Cache)    │
└─────────────────────────────────────────┘
```

### 2.3 业务规则封装

#### 示例：患者聚合业务规则
```csharp
public class Patient : AggregateRoot
{
    public void AddVisitRecord(...)
    {
        // 业务规则1：就诊日期不能是未来
        if (visitDate > DateTime.Now)
            throw new PatientDomainException("就诊日期不能是未来时间");
        
        // 业务规则2：只有活跃患者可以添加就诊记录
        if (_status != PatientStatus.Active)
            throw new PatientDomainException($"患者状态为{_status}，不能添加就诊记录");
        
        // 业务逻辑执行
        _visitRecords.Add(visitRecord);
        
        // 发布领域事件
        AddDomainEvent(new VisitRecordAddedDomainEvent(Id, visitRecord));
    }
}
```
