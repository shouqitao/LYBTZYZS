# 前端对话框重构方案

## 背景

当前系统中存在大量直接创建对话框实例和使用 MessageBox.Show 的代码（约 409 处），这违反了依赖注入原则，使得代码难以测试和维护。

## 重构目标

1. 使用 Prism 的 IDialogService 实现对话框的依赖注入
2. 消除直接创建对话框实例的代码
3. 统一对话框的调用方式
4. 提高代码的可测试性

## 现状分析

### 当前对话框使用方式

1. **直接创建对话框实例**
```csharp
var dialog = new Views.AddFormulaTemplateDialog(herbService, formulaService);
dialog.Owner = Application.Current.MainWindow;
if (dialog.ShowDialog() == true)
{
    RefreshCommand.Execute();
}
```

2. **使用 MessageBox.Show**
```csharp
MessageBox.Show($"错误信息: {ex.Message}", "错误", 
    MessageBoxButton.OK, MessageBoxImage.Error);
```

3. **已使用 IDialogService 的模块**（良好示例）
- PharmacyManagementViewModel
- PaymentManagementViewModel

## 重构方案

### 1. 创建统一的对话框服务接口

```csharp
public interface ICommonDialogService
{
    // 消息对话框
    Task<bool> ShowConfirmationAsync(string message, string title = "确认");
    Task ShowInformationAsync(string message, string title = "信息");
    Task ShowWarningAsync(string message, string title = "警告");
    Task ShowErrorAsync(string message, string title = "错误");
    
    // 输入对话框
    Task<string> ShowInputAsync(string message, string title = "输入", string defaultValue = "");
    
    // 文件对话框
    Task<string> ShowOpenFileDialogAsync(string filter = "All Files (*.*)|*.*", string title = "打开文件");
    Task<string> ShowSaveFileDialogAsync(string filter = "All Files (*.*)|*.*", string title = "保存文件");
}
```

### 2. 注册对话框到 Prism 容器

每个对话框需要：
1. 实现 IDialogAware 接口
2. 在模块中注册

```csharp
public class SystemManagementModule : IModule
{
    public void RegisterTypes(IContainerRegistry containerRegistry)
    {
        // 注册对话框
        containerRegistry.RegisterDialog<AddFormulaTemplateDialog, AddFormulaTemplateDialogViewModel>();
        containerRegistry.RegisterDialog<EditFormulaTemplateDialog, EditFormulaTemplateDialogViewModel>();
        // ... 其他对话框
    }
}
```

### 3. 重构 ViewModel 使用 IDialogService

```csharp
public class FormulaTemplateManagementViewModelRefactored : BaseManagementViewModel<FormulaTemplateInfo>
{
    private readonly IDialogService _dialogService;
    private readonly ICommonDialogService _commonDialogService;
    
    public FormulaTemplateManagementViewModelRefactored(
        IDialogService dialogService,
        ICommonDialogService commonDialogService,
        IFormulaTemplateApiService service) : base(service)
    {
        _dialogService = dialogService;
        _commonDialogService = commonDialogService;
    }
    
    private void AddNew()
    {
        _dialogService.ShowDialog("AddFormulaTemplateDialog", result =>
        {
            if (result.Result == ButtonResult.OK)
            {
                RefreshCommand.Execute();
            }
        });
    }
    
    private async void ShowError(string message)
    {
        await _commonDialogService.ShowErrorAsync(message);
    }
}
```

### 4. 对话框实现 IDialogAware

```csharp
public partial class AddFormulaTemplateDialog : UserControl, IDialogAware
{
    public string Title => "新增验方模板";
    
    public event Action<IDialogResult> RequestClose;
    
    public bool CanCloseDialog() => true;
    
    public void OnDialogClosed() { }
    
    public void OnDialogOpened(IDialogParameters parameters)
    {
        // 初始化逻辑
    }
}
```

## 重构优先级

基于使用频率和复杂度，建议按以下顺序重构：

1. **高优先级**（频繁使用的模块）
   - FormulaTemplateManagement（19处）
   - HerbManagement（16处）
   - RegistrationManagement（18处）
   - PatientManagement（7处）

2. **中优先级**（一般使用的模块）
   - UserManagement（8处）
   - DoctorManagement（10处）
   - PrescriptionManagement（23处）

3. **低优先级**（较少使用的模块）
   - 系统设置相关
   - 备份还原
   - 其他辅助功能

## 注意事项

1. **保持向后兼容**：在完全重构前，保持旧代码可用
2. **逐步迁移**：一次重构一个模块，确保稳定性
3. **充分测试**：每个模块重构后进行完整测试
4. **文档更新**：及时更新相关文档和示例代码

## 预期收益

1. **提高可测试性**：可以模拟对话框进行单元测试
2. **统一用户体验**：所有对话框风格一致
3. **简化维护**：集中管理对话框逻辑
4. **支持主题切换**：便于实现暗色主题等功能
