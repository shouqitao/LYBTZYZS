# 开发检查清单

在提交代码前，请确保完成以下检查项：

## 代码质量检查

### 基础检查
- [ ] 代码可以成功编译，没有错误和警告
- [ ] 所有单元测试通过
- [ ] 代码符合项目编码规范
- [ ] 没有硬编码的配置信息（如连接字符串、密码等）
- [ ] 删除了所有调试代码和console.log语句
- [ ] 代码注释清晰且有意义

### 命名规范
- [ ] 类名使用PascalCase
- [ ] 方法名使用PascalCase（C#）或camelCase（TypeScript）
- [ ] 变量名使用camelCase
- [ ] 常量使用UPPER_CASE
- [ ] 文件名与主要类名一致

### 代码结构
- [ ] 遵循单一职责原则
- [ ] 没有重复代码
- [ ] 方法长度合理（建议不超过50行）
- [ ] 类的大小合理（建议不超过500行）
- [ ] 适当使用设计模式

## 功能检查

### 业务逻辑
- [ ] 功能符合需求文档描述
- [ ] 边界条件已处理
- [ ] 异常情况已处理
- [ ] 输入验证完整
- [ ] 业务规则正确实现

### 数据处理
- [ ] 数据库操作使用事务
- [ ] SQL查询已优化
- [ ] 避免N+1查询问题
- [ ] 敏感数据已加密
- [ ] 数据验证在前后端都有实现

## 安全检查

- [ ] 没有SQL注入风险
- [ ] 没有XSS攻击风险
- [ ] API需要适当的身份验证
- [ ] 敏感操作有权限控制
- [ ] 日志中不包含敏感信息
- [ ] 使用参数化查询

## 性能检查

- [ ] 避免在循环中进行数据库查询
- [ ] 合理使用缓存
- [ ] 大数据量操作使用分页
- [ ] 异步操作正确使用async/await
- [ ] 资源正确释放（using语句）

## 测试检查

- [ ] 新功能有对应的单元测试
- [ ] 测试覆盖率达到要求（建议>80%）
- [ ] 边界条件有测试用例
- [ ] 异常情况有测试用例
- [ ] 测试数据不依赖外部环境

## 文档检查

- [ ] API有完整的注释文档
- [ ] 复杂逻辑有说明文档
- [ ] README已更新（如有需要）
- [ ] 更改日志已更新
- [ ] 部署文档已更新（如有需要）

## Git提交检查

- [ ] 提交信息符合规范
- [ ] 一个提交只包含一个功能
- [ ] 没有提交生成的文件
- [ ] 没有提交敏感信息
- [ ] 分支名称符合规范

## 前端特定检查

- [ ] 界面在不同分辨率下正常显示
- [ ] 支持的浏览器都已测试
- [ ] 没有控制台错误
- [ ] 加载性能可接受
- [ ] 用户体验流畅

## 后端特定检查

- [ ] API响应格式统一
- [ ] 错误信息对用户友好
- [ ] 日志记录完整
- [ ] 数据库迁移脚本已创建
- [ ] API版本控制正确

## 最终确认

- [ ] 代码已自测通过
- [ ] 相关人员已知会
- [ ] PR描述清晰完整
- [ ] 没有遗留的TODO项

---

提示：可以将此清单复制到PR描述中，逐项检查并标记完成。
