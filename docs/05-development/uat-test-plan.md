# v1.0 用户验收测试 (UAT) 计划

> **版本**: v1.0
> **创建日期**: 2026-03-09
> **目的**: 定义 v1.0-rc Exit Criteria 中 UAT 的测试范围、场景和验收标准
> **依据**: user-story-map.md (4 Narrative) + clinical-workflow.md (端到端流程) + nfr.md (性能指标)

---

## 1. 测试范围

### 1.1 覆盖范围

- Narrative 0: 系统引导 (Bootstrap) -- 从零开始的完整部署流程
- 4 个核心 Narrative 端到端流程验证
- 15 个功能模块交叉验证
- 异常路径和业务规则 (BR) 验证
- 跨 Narrative 系统级验证 (安全/备份/脱敏)
- Desktop 客户端性能感知验证

### 1.2 不在范围

- API 级性能基准测试 (见 performance-baseline.md)
- 自动化回归测试 (已有 2021 tests 覆盖)
- v2.0 功能 (MedicalCase 同步/自动同步提示/User 同步/字段加密)

---

## 2. 测试环境

### 2.1 硬件要求

| 项目 | 规格 | 说明 |
|------|------|------|
| PC | Windows 10, 8GB RAM, SSD | 代表性诊所 PC |
| 打印机 | A5/A4 支持 | 处方打印验证 |
| 读卡器 | 华大 HD100 | 身份证读取验证 (可选) |

### 2.2 软件环境

| 项目 | 配置 |
|------|------|
| 编译模式 | Release |
| 远程数据库 | SQL Server (非 LocalDB) |
| 本地数据库 | SQL Server LocalDB |
| .NET Runtime | .NET 8 Desktop Runtime |

### 2.3 测试数据

**模式 A: 首次 UAT (从零开始)**

从 Narrative 0 开始，全新空数据库。Server 自动创建 sysadmin，其余数据在 Narrative 0 中手工创建:
- 用户: 在 Phase B 创建 (Admin + Doctor + Receptionist)
- 药材: 在 Phase C 创建 (手动 2 个 + Excel 导入 50-100 个)
- 验方: 在 Phase D 创建 (1-2 个)
- 患者/医案: 在 Narrative 1 中首次创建

**模式 B: 回归测试 (预置数据)**

跳过 Narrative 0，使用预置数据直接进入 Narrative 1~4:

| 实体 | 预置数量 | 说明 |
|------|---------|------|
| 用户 | 4 (SuperAdmin + Admin + Doctor + Receptionist) | 覆盖四种角色 |
| 患者 | 300+ | 含不同年龄/性别分布 |
| 药材 | 100+ | 含已禁用药材 |
| 验方 | 20+ | 含个人/共享/已验证/待验证 |
| 医案 | 50+ | 含不同状态 (Active/Completed/Cancelled) |

## 6. 缺陷分级与处理

| 级别 | 定义 | 处理方式 |
|------|------|---------|
| P0 - 阻塞 | 核心流程无法完成 (如聚合保存失败) | 立即修复，重新测试 |
| P1 - 严重 | 功能缺失或数据错误 (如费用计算错误) | 本轮修复 |
| P2 - 一般 | UI 显示问题或次要功能异常 | 记录，评估修复优先级 |
| P3 - 建议 | 体验优化建议 | 记录到 v2.0 backlog |

## 7. 验收标准

### 7.1 UAT 通过标准

- [ ] Narrative 0 (Bootstrap) 全部 Pass (首次 UAT 必测)
- [ ] 4 个 Narrative 正常路径全部 Pass
- [ ] 异常路径 (1.E1~E4, 2.E1~E2) 全部 Pass
- [ ] 跨 Narrative 验证 (X.1~X.8) 全部 Pass
- [ ] 无 P0/P1 级别缺陷
- [ ] Desktop 性能指标全部达标 (或偏差在合理范围内)

### 7.2 UAT 完成后更新

- [ ] 更新 roadmap.md v1.0-rc Exit Criteria: UAT 勾选
- [ ] 更新 nfr.md 性能指标: 填入实测值
- [ ] 记录发现的 P2/P3 缺陷到 v2.0 backlog
- [ ] 性能实测值与 nfr.md 目标偏差大时，评估是否调整目标或优化代码
