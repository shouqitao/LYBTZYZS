# Sysadmin 功能闭环分析（对标业界基准）

> **方法**：以 on-premise 桌面应用/医疗诊所管理系统的业界 admin 基准为参照，逐项对比我们的 sysadmin 功能，识别缺口。
> **基准来源**：Velopack 官方集成文档（确认）+ 业界 on-premise admin 通用能力（ITIL/医疗信息化标准/桌面应用管理惯例）+ 本项目 NFR/PRD。
> **目的**：验证 sysadmin 角色是否"闭环"——能否让 sysadmin 独立完成系统全生命周期管理。

---

## [S1] Sysadmin 完整性基准框架（业界标准 9 大领域）

任何 on-premise 系统的 sysadmin 都应覆盖**安装→配置→监控→维护→安全→备份→升级→恢复→退役**全生命周期。以下是每领域的业界标准能力 vs 我们的状态：

| # | 领域 | 业界标准能力 | 我们的状态 | 差距 |
|---|------|-------------|-----------|------|
| 1 | **安装部署** | 一键安装包 + 首次配置向导 | 📋 已设计（Velopack + 5 步向导） | 无差距（待实现） |
| 2 | **身份与权限** | 创建用户 + 重置密码 + 会话管理 + 账户锁定查看 | ⚠️ 部分 | **缺会话管理、缺锁定详情查看** |
| 3 | **配置管理** | 运行时配置（免重启）+ 配置备份/还原 | ⚠️ 部分 | **缺配置导出/导入、改配置需重启** |
| 4 | **监控诊断** | 系统健康 + 日志级别 + **资源监控**（CPU/内存/磁盘/DB大小） | ⚠️ 健康/日志有，资源监控无 | **缺系统资源监控面板** |
| 5 | **数据维护** | 一键备份 + **一键恢复** + 备份状态 + DB大小监控 | ⚠️ 仅备份（LocalDB），无恢复 | **缺恢复 UI、缺备份状态查看** |
| 6 | **安全合规** | 审计日志 + 访问追踪 + **加密状态** | 🔴 大面积缺失 | **缺审计日志、访问追踪、加密管理** |
| 7 | **更新管理** | 检查 + 安装 + **回滚** + 升级说明 | 📋 自动更新已设计 | **缺回滚机制、缺升级说明管理** |
| 8 | **灾难恢复** | 备份恢复 + 回滚 + 降级 | ⚠️ 部分 | **缺恢复能力、缺更新回滚** |
| 9 | **退役清理** | 数据导出 + 系统重置 + 完全卸载 | ❌ 无 | **缺系统重置/数据全量导出** |

**初步结论**：9 个领域中 1 个完全闭环（部署）、4 个部分闭环、4 个有显著缺口。**sysadmin 角色尚未闭环**。

## [S2] 逐领域深度对比

### 领域 2：身份与权限管理

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| 创建/编辑/禁用/删除用户 | ✅ Admin 能做（Users US-001~012） | ✅ |
| 重置用户密码（sysadmin） | 📋 已设计（UI 自助） | 闭环 |
| 账户锁定策略配置 | ⚠️ 硬编码在 SecurityOptions，无 UI | 可改文件，不优雅 |
| **查看活跃会话数** | ❌ | 业界标配（防止未授权共享账号） |
| **强制登出某用户** | ❌ | 业界标配（安全事件响应） |
| **密码策略修改**（长度/复杂度/有效期） | ❌ | 硬编码在 Program.cs |

**缺口**：会话管理 + 密码策略可配置性。**严重度：中低**（小诊所账号少，共享风险小）。

### 领域 3：配置管理

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| 查看当前配置 | ✅ US-CFG-001/002 | ✅ |
| ClinicSettings 诊所信息 | 📋 向导写入 + 后续 UI | 闭环 |
| FeatureToggle 功能开关 | ✅ appsettings.json | 能改但需重启 |
| **配置备份/导出** | ❌ | 业界标配（迁移/备份配置） |
| **配置导入/还原** | ❌ | 重装后能快速恢复 |
| **运行时热更新配置** | ❌ | 改配置需重启 Desktop |

**缺口**：配置导出/导入。**严重度：低**（配置文件简单，手动复制不难，但体验差）。

### 领域 4：监控诊断

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| 系统存活检查 | ✅ /health, /ping | ✅ |
| DB 连接状态 | ✅ /details | ✅ |
| 日志级别管理 | ✅ 调试模式 + 级别设置 | ✅ |
| **CPU/内存/磁盘使用** | ❌ | 业界标配（性能异常预警） |
| **数据库大小监控** | ❌ | NFR-DATA-001 提到数据量预估，但无运行时监控 |
| **API 响应时间监控** | ⚠️ StartupPerformanceMonitor 仅启动阶段 | 缺运行时 |
| **连接池状态** | ❌ | NFR 提到 MaxConnections=20，但无法运行时查看 |

**缺口**：系统资源监控。**严重度：中**（小诊所性能问题少，但出问题时无数据）。

### 领域 5：数据维护

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| LocalDB 自动备份 | ✅ 7 天保留 | ✅ |
| **一键恢复（LocalDB）** | ❌ | **关键缺口**——崩溃后无法恢复 |
| **备份状态查看** | ❌ | 不知道"上次备份什么时候" |
| **备份手动触发** | ❌ | 只在登录时自动 |
| 远程 SQL Server 备份 | ⚠️ 依赖 SQL Agent | 无应用层控制 |
| **数据库大小/行数** | ❌ | 无法查看 |

**缺口**：恢复能力 + 备份状态。**严重度：高**——数据丢失时 sysadmin 无法自助恢复。

### 领域 6：安全合规

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| **安全审计日志**（登录/登出/失败/权限变更） | 🔴 未实现（D1 决策待定） | **关键缺口**——合规核心 |
| **谁查了哪个患者** | ❌ | v1.0 可简化 |
| **密码修改历史** | ❌ | 无法追溯密码何时被改 |
| **字段级加密状态** | 🔴 待实现（v1.0 已决定加入） | 需要查看加密状态的入口 |
| 账户锁定/解锁 | ⚠️ 自动锁定有，解锁无 UI | 需手动 DB 操作 |

**缺口**：审计日志 + 加密状态查看。**严重度：高**——医疗合规必需。

### 领域 7：更新管理

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| 检查新版本 | 📋 Velopack | 闭环 |
| 下载安装 | 📋 Velopack | 闭环 |
| **回滚到上一版本** | ❌ Velopack 无内置回滚 | 业界期望有 |
| **版本更新说明** | ❌ 无 CHANGELOG/Release Notes 管理 | 无变更通知 |
| 更新频率/通道管理 | ❌ | 无 channel/分组机制 |

**缺口**：回滚 + 更新说明。**严重度：中**——更新失败时无法回退。

### 领域 8：灾难恢复

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| 从备份恢复数据库 | ❌ | 关键缺口 |
| 系统降级（本地模式接管） | ✅ 双模式切换 | ✅ |
| **更新回滚** | ❌ | 更新失败无回退路径 |
| **配置还原** | ❌ | 误改配置无法快速恢复 |

**缺口**：恢复 + 回滚。**严重度：高**。

### 领域 9：退役

| 业界能力 | 我们的状态 | 判断 |
|---------|-----------|------|
| **数据全量导出** | ❌ | 迁移到其他系统或做审计用 |
| **系统重置** | ❌ | 回到初始状态（新员工接替时） |
| 完全卸载（含数据清理） | ⚠️ Velopack 提供卸载，但数据目录不清理 | 数据残留在 LocalAppData |

**缺口**：数据导出 + 系统重置。**严重度：低**（小诊所退役场景极少）。

## [S3] 完整性评分

| 闭环度 | 领域数 | 说明 |
|--------|:---:|------|
| ✅ 完全闭环 | **1/9** | 部署安装（Velopack + 向导设计完成） |
| ⚠️ 部分闭环 | **4/9** | 身份权限 / 配置管理 / 监控诊断 / 更新管理 |
| ❌ 显著缺口 | **4/9** | 数据维护（无恢复） / 安全合规（无审计） / 灾难恢复（无回滚/恢复） / 退役（无导出） |

**综合评分：45/100** — 约一半的业界标配能力缺失或部分实现。

**但注意**：这个评分是和"全功能系统"对比。对于 v1.0 小诊所（1-3 医生），部分缺口可以降优先级或标 v2.0。

## [S4] 我的专家建议：哪些缺口必须在 v1.0 闭环

按**业务影响**排序：

### 🔴 P0 必须闭环（缺了 sysadmin 角色就不完整）

| 缺口 | 为什么必须 | 估计工作量 | 落地点 |
|------|-----------|:---:|-------|
| **数据恢复 UI** | sysadmin 崩溃后无法自助恢复 = 数据永久丢失 | ~1 人日 | Phase② |
| **安全审计日志**（D1） | 医疗合规 + sysadmin 无法追溯安全事件 | ~3-5 人日 | 依赖 D1 决策 |
| **备份状态查看** | sysadmin 不知道"上次备份什么时候" = 盲管理 | ~0.5 人日 | Phase② |

### 🟠 P1 强烈建议闭环（缺了体验/安全明显不完整）

| 缺口 | 为什么建议 | 工作量 |
|------|-----------|:---:|
| **配置备份/导出** | 重装后能快速恢复配置 | ~1 人日 |
| **更新回滚** | 更新失败时能退回到旧版本 | ~1-2 人日（Velopack 手动方案） |
| **密码策略可配置** | 默认 8 位/无特殊字符可能不够 | ~0.5 人日 |

### 🟡 P2 可以推 v2.0（小诊所场景下可接受）

| 缺口 | 理由 |
|------|------|
| 系统资源监控（CPU/内存/磁盘） | 小诊所机器少，性能问题靠日志可排查 |
| 会话管理（活跃会话/强制登出） | 3-5 人办公，共享账号风险低 |
| 数据全量导出/系统重置 | 退役场景极少 |
| 配置运行时热更新 | 重启 Desktop 即可，非紧急 |
| 数据库大小/行数监控 | 小数据量，手动查即可 |

## [S6] 对标结论

**v1.0 Sysadmin 角色不完全闭环**——和业界基准比，有 4 个领域存在显著缺口（数据恢复、审计日志、备份管理、更新回滚）。

**新增 5 项到 v1.0 范围**：
1. 数据恢复 UI（~1 人日）
2. 安全审计日志查看（~3-5 人日，依赖 D1）
3. 备份状态+手动备份（~0.5 人日）
4. 配置导出/导入（~1 人日）
5. 更新说明展示（~0.5 人日，Velopack 内置支持，集成成本低）

这些工作量合计 **~6-8 人日**，属于 v1.0 合理范围。不做的话 sysadmin 在崩溃/恢复/合规场景下束手无策。

**其余 4 项（系统资源监控、会话管理、数据导出、配置热更新）推 v2.0**——小诊所场景下可接受。
