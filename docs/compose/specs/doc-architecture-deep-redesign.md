# 文档架构深化精设计方案

> 基于 Diátaxis + C4 + Stripe 最佳实践，结合本项目特点。

## 一、框架选择

| 框架 | 核心思想 | 适用场景 |
|------|---------|---------|
| **Diátaxis** | 4 类文档各司其职：教程/操作指南/参考/解释 | 文档分类 |
| **C4 Model** | 4 层抽象：上下文/容器/组件/代码 | 架构文档分层 |
| **Stripe 风格** | 目标导向而非端点导向 | API 文档 |

## 二、Diátaxis 分类映射

### 当前问题：每个文档混合了多种类型

`02-auth.md` 同时包含：
- 模块概述（Explanation）
- 业务规则（Reference）
- US 验收标准（How-to）
- 双模式差异表（Reference）
- 实现参考（Code Reference）

### 新分类：每个文档只属于一种类型

| 类型 | 目的 | 当前对应 | 新位置 |
|------|------|---------|--------|
| **教程** | 引导学习 | `training/` | `training/` |
| **操作指南** | 完成任务 | US 验收标准 | `02-requirements/` 各 US |
| **参考** | 查阅事实 | API 端点/配置/权限 | `04-api-reference/` + 各 SSOT |
| **解释** | 理解原因 | 架构决策/设计原理 | `03-architecture/` + ADR |

## 三、C4 分层映射

### 架构文档按 C4 层级组织

| C4 层 | 内容 | 对应文档 |
|-------|------|---------|
| **L1 上下文** | 系统边界、角色、外部依赖 | `00-architecture-summary.md` |
| **L2 容器** | 模块划分、数据流 | `01-system-overview.md` + `03-server.md` |
| **L3 组件** | 各模块内部结构 | `modules/*.md` |
| **L4 代码** | 实现细节 | 代码本身 + ADR |

### 当前问题
- `03-server.md` 混合了 L2+L3+L4
- `14-structure-design-blueprint.md` 与 `03-server.md` 重叠

### 新设计：每个 C4 层一个文档

```
00-architecture-summary.md    → L1 上下文（100 行）
01-system-overview.md         → L2 容器（300 行）
modules/auth.md               → L3 组件
modules/users.md              → L3 组件
...
decisions/*.md                → ADR（历史决策）
```

## 四、需求文档精简方案

### US 模板精简

**当前模板**：
```
## US-AUTH-001: 用户名密码登录
**角色**: 所有用户
**优先级**: Must
**状态**: ✅ 已实现
**作为** ... **我想要** ... **以便** ...
**验收标准**: 5-8 条
**业务规则**: 3-5 条
**双模式差异**: 表格（通常"同下"）
**实现参考**: AuthController.cs:44
```

**新模板**：
```
## US-AUTH-001: 用户名密码登录
**角色**: 所有用户 | **优先级**: Must | **状态**: ✅
**作为** ... **我想要** ... **以便** ...
**验收标准**: 5-8 条
**业务规则**: 3-5 条（如有）
**双模式**: 一致（除非有差异才展开）
```

### 精简规则

| 删除项 | 原因 |
|--------|------|
| **双模式表格（"同下"）** | 模块级声明覆盖 |
| **实现参考（行号）** | 会过时，用文件名替代 |
| **重复的权限摘要** | 引用 04-permissions.md |
| **变更日志详细条目** | 精简为版本号+关键变更 |

## 五、架构文档合并方案

### 三合一：01 + 03 + 14 → 新 03-server.md

当前重叠：
- `01-system-overview.md` — 系统概览+模块图
- `03-server.md` — Server 架构+模块详情
- `14-structure-design-blueprint.md` — ~~合规表+DTO 约定~~

合并为：
- `01-system-overview.md` — L1+L2（上下文+容器）
- `03-server.md` — L3（组件详情）
- `14-structure-design-blueprint.md` → 内容分散到 01（设计原则+技术栈）/02（Desktop 层）/03（Server 分层规则+Tests+设计依据索引）

### 模块文档精简

当前 `modules/*.md` 每个模块描述了大量重复的架构模式。

精简为：
- 只写**该模块独有的**设计决策
- 通用模式（CQRS/MediatR/BaseRepository）引用 `03-server.md`

## 六、API 文档精简

### Stripe 风格：目标导向

**当前**：按端点列出（GET/POST/PUT/DELETE）
**新设计**：按用户目标组织

```
## 认证
### 登录
POST /api/v1/auth/login
→ 返回 JWT Token

### 刷新令牌
POST /api/v1/auth/refresh
→ 返回新 Token

## 用户管理
### 创建用户
POST /api/v1/users
→ 返回用户信息
```

每个端点：**一句话描述 + 请求参数 + 响应示例**
