# 用户期望采访稿（按角色）

> **目的**：以"我问你答"的形式，逐角色厘清**真实工作流、期望、当前痛点**。这是验证"用户期望 → PRD → 代码"三层对齐的最直接方式，也是 v1.0 范围冻结的核心依据。
> **方式**：你（产品负责人，熟悉诊所实际）扮演各角色的"知情人"回答。我会一次问一个问题，你可答「是/否」或展开。
> **依据**：基于 `personas.md` 角色职责 + 8 模块审计 + 端到端功能地图的断点，针对性提问（不问空泛的"你做什么"，而是问审计暴露的具体争议点）。
> **角色顺序**：Receptionist（最瘫痪）→ Doctor（卖点失效）→ Admin（初始化/合规）→ Sysadmin（低频）→ 跨角色议题。
>
> **标注说明（2026-06-28 补）**：每个问题点末尾的 `→ US-XXX` 表示该问题点对应的需求故事；`→ 系统外` 表示不在系统范围；`→ 移除` 表示对应功能已从 v1.0 移除；`→ v2.0` 表示延期到 v2.0；`→ 背景/决策` 表示为访谈背景或优先级决策依据（不映射到单一 US）。详见 [13-traceability-matrix.md](../../02-requirements/13-traceability-matrix.md)。

## [R] Receptionist 前台接待（当前代码中职能瘫痪，优先级最高）

### R-背景：一天工作流
- R1. 前台一天的工作从开门到关门，大致分几个阶段？每个阶段主要做什么？ → 背景（映射 US-REG-001/004 挂号/候诊）
- R2. 高峰时段（如早晨开诊、午饭后）一天大概接待多少患者？非高峰呢？ → 背景（容量估算）

### R-核心场景：新患者登记
- R3. 一个**新患者**第一次进门，从接待到患者坐等看病，你期望的完整步骤是哪些？（读卡？填表？建档？挂号？分诊？） → US-CARD-001 / US-PAT-003 / US-REG-001
- R4. 身份证读卡器实际使用频率？如果读卡失败/没带身份证，你期望怎么登记？ → US-CARD-001
- R5. 登记时系统需不需要自动查重（避免重复建档）？你期望按什么查重（身份证号？手机号？姓名+生日？） → US-CARD-002

### R-核心场景：老患者挂号
- R6. **老患者复诊**挂号，你期望几秒内完成？操作步骤？ → US-REG-001
- R7. 老患者如果忘了病历号/手机号，你怎么找到他？ → US-PAT-001

### R-核心场景：候诊与分诊
- R8. 候诊队列你期望看到哪些信息？（患者名/序号/状态/挂的哪个医生/等候时长？） → US-REG-004
- R9. 候诊队列要不要展示给患者看（大屏/叫号）？ → 系统外（大屏叫号 v2.0/按需，v1.0 候诊队列仅前台/医生端可见）
- R10. 挂号后怎么通知医生"有新患者"？（自动？手动？医生自己刷？） → US-REG-008（SignalR 实时推送）

### R-争议点（审计发现）
- R11. **取消挂号**：什么情况下你会取消？只取消自己的还是也能取消医生的？（审计发现前台当前完全无法取消——权限错配） → US-REG-006（D7 权限错配）
- R12. **前台要不要能查药材**？（审计发现前台被锁在药材查询外）—— 比如 patient 问"这个药有没有"？ → US-HERB-001（D7 权限错配）
- R13. 前台要不要能**代医生快速就诊**（QuickVisit）？还是严格只做挂号？ → US-REG-002

## [D] Doctor 医生（核心卖点"复诊秒查"失效，优先级高）

### D-背景：接诊节奏
- D1. 一天大概看多少患者？复诊占多少比例？ → 背景（容量估算，映射 US-MC-005/011）
- D2. 一个复诊患者从叫号到送走，你期望的完整步骤？ → US-MC-001 / Flow 2

### D-核心卖点：复诊历史调阅
- D3. 复诊时你想**第一眼**看到患者的哪些历史信息？（诊断/处方/费用/过敏/病史/...） → US-MC-008 / US-MC-009
- D4. "10 秒调出完整历史医案"——你期望以什么形式呈现？（时间轴？列表？最近一次？） → US-MC-008 / US-MC-009
- D5. 历史处方你最关心什么？（用药？剂量？诊断？费用？效果？） → US-MC-009
- D6. **复制上次处方微调**这个场景，实际多频繁？你期望怎么操作？（一键复制？选择性复制？） → US-MC-019

### D-核心场景：诊疗录入
- D7. **辨证论治（望闻问切）**你期望怎么录入？自由文本？结构化字段？模板？舌象/脉象怎么记？ → US-MC-002
- D8. 主诉/现病史/既往史这些，你希望是必填还是选填？ → US-MC-002（BR-003 字段必填性）
- D9. 同一个患者本次诊疗，你期望和上次诊断关联（"复诊"语义）吗？ → US-MC-008

### D-核心场景：开方
- D10. 开方时药材搜索你期望怎么查？（拼音码？功效？分类？君臣佐使？） → US-HERB-001
- D11. **验方（经验方）**你现在怎么积累？期望系统怎么帮你？（个人验方库？一键导入？共享给团队？） → US-FORM-003 / US-FORM-007
- D12. 处方费用你期望自动算还是手动确认？要不要显示单价/小计？ → US-MC-003
- D13. 剂量单位（g/ml/钱）和用法（水煎服/外用/...）怎么管理？ → US-HERB-004（D13：默认 g，不换算）

### D-核心场景：打印
- D14. 处方打印你期望**几张**？分别给谁？（患者联？药房联？存根？） → US-PRINT-001（D14：v1.0 单联）
- D15. A5 还是 A4？还是可选？ → US-PRINT-001
- D16. **打印后医案能不能改**？什么情况下能改？改了要不要重新打印 + 记录？ → US-PRINT-004 / US-MC-014
- D17. 草稿（未完成医案）要不要能打印？打出来的处方要不要水印？ → US-PRINT-001（草稿水印）

### D-争议点：双模式/义诊
- D18. 你会外出义诊/上门吗？频率？ → US-SHELL-007 / Flow 3
- D19. **断网时**你期望系统能做到什么？（完整接诊？只读？完全不能用？） → US-SHELL-007 / US-AUTH-012
- D20. **断网期间录入的医案，网络恢复后你期望怎么处理？**（自动同步？手动同步？还是义诊就是临时用、数据可丢？）← **这是双模式 v1.0 根本矛盾，必须问清** → v2.0（Sync 数据同步整模块延期到 v2.0）

## [A] Admin 业务管理员（初始化/合规卖点失效）

### A-核心场景：药材库管理
- A1. 药材库**初次建立**：你期望怎么把 400+ 味药材录入？（Excel 导入？手动？厂商提供清单？） → US-HERB-006（D6：Excel 服务不存在）
- A2. 药材**调价**多久一次？调价时要不要记录历史价格？历史处方要不要受影响？ → US-HERB-004（A2：调价审计并入 D1，PrescriptionItem 快照隔离）
- A3. 药材**停用/启用**（不删）：什么情况下停用？停用后历史处方怎么显示？ → US-HERB-010
- A4. 你需要按分类/功效管理药材吗？分类标准是什么？ → US-HERB-001

### A-核心场景：医案审核
- A5. 你实际会**审核医案**吗？审什么？（金额异常？用药合理性？诊断完整性？） → 移除（医案审核已从 v1.0 移除，确立医生负责制，见 plan Task 2）
- A6. 审核出问题你期望怎么处理？（驳回？标记？联系医生？） → 移除（同上）
- A7. 你需要哪些**统计报表**？（日营业额/就诊量/热门药材/医生工作量/...） → 报表清单待讨论（A7 标待讨论，见 plan Task 5）

### A-核心场景：用户管理
- A8. 创建新用户的流程？密码怎么给用户？强制改吗？ → US-USER-004
- A9. **禁用/删除用户**后，他的历史医案归属怎么处理？ → US-USER-006 / US-USER-010
- A10. **误删用户/药材后需要恢复吗**？（Restore 体系）多久内可恢复？ → US-USER-011（D4 Restore 补回）

### A-争议点：审计合规
- A11. 医疗纠纷时你需要能追溯什么？（谁改了医案？何时？改了什么字段？） → US-MC-017（D1：审计日志补回）
- A12. 审计日志要保留多久？谁有权查看？ → US-LOG-004 / US-LOG-007

## [X] 跨角色议题

### X1. 双模式 v1.0 根本意图（最高优先级）
- X1.1 v1.0 的本地模式，定位是**"远程故障时的临时降级"**（数据事后手动补/可丢），还是**"独立的离线工作站"**（数据必须能回到远程）？ → US-SHELL-007 / Flow 3
- X1.2 如果是后者，**医案数据同步是否应从 v2.0 拉回 v1.0**？ → v2.0（Sync 数据同步整模块）
- X1.3 一个诊所几台机器？都是远程模式，还是有机器常驻本地？ → 背景（部署形态）

### X2. 角色协作
- X2.1 前台挂号后，医生怎么知道？（推送？刷新？大屏？） → US-REG-008（SignalR）
- X2.2 医生开完方，前台/药房怎么知道？（用于收费/发药——虽然发药不在范围） → 系统外（收费/发药不在系统范围，患者凭打印处方笺线下付费取药）
- X2.3 多医生同时接诊，互相能看到对方的患者吗？ → US-MC-005 / US-MC-016（权限矩阵：Doctor 仅自己）

### X3. 数据与隐私
- X3.1 患者隐私：除了已确认的"字段级加密拉回 v1.0"，还需要什么？（操作日志？谁查了谁的患者？） → US-PAT-013（字段脱敏，D10 字段级加密）
- X3.2 数据导出：Admin 要不要能导出全部数据（备份/迁移）？ → US-SHELL-013 / US-SHELL-016

### X4. 优先级排序
- X4.1 如果只能先修好**一个角色**的完整工作流，你选哪个？（Receptionist / Doctor / Admin） → 决策（优先级排序依据，见 scenario-functional-map S10）
- X4.2 vision 三大卖点（复诊秒查 / 药材库初始化 / 双模式）哪个对你**最关键**？ → 决策（vision 卖点优先级依据）

## 采访执行规则

1. **一次一题**：我会按顺序逐题问，你答「是/否」或展开。
2. **可跳过**：某题不适用或不想答，说"跳过"。
3. **可反问**：题意不清可让我解释。
4. **可改序**：你想先聊某角色/某议题，随时说。
5. **答案去向**：你的回答会更新到本稿，最终汇成《用户期望确认书》，作为 PRD 对账与 v1.0 冻结的权威输入。
