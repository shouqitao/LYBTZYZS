## [S3] SignalR 实时推送架构（新增 v1.0 技术决策）

**决策**：v1.0 实现挂号→医生工作台的实时推送（SignalR），医生工作台待诊列表实时刷新。参考市面医院系统标配。

**待专项设计的架构问题**（本 spec 仅锚定决策，细节由后续 SignalR 专项 spec + ADR-0013 承载）：
- **双模式推送机制**：远程模式 Hub 部署于 WebAPI（公网）；本地模式如何推送——LocalWebAPI 内嵌 Hub？或本地模式仅前端轮询降级？
- **推送内容**：新挂号、挂号状态变更（开始就诊/取消）
- **降级策略**：推送失败时医生端回退轮询（复用 US-REG-004 候诊队列）
- **与 SwitchingApiClient 的关系**：推送通道是否随 URL 模式切换

**产出物**：
- 新增 **ADR-0013**（SignalR 实时推送）记录决策与双模式方案
- 新增 **US**（REG 模块）：医生工作台待诊列表实时更新（依赖 SignalR）
- `01-system-overview.md`/`03-server.md` 架构图补 SignalR Hub 组件

> ⚠️ SignalR 涉及双模式架构深层问题，建议作为独立 brainstorm 主题（类比 Shell Phase2）。本 spec 仅锁定"v1.0 要做"的范围决策。

## [S6] 系统边界声明（打印为终点）

**决策**：系统边界止于**打印处方笺**；付费、发药、库存为线下流程，不在系统范围。

**落地**：
- `01-vision.md`「系统边界」段补：「范围外：收费、发药、库存管理——患者凭处方笺线下付费取药」
- `01-prd.md` 补「范围外」小节
- X2.2（开方→前台通知）标注「系统外，不实现」

**理由**（用户 2026-06-28）：医生看完→打印处方笺（含详情+价格）→患者持单线下付费→抓药。打印为系统侧终点。
