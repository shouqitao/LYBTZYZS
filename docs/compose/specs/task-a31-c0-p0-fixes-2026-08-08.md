## P0-1：LocalWebAPI 缺 `DoctorOrAdminOrReceptionist` 策略注册

**背景**：`LocalJwtConfig.cs:70-90` 注册了 5 个策略（AdminBusinessOnly/DoctorOrAdmin/DoctorOnly/AdminOrSuperAdmin/DoctorOrReceptionist），但**缺 `DoctorOrAdminOrReceptionist`**；3 个 Controller 引用它：
- `LocalWebAPI/Controllers/PatientsController.cs:20`
- `LocalWebAPI/Controllers/RegistrationsController.cs:17`
- `LocalWebAPI/Controllers/ReportsController.cs:13`

**影响**：本地模式（LocalWebAPI）下这 3 个模块的所有端点 `[Authorize(Policy = ...)]` 找不到策略 → 运行时异常，**患者/挂号/报表在本地模式整体不可用**。

**对照**：WebAPI 侧已注册（`AuthenticationServiceCollectionExtensions.cs:132`）。

**动作**：
1. 在 `LocalJwtConfig.cs` 补注册 `DoctorOrAdminOrReceptionist` 策略（与 WebAPI 侧同语义：Doctor OR Admin OR Receptionist 任一角色可访问）
2. 参照现有 5 个策略的注册写法（RoleNames 常量 + RequireRole）
3. 核实 LocalWebAPI 侧角色名常量（LocalJwtConfig 用的角色名与 WebAPI 是否一致——如 RoleNames.Doctor 等）

**验证**：build 0 错误 0 警告；`grep "DoctorOrAdminOrReceptionist" src/Client/Desktop/LocalWebAPI/` 同时出现在注册处 + 3 个 Controller；架构测试全绿。

## P0-2：MedicalCase 验证管道丢失

**背景**：`MedicalCaseInputDtoValidator`（Shared.Models/Validators）经 `MedicalCaseModule.cs:58` 注册后**无任何注入点**——MedicalCase 模块是 Service 化（无 MediatR 管道），`ValidationBehavior`（`Infrastructure/Validation/ValidationBehavior.cs:10`）不生效；`CreateFromInputDtoAsync:106-110` 仅手工校验 TcmDiagnosis，Save/Complete/Suspend 无 FluentValidation 校验。

**影响**：医案创建/保存/完成/暂停的输入无统一验证（部分字段如 TcmDiagnosis 有手工校验，但 Validator 中定义的其他规则未生效）。

**动作**：
1. 调研 `MedicalCaseInputDtoValidator` 定义了哪些规则（Shared.Models/Validators/ 下）
2. 在 MedicalCase 的 Service 化模块中接入验证：**在 `MedicalCaseCommandService` 的写方法（CreateFromInputDtoAsync/UpdateAsync/CompleteAsync/SuspendAsync 等）调用 `MedicalCaseInputDtoValidator.Validate()`**（或注入 IValidator<MedicalCaseInputDto>）
3. 推荐注入方式：CommandService 构造函数注入 `IValidator<MedicalCaseInputDto>`，写方法入口调用 `validator.ValidateAndThrow()`（FluentValidation）或返回 ValidationFail——**选择与模块现有错误处理一致的方式**（Result<T> 模式）
4. 若存在多个 DTO（如状态流转 DTO），评估是否也有对应验证器需接入

**验证**：build 0 错误 0 警告；`grep "IValidator<MedicalCaseInputDto>" src/Server/Modules/LYBT.Module.MedicalCase/` 有注入点；架构测试全绿。

## P0-3：Reports 双轨策略分歧

**背景**：Reports 同端点双端授权策略不同——
- LocalWebAPI：`ReportsController.cs:13` `[Authorize(Policy = PolicyConstants.DoctorOrAdminOrReceptionist)]`
- WebAPI：`ReportsController.cs` 用 `DoctorOrAdmin`（A-30-S3 §4 确认）

**影响**：同一报表端点，本地模式前台（Receptionist）可访问、远程模式前台不可访问——**双端行为不一致**。

**动作**：
1. 确认两端 ReportsController 所有端点的实际策略标注（逐端点对照）
2. **统一策略**：与权限矩阵（`docs/01-product/04-permissions.md`）核对 Reports 的**产品规则**（谁应能看报表？）
3. 按产品规则统一两端（若产品规则是"报表仅 Doctor/Admin 看"→ 两端都用 DoctorOrAdmin；若是"前台也能看"→ 两端都用 DoctorOrAdminOrReceptionist）
4. 同步其他双端 Controller 若有类似分歧（顺带核实，不扩大范围）

**验证**：build 0 错误 0 警告；两端 ReportsController 策略标注一致；架构测试全绿。
