## 四、教训与模式沉淀

### 4.1 五个教训
1. **测试自洽 ≠ 守护需求**（T1）——测试验证「代码做了什么」而非「需求要求什么」→ AC 映射体系
2. **文档滞后 = 技术债**——踩坑清单 5 号曾写错（「相对路径」vs 实际绝对路径）——修正后明确「文档是地图，发布是校验器」
3. **复制漂移会咬人**（HEALTHCHECK-FALLBACK）——同一 fallback 逻辑两处复制 → 一处漏 → 抽共享 resolver
4. **手工文本替换有破坏性**——多次 python 替换破坏语法/路由（CS0106/version 重复）→ LSP + 结构性工具
5. **环境依赖测试需分层**——Integration 失败 ≠ 回归（stash 基线实证）——单元层守护主体

### 4.2 六个工作模式（已固化）
1. **0 错误 0 警告门禁**——每批全量构建 + 架构测试实证
2. **先文档后代码**——冲突先改文档再改代码
3. **外科手术式修改**——每行可追溯
4. **每批自带测试守护**——新功能/修复随批补守卫
5. **13c/总账实时登记**——每批 commit SHA + 状态
6. **发布踩坑即沉淀**——实战问题直接进 Runbook
