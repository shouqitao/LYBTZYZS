> 证据等级：Fluent/M3/Element 为 A 官方规范；Ant/VS Code 为 B 默认值可验证；Figma/JetBrains/断点为 C 社区共识。每个定值至少 2 源交叉。

### 逐维小结

- **顶部 48**：不是拍脑袋——32（系统 chrome）→ 48（应用头栏）→ 52（Fluent Nav Header）→ 60（Element）→ 64（M3）形成连续阶梯，48 恰在 8pt 网格上且与品牌字 36 + 操作区 14 同框不溢出（见 §3.1）。
- **侧栏 240/64**：240 是 Figma/Pro/VS Code 三源收敛的“安静默认值”；64 是图标轨中位，比 80 省宽度、比 48 多呼吸，且与 `MainWindow.pen NavItem cornerRadius 10` 不裁切。
- **底部 32**：行业底栏 22–32 区间取上沿，因本项目底栏承载 4 段信息（连接/用户/版本/时间）且用 12px 辅助字，22 在 100%DPI 下贴边。
- **动画 220ms**：Fluent Pane 167–250、Ant 200、Element 300 的中位；`CubicEase Out` 与 WPF 默认缓动一致，无需自定义贝塞尔。
- **断点三档**：不是照搬 Web 的 768/1024，而是按 1920→1440→1280（2/3 等比）收敛；1280 为 MinWidth，<1280 不支持而非自适应——与 Fluent 双阈值思想一致。

## 3. 试点 `patient-list.pen` 双帧精读

> 分析方法：解包 `.pen` JSON 逐层核对 `width/height/fill/padding/gap/fontSize/content`，两帧逐项 diff；以 SSOT 与 §1 对标为尺子。

### 3.1 顶部 Header 48

**结构（两帧一致）**：
`36×36 品牌方块 $accent 圆角10` + `诊所名 17/600 #FFFFFF（$on-primary）` + `页面名 13/#D9C7C1` + `弹性占位` + `通知 22 #F0E4DE` + `头像 32 $accent 圆角16 / 字 13/600 $primary-dark`

| 优点 | 依据 |
|------|------|
| 48 高度利用充分：36 方块上下各 6 呼吸，17 与 13 双字阶同行不折行 | 与 SSOT 48 论证一致；Figma/Fluent 48–52 同档 |
| gap 12 + padding [0,24] 与 Sider 240 的内边距对齐，视觉连贯 | 符合 8pt 网格 |
| 深棕 $primary 背景与 Sider $primary-dark 形成同色系深浅阶梯，头/侧一体感强 | 优于 Tokens 白头方案的割裂 |

| 待改进 | 对标与影响 |
|--------|------------|
| **P1 — 头部品牌区信息密度偏高**：36 方块 + 17 诊所名 + 13 页面名 三段在 1280 窗口（内容 1040）下易拥挤；Element/Pro 顶栏多为「Logo + 标题」两段，页面名放在面包屑而非头栏 | 建议：1280 断点下隐藏或弱化“页面名”（改为面包屑承载），诊所名 17 可考虑 16 以换 1px 呼吸 |
| **P2 — 头栏与 Tokens 白色方案不一致**：`desktop-design-tokens.md §5` 写头栏 `$surface-1` 白底，试点却是 `$primary` 深棕 | 需 SSOT 明确：本项目头栏定深棕（与试点一致）还是白底（与 Tokens 旧值一致）；二选一，批量前统一 |

### 3.2 左侧 Sider 240 / 64

**展开 240**：`pad [20,12]` + 标题 `导航 NAVIGATION  #8D8078` + 7 项菜单 `h 36  fill透明 / 选中 #6D4C41` + 分割线 1px

**收拢 64**：同结构但 `width 64`，所有 `菜单文字 content=""`（清空）、`导航标题 content=""`（清空）

| 优点 | 依据 |
|------|------|
| 240 展开态菜单文字完整、选中态 $primary 填充对比清晰 | 与 Pro 256 / VS Code 260 同档验证 |
| 36 高度菜单项在 240 宽度下行距舒适，分割线区分“系统设置” | 符合 MDIX 列表项规范 |

| 待改进 | 对标与影响 |
|--------|------------|
| **P0 — 收拢态“去文字未补图标”**：收拢帧所有菜单文字被清空为空字符串，但**未放置任何 icon**（JSON 中无 `type:icon` 子节点），导致 64 轨为空轨；Ant `collapsedWidth 80` 保留图标、Fluent Compact 48 保留图标、VS Code ActivityBar 48 仅图标——三家收拢态均为“图标 + Tooltip” | 后果：收拢后无法识别导航；批量前必须在模版补图标（详见 §5 建议 1） |
| **P1 — 收拢态内边距未适配**：pad 仍为 [20,12]，在 64 轨中左右 20 导致可用仅 24（64-40），图标若 20 则仅剩 2 呼吸；Fluent Compact 48 的图标居中无侧边字 | 建议：收拢态 pad 改 [8,12] 或 [12,12]，图标 20 居中 |
| **P1 — 菜单项高度 36 < SSOT 48**：Tokens 规定菜单项 48，试点 36 偏矮；在 64 轨中 36 高度的点击区小于 44 触控底线 | 建议：统一回 44–48，或至少收拢态保持 48 以保证图标轨点击区 |
| **P2 — 导航标题清空但未隐藏容器**：标题文字置空但容器仍占位，收拢后顶部留白 | 建议：收拢态隐藏标题行或改为仅图标指示 |

### 3.3 底部 StatusBar 32

**结构（两帧一致）**：`h 32 fill #FFFFFF pad [0,16]` + `共 128 条记录 12/#8D8078` + `弹性占位` + `2026-08-23 12/#8D8078`

| 优点 | 依据 |
|------|------|
| 32 高度与 12px 辅助字匹配，上下呼吸约 10 | 高于 VS Code 22，层次清晰 |

| 待改进 | 对标与影响 |
|--------|------------|
| **P0 — 信息不完整**：SSOT 要求底栏承载 4 段（连接模式 / API 状态 / 用户名 / 时间），试点仅 2 段（记录数 + 日期），缺“连接/API/用户”三项；与 `desktop-design-tokens.md §5` 与 `desktop-design-spec.md §4.1` 均不一致 | 批量前必须补齐 4 段分区（建议见 §5 建议 2） |
| **P1 — 背景色与 SSOT 不一致**：试点 `fill #FFFFFF`（白），SSOT 与 Tokens 均为 `$bg-warm #FBF7F3`（暖灰白）；白底在 L0 暖灰底上层次弱，暖灰底更“安静” | 改为 `$bg-warm`，顶部加 1px `$border-soft` 分隔 |
| **P2 — 记录数与时间左右对齐但无分隔**：两段分居两端，中间弹性占位过大，在 1920 下中间 1600 留白割裂 | 建议：按 SSOT 四段分区，左：连接/API；右：用户/时间；记录数归工具栏或分页区而非底栏 |

### 3.4 工具栏 76 vs 头栏 48 的层次

**结构**：`h 76 fill $surface gap 10 pad [0,24] align center`  内含 `搜索 340×40 #F5EFE8` + `筛选 40` + `新增 40 $primary` + `导入 40 $primary-soft` + `导出 40` + `弹性占位` + `批量删除 96×36 #B00020`

| 优点 | 依据 |
|------|------|
| 76 高度容纳 40 高度按钮/搜索框，上下各 18 呼吸，不拥挤 | 与 Element 表头工具栏 56–64 同类，但更宽松 |
| 按钮层次清晰：主操作 $primary、次操作 $surface、危险 #B00020 | 符合 MDIX 按钮规范 |

| 待改进 | 对标与影响 |
|--------|------------|
| **P1 — 工具栏高于头栏，层次倒置**：Header 48（chrome）< Toolbar 76（page），在 900 高度视口中 chrome 共 80（48+32）占比 8.9%，Toolbar 再占 76 达 8.4%，两者高度接近导致“头栏不像头栏”；M3 中 TopBar 64 > Toolbar 56，Fluent Header 52 > CommandBar 44，均保持 chrome > page | 建议二选一：A) 工具栏收敛至 **64**（推荐，仍可容纳 40 按钮，上下 12 呼吸）；B) 保持 76 但头栏视觉加重（已用深棕，算部分缓解，需文档明确此为有意设计） |
| **P2 — 工具栏与内容区间无分隔**：fill $surface 与下方表格 $surface 同色，76 工具栏与表格粘连 | 建议：工具栏底部加 1px $border-soft 或 8 间距分隔 |

### 3.5 其他框架层问题

| 项 | 现状 | 对标/SSOT | 级别 |
|----|------|-----------|------|
| 画布 1440×900 vs 基准 1920×1080 | 试点两帧均为 1440×900 | SSOT 基准 1920×1080；Tokens 亦写 1440×900（旧值） | P1：画布与基准不一致，批量前需定“设计画布 1920 还是 1440”；建议设计画布统一 1920，1440 作为断点预览而非基准 |
| 动画 220ms 未在试点体现 | 静态帧无 SideBar 切换动效演示 | SSOT 220ms CubicEase Out | P1：下一批试点需补一帧动效标注或 Pen 交互原型 |
| 断点行为未演示 | 两帧仅展示 240/64 静态，未展示 1280 自动收拢提示 | SSOT <1360 自动收拢 + Tooltip | P2：需在批量模版中加断点行为注释 |

## 5. 下一步批量修正建议（不改文件，仅建议）

> 批量对象：12 个一级页面（同 `desktop-layout-framework.md §实施`：不含 `login`/`first-run`/`dialog-*`/`form-*`），逐页 `pencil_mcp.execute + TakeScreenshot` 验证。

### 5.1 先修模版（1 次修，所有页受益）

**建议 1 — 补收拢图标轨（P0-1 + P1-2，最高优先级）**
- 在 `patient-list.pen` 收拢帧基础上定“收拢模版”：
  - 7 项菜单各补 `icon 20×20`（复用展开态图标库：home/patients/registration/case/herb/report/settings），文字隐藏但保留 `Tooltip`（Pen 中用注释或第二帧悬浮态示意）。
  - Sider pad：展开 `[20,12]` 保持，收拢 `[8,12]`（或 [12,12] 二选一，定后全量统一）。
  - 菜单项 h：统一 **44**（兼顾 48 规范与 36 现状的折中）或回 **48**（严格按 Tokens），收拢/展开一致。
  - 标题行：收拢态隐藏 `导航 NAVIGATION` 行（`visible false` 或高度 0）。
- 产出：一份“收拢模版帧”作为 12 页复制源，避免每页各补各的图标不一致。

**建议 2 — 补底栏四段（P0-2 + P1-3）**
- 底栏改为：`h 32 fill $bg-warm borderTop 1px $border-soft pad [0,16]`
- 四段分区：左 `连接模式 · API 状态`（带 8px 圆点 Success/Danger + 12px 文字），右 `用户名 · 时间`（12px $text-secondary），中间弹性占位。
- “共 N 条记录”移至分页区或工具栏右侧，不占底栏。
- 产出：底栏组件化，12 页复用同一底栏帧。

**建议 3 — 定工具栏高度（P1-4）**
- 决策点：**64 还是 76**
  - 选 64：与 M3 Toolbar 56–64 对齐，头栏 48 仍为最高 chrome，层次正；改动小（76→64 仅减 12，按钮 40 仍居中，上下 12 呼吸）。
  - 选 76：需在 SSOT 明确“工具栏高于头栏为有意设计，靠颜色（深棕头 vs 白工具）区分层次”，否则审查时会被反复质疑。
- 推荐 **64**，并在底栏与表格间加 1px 分隔或 8 间距。

**建议 4 — 同步 Tokens 三项（P1-5）**
- `desktop-design-tokens.md §5`：`Min 1024×768 → 1280×720`；新增“断点 1280/1440/1920”与“动画 220ms CubicEase Out”两行；画布 `1440×900 → 1920×1080`（或注明 1920 基准、1440 为断点预览）。
- `desktop-design-spec.md §4`：同步 Min/断点/动画；MainWindow XAML `MinWidth/MinHeight` 改 1280/720（代码侧另起任务）。

### 5.2 再批量 12 页

1. 以修后 `patient-list.pen` 为母版，逐页复制 Header48/Sider240-64/Status32/Toolbar64 四件套。
2. 每页保留 Pen 双帧（展开/收拢）或至少收拢帧，保证 1280 断点可预览。
3. 每页 `pencil_mcp.execute` 后 `TakeScreenshot` 核对：头栏不折行、侧栏图标居中、底栏四段齐全、工具栏与表格分隔清晰。
4. 出 `批量验收清单`（12 页 × 4 件套 = 48 格），P0 项一票否决。

### 5.3 可选增强（不阻塞批量）

- 补一帧“220ms 侧栏开合”动效标注（Pen 交互或文档时序图）。
- 补一帧“1280 自动收拢 + Tooltip”行为标注（窗口 <1360 时提示“已自动收拢，点击展开”）。
