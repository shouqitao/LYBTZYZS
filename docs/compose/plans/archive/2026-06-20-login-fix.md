# Sysadmin Login Fix — Remote + Local Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use compose:subagent (recommended) or compose:execute to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix sysadmin/admin login in both remote (WebAPI → SQL Server) and local (embedded LocalWebAPI → LocalDB) modes so the Desktop client can authenticate successfully.

**Architecture:** The login flow is: Desktop `LoginViewModel` → `LoginCoordinator` → `AuthenticationService` → Refit `IAuthApi` → HTTP POST `/api/v1/auth/login` → `AuthController` → `UserManager.FindByNameAsync` + `SignInManager.CheckPasswordSignInAsync`. Both remote and local servers must use ASP.NET Core Identity (`UserManager`) for user creation and password hashing. `DatabaseInitializationService` and `LocalWebApiSeedData` must NOT touch password hashes.

**Tech Stack:** .NET 8, ASP.NET Core Identity, EF Core, SQL Server (remote) + LocalDB (local), Refit (client)

## Task 3: Remove LocalWebApiSeedData user creation (delegate to IdentitySeedData)

**Files:**
- Modify: `src/Client/Desktop/LocalWebAPI/Data/LocalWebApiSeedData.cs`

`LocalWebApiSeedData` still creates user records via raw EF Core without password hashes. `IdentitySeedData` (which runs first via UserManager) already creates both users properly. The `LocalWebApiSeedData` user creation is redundant and can create ghost records that interfere with Identity.

- [ ] **Step 1: Remove all user creation from LocalWebApiSeedData**

Replace the entire file with a version that ONLY seeds business data (herbs, formulas, patients), NOT users:

```csharp
using System;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using LYBT.Entities.Common;
using LYBT.Entities.Patients;
using LYBT.Entities.Herbs;
using LYBT.Entities.Formulas;
using LYBT.Shared.Models.Enums;
using LYBT.Infrastructure.Data;

namespace LYBT.LocalWebAPI.Data;

public static class LocalWebApiSeedData
{
    public static async Task SeedAsync(AppDbContext context, IServiceProvider? serviceProvider = null)
    {
        await context.Database.EnsureCreatedAsync();

        // Users are created by IdentitySeedData via UserManager (proper Identity password hashing).
        // Do NOT create users here — raw EF Core bypasses Identity and creates incompatible password hashes.

        if (!await context.Herbs.AnyAsync())
        {
            context.Herbs.Add(new Herb
            {
                Name = "Ginseng",
                Category = "Adaptogen",
                Unit = "g",
                Price = 9.99m,
                Status = CommonStatus.Enabled
            });
        }

        if (!await context.Formulas.AnyAsync())
        {
            context.Formulas.Add(new Formula
            {
                Name = "Sample Formula",
                Status = CommonStatus.Enabled,
                FormulaType = FormulaType.Experience,
            });
        }

        if (!await context.Patients.AnyAsync())
        {
            context.Patients.Add(new Patient
            {
                Name = "Sample Patient",
                BirthDate = DateTime.UtcNow.AddYears(-30),
                Gender = LYBT.Shared.Models.Enums.Gender.Unknown,
                Status = CommonStatus.Enabled
            });
        }

        await context.SaveChangesAsync();
    }
}
```
