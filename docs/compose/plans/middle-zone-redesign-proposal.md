# 中间区重设计方案 v2 — 多角度调研版

> 状态：**待评审** | 调研来源：Ant Design 页面模板 / Fluent ListDetails / 企业级 DataTable 模式 / EHR 临床工作区模式 / Carbon 空状态 / 表单分组最佳实践
> 本版基于 7 组外部调研修订 v1，吸收业界成熟模式。

## 一、调研结论（逐源）

### 1. Ant Design 六大页面模板（官方规范）
官方总结 6 类常用模板：首页 / 仪表盘 / 列表页 / 表格页 / 详情页 / 表单页。
- **详情页原则**：信息分层分组、就近原则、结构一致降低干扰——用户注意力应留在信息本身
- 对我们的映射：P-A 主从式=表格页+详情页组合；P-D 导航网格=工作台(Workbench)

### 2. Fluent ListDetails（Windows 官方）
- Master 列默认宽 360（我们定 880 列表+自适应详情，符合桌面密度）
- 断点切换 side-by-side / stacked @720epx —— 我们固定并排（桌面 ≥1280 无需 stacked）
- 详情区字段多时用 Grid 表单布局 ✓ 与 C6 DetailPanel 一致

### 3. 企业级 DataTable 最佳实践（Pencil&Paper/SetProduct）
- **工具栏**：搜索+筛选+列设置+主操作；批量操作在选中行后出现（减少常驻杂乱）
- **粘性表头**：长表滚动保持上下文
- **分页**：必须显示总数（不能只有"第3页"）；页大小可调
- **排序指示**：激活列显示方向
- **危险操作守卫**：批量删除需确认
→ 采纳：C2 Toolbar 增加选中态批量条变体；C3 表头加排序箭头位；C5 分页含总数+页大小

### 4. EHR 临床工作区模式（PMC 人因研究）
- **单一工作区聚合所有核心功能**，避免"碎片化显示"和"隐藏信息"问题
- 高频功能放显著位置：现病史(HPI)是最高频访问区
- 功能捆绑模式：「评估与计划⇆诊断」「医嘱⇆用药」「医嘱⇆检验」成对出现
→ 采纳：clinical-workspace 采用"患者卡(左) + 诊疗录入(中) + 处方(右)"单屏聚合，四诊输入紧邻辨证，处方药材与验方导入就近

### 5. Carbon 空状态模式
- 三类空状态：首次使用 / 操作确认 / 错误
- 首次使用空状态 = 标题(说明用途) + 描述(将出现什么) + 主 CTA(创建第一项) + 可选引导内容
→ 采纳：C10 EmptyState 升级为三要素结构；列表页无数据时显示而非留白

### 6. 表单设计最佳实践（NN/g + Designlab）
- 字段逻辑分组（个人信息/联系方式/偏好 各自成组）
- label 紧贴字段上方；相关字段视觉成组并与他组分隔
- >6 个字段就分组或分步；单列布局优于多列
- 避免 Reset 按钮；Cancel 弱于 Submit
→ 采纳：C7 FormField 单列布局 + SectionCard 分组卡；系统设置页按「基本信息/数据库/服务器」三组

### 7. TCM 诊所软件对标（SmartTCM/ClinicOne/MedicalMet）
- 共性功能：患者登记、预约日历、草药处方(克/两计量)、配伍禁忌提醒、双语支持
- 处方打印标签含剂量/注意事项/有效期
→ 我们 v1.0 不做禁忌提醒（无需求依据），但处方区预留"煎法"列已覆盖差异点

## 三、六种页面布局模式（含调研依据）

### P-A 主从式（Master-Detail）— 6 页复用
`PageHeader + Toolbar/BulkBar + [DataTable | GridSplitter | DetailPanel] + PaginationBar`
- 适用：patient-list / patient-selection / herb-management / formula-management / medical-case-management / user-management
- 依据：Fluent ListDetails + 企业表格模式；详情面板字段按 DTO 分组，组间小标题

### P-B 表单式 — 4 页复用
`PageHeader + SectionCard×N(单列表单流)`
- 适用：account-settings / system-settings / server-config(Modal 内容) / data-import-export
- 依据：NN/g 字段逻辑分组、>6 字段分组、单列布局；server-config 按 Modal 内容组织（RemoteUrl+测试连接+保存/取消）

### P-C 工作台聚合式 — 1 页
`患者信息卡(280) + 四诊录入区(自适应) + 处方编辑区(360)`
- 适用：clinical-workspace
- 依据：EHR 单工作区原则——所有核心功能同屏，高频输入(四诊)居中显著；处方药材表含 用法说明+煎法 列，验方导入按钮就近处方区

### P-D 导航网格式 — 3 页复用
`欢迎语 + NavCard 网格(2~3列)`
- 适用：admin-home(6卡) / receptionist-home / sysadmin-home(3入口+7面板)
- 依据：Ant Workbench 模板 + MS 卡片指南「每卡单一交互」「计数徽标动态刷新」；sysadmin-home 特殊=上3入口卡+下配置中心7面板分组

### P-E 流程步骤式 — 2 页复用
`StepBar + 当前步内容卡`
- 适用：medical-case(工作台) / first-run 向导页风格延续
- 步骤映射真实状态机：已挂起→进行中→已完成

### P-F 记录查询式 — 3 页复用
`Toolbar(仅搜索+筛选) + DataTable(只读无操作列) + PaginationBar`
- 适用：audit-log / security-audit-log / reports
- 依据：审计类页面只读，操作列是编造；报表首页实为 NavCard(P-D 变体)

## 六、超越现有 View 的优化提案（设计驱动，需评审取舍）

> 以下为基于功能需求与业界模式主动提出的优化，**不绑定现有 XAML 结构**。每条标注价值/成本，评审后决定采纳范围。

### O1 列表页「密度切换」⭐推荐
- 现状：行高固定48
- 提案：工具栏加 密度切换钮（舒适48/紧凑40），偏好持久化
- 价值：药材/验方动辄数百条，紧凑态一屏多显示 ~17% 行数；成本：低（组件参数化）

### O2 表格「列显隐 + 排序记忆」⭐推荐
- 提案：工具栏右侧「列设置」弹层，勾选显示列；排序/列宽持久化到用户偏好
- 依据：企业表格标配；DTO 字段多于常用视图（如患者 12+ 列）
- 成本：中（组件支持 columns 配置即可）

### O3 详情面板「就地编辑」
- 提案：详情面板字段 hover 出现编辑笔，点击变输入框，失焦保存——替代"必须开编辑对话框"
- 价值：高频微调（改手机号/价格）少 2 次跳转；风险：误触→需 Esc 撤销
- 建议：仅对 低敏字段 开放（联系方式/备注），金额与状态仍走对话框留痕

### O4 工作台「处方模板快捷区」
- 提案：clinical-workspace 处方区上方加 常用验方 chips 行（按医生使用频次 Top5），单击即导入
- 价值：复诊场景最高频动作从「打开验方管理→搜索→导入」3 步缩为 1 步
- 依据：需求 US-MC 验方一键导入是核心卖点；TCM 对标软件均有类似快捷区

### O5 全局命令面板 Ctrl+K ⭐推荐
- 提案：任何页面按 Ctrl+K 弹搜索框，可搜患者/药材/验方并直达，也可执行页面跳转
- 价值：熟练用户全键盘操作；中医诊所单人日均切换页面 50+ 次
- 成本：Shell 层一个浮层组件 + 各页注册搜索源

### O6 状态徽标「点击筛选」
- 提案：表格内状态徽标可点击，点击即按该状态过滤（再点取消），替代下拉筛选的部分场景
- 价值：看到异常状态直接点进去，比先找筛选器快
- 依据：企业表格"visible filters as chips"模式反向应用

### O7 表单页「未保存更改守卫」
- 提案：P-B 页面字段变更后标题旁出现「未保存」圆点 + 离开时确认弹窗
- 价值：系统设置/诊所信息误关丢配置是真实事故源；成本低

### O8 报表首页改为「最近查看 + 收藏」
- 提案：reports 页 NavCard 上方加「最近查看」行（最近3个报表直达），卡片支持收藏置顶
- 价值：报表使用高度头部集中；符合 dashboard"战略入口"定位

### 不建议做（评审时说明理由）
- ❌ 配伍禁忌提醒：v1.0 无此 US，属 v2 范围
- ❌ 富文本病历编辑器：四诊录入用结构化字段足够，富文本引入复杂度不成比例
- ❌ 拖拽排序列：WPF DataGrid 实现成本高，收益低

## 九、已确认设计决策（评审后补充）

### D1 双入口回跳 — 显式 ReturnView 参数（最成熟方案）
- 患者管理「查看医案」与医案管理「查看详情」共用同一医案详情页，跳转时携带 `NavigationParameters { ReturnView, PatientId, CaseId }`
- 详情页返回按钮读取 ReturnView 决定回到患者管理或医案管理，并恢复选中态；无参时降级为 `IRegionNavigationJournal.GoBack()`
- 依据：Prism 显式参数导航为企业级成熟模式，避免历史栈不确定性

### D2 医案详情独立页（非右侧小卡）
- 患者详情卡仅放轻量患者档案字段；医案详情为聚合根（诊断+处方14字段+煎法+步骤状态+编辑状态机+打印），需独立工作台页 `MedicalCaseWorkspaceView / ClinicalWorkspaceView` 承载
- 依据：`desktop-view-inventory.md` DOC-04/05/06 已分 View；`desktop-ui-detailed-design.md:102` 导航链已明确

### D3 患者详情内历史医案区 — 按角色显隐
- 有权角色（Doctor 完整可点+查看全部 / Admin 只读可点）显示最近 3 条可点击行（日期+诊断摘要+状态徽标+箭头，行44 hover高亮），点行整行跳转至医案详情
- 无权角色（Receptionist / Sysadmin）不留空，显示权限空状态：锁图标16 + 「历史医案」标题 + 「当前角色无权查看医案，需医生权限」描述，居中占位约 80h，无按钮，保持卡片高度稳定
