# 阶段 G：清理与文档 PRD

## 目标
- 移除已无引用的旧代码与兼容层；完善开发文档，固化统一标准与最佳实践。

## 范围
- In Scope：删除未引用的事件类型/服务/控件；更新 README/模块文档；开发指引（事件白名单、状态标准、通知/加载规范）。
- Out of Scope：对运行时行为的新增功能（仅清理/文档）。

## 交付物
- 删除遗留“New”事件、影子枚举/模型、无用服务实现与重复控件。
- 文档：
  - 事件白名单清单与如何新增事件（审批/评审流程）。
  - 状态标准（Active/Closed）与映射示例。
  - 通知/加载统一用法（示例代码/截图）。

## 验收标准
- `rg` 全局搜索：无“EventNew”、“Registered/InConsultation/Completed/Cancelled”业务判断遗留；无未使用的类型。
- 文档齐备，能指导新代码按统一规范编写。

## 里程碑
1. 清理未引用类型：按编译引用与 `rg` 搜索，提交删除补丁。
2. 完成桌面开发指引文档与事件/状态规范；在 Shell 或 Core 的 README 链接汇总。
3. 最终全量构建与回归，提交变更。

## 风险与缓解
- 风险：误删仍被反射/动态加载使用的类型。缓解：使用 `rg` + 手动穷举搜索；对可疑类型先标记 Obsolete 并观察。

## 依赖
- 前置阶段完成并稳定。

## 回滚方案
- 使用 Git 恢复被误删文件；将敏感类型转为 Obsolete 而非删除。

## 度量
- 删除文件/类型数量；文档覆盖率与团队确认反馈。

## 测试计划
- 编译 + 手工主路径回归；随机模块走查。

## 受影响文件（示例）
- `src/Client/Desktop/Core/Events/*`（旧类型）
- 其他冗余实现与控件目录
